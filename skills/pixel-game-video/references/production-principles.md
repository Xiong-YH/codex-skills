# 制作总则与经验入口

这是像素视频制作体系的上层入口，适用于 pixel-game-video、pixel-video-director 以及本体系的 pixel-video-writer。开始制作、续作或复盘时先读本页，再读取当前项目的要求与对应模块。具体参数、素材和配方仍由各模块维护。

用户本次明确要求优先；既有约定按其适用范围沿用。发现冲突时按本次要求调整，不能用历史偏好覆盖新指示，也不能把未实现能力写成已经执行。

## 要求分别记在哪里

| 层级 | 记录内容 | 位置与使用方式 |
| --- | --- | --- |
| 仓库维护 | 文件归属、技能独立、分支、缓存与验证 | 仓库 AGENTS.md；只约束仓库维护 |
| 通用制作原则 | 解释任务、视觉层级、运动、证据与经验使用 | 本页；三个视频 skill 按当前任务读取 |
| 系列与项目偏好 | 画风、人物职责、背景、声音及明确禁用项 | 当前项目的要求；本仓库的计算机口播系列由 director 的 references/computing-voiceover.md 维护 |
| 单片决策与限制 | 受众、主题、片长、镜头约束、实际采用的偏好 | 本片 brief.json；导演工程另由 script/storyboard/production-plan 分工 |
| 反馈与经验 | 哪次尝试有效、哪里失败、适用范围与后续处理 | [迭代记录](iteration-history.md)；每片 review.json 保留本次审片证据 |
| 执行能力 | 已实现的组件、参数、素材、转场和声音 | 对应模块的 catalog、合同及 GUIDE；参考设计不等于可调用能力 |

安装基础 skill 单独使用时，本页与迭代记录随之保留；系列偏好由当前项目提供。安装了 director 时，通过它的入口读取对应系列文件，不把同一份偏好复制进两个技能。

## 当前制作原则

**新视频先确认方向：** 与使用者讨论“帮谁、解决什么具体问题、提供什么价值”，记录摘要与真实确认依据后再进入叙事、文案、分镜或制作。续作沿用有效确认，三项改变时重新确认受影响方向；基础技能独立使用也适用。选题与文案归 pixel-video-writer，视听设计与创作审片归 pixel-video-director，执行与技术核验归 pixel-game-video；角色交接不重复确认。导演构思草图仅作参考，明确要求另行继承，动态白模不替代正式成片核验。

场景美术按 [项目主画风与片段透传](../modules/style/ART-DIRECTION-CONTRACT.md) 执行：项目主画风、片段可整段特选，四个场景分支统一继承；组件独立。八类描述与分支提示词唯一维护在 style/art-profiles.json，规范及实际使用样板随项目保留快照。本规则取代此前“分支各选画法”原型，不扩大为引擎自动换肤能力。

| 原则 | 执行含义 | 细则入口 |
| --- | --- | --- |
| 先确定解释任务，再选画面 | 每镜回答一个明确问题；根据介绍、比较、过程、条件或结论选择组件与场景 | [组件看图指南](../modules/components/GUIDE.md)、[场景](../modules/scenes/GUIDE.md) |
| 参考提炼机制，每题重新设计 | 不得抄袭参考文案、美术或独特表达组合；从当前主题重新选择对象、布局、节奏和反馈，不将认可样片固化为全片套用的效果模板 | [手法参考与原创检查](../modules/text/EXPRESSION.md#可迁移手法参考按主题重新设计) |
| 关键画面推进理解 | 先明确本段比前段新增什么理解，再让关键变化、比较或阅读支撑它；后镜使用前镜的结果或接续其疑问。图解与定义可保持稳定，示意画面不自动构成现实证据 | 创意与整段设计由 pixel-video-director 的 `references/visual-storytelling.md` 维护；基础层按本项目分镜执行，不依赖 director 安装 |
| 让画面承担解释 | 用对象、状态、数量和空间关系推进观点；旁白组织信息，字幕辅助阅读 | [场景](../modules/scenes/GUIDE.md)、[文字](../modules/text/GUIDE.md) |
| 同镜先定主次 | 一个主要解释对象，辅助信息服务它；保留主体与字幕空间，动作落稳后留阅读时间 | [组件与组合](../modules/components/GUIDE.md) |
| 文字重音与状态变化共同推进 | 先做完整语义组的稳定排版，再按文意选主要落点；字幕与道具反馈引用同一事件，代表片段实看后再扩展 | [重点字制作方法](../modules/text/EXPRESSION.md#重点字与道具共同推进的制作方法)、[反馈协同](../modules/scenes/GAME_FEEL.md#字幕重音震动与粒子的协同) |
| 基础组件区分风格与特性，自定义组件有设计约定 | 基础组件可选朴素原版；机械／能量风格互斥，各选开放／一体／传递样式，可附加堆叠特性；新机制从脚本关系出发判断复用或定制，按五维设计与事件驱动试样核验，动作与阅读停顿分开 | [基础规则](../modules/components/BASIC-COMPONENTS.md)、[自定义五维](../modules/components/DESIGN.md)、[动作时长](../modules/motion/GUIDE.md#组件内部的离散动作与节拍) |
| 运动对应关系与状态 | 先明确交出与接住的主体；避免无解释任务的反复推拉，声音跟随实际触点 | [转场库](../modules/motion/TRANSITIONS.md)、[游戏反馈](../modules/scenes/GAME_FEEL.md)、[声音](../modules/audio/GUIDE.md) |
| 音效少而精准 | 默认留白，只强调有明确增益的关键变化；可用音色、可见动作和卡点不构成发声理由，审片做删音对照 | [音效必要性与密度](../modules/audio/GUIDE.md#先减触发再调强弱) |
| 组件画风按共同规则生成 | 基础与自定义组件共用材质分工、相对厚度、受光、接触和主次要求；对象形态按内容设计，旧参考库迁移另行核验 | [组件共同画风](../modules/style/COMPONENT-ART.md) |
| 空间与形状保持可信 | 连续房间遵循统一镜头；局部滑动用于独立面板；卡片保持比例，连接线避字 | [运动](../modules/motion/GUIDE.md)、[组件](../modules/components/GUIDE.md) |
| 保留已确认的角色职责和风格 | 将适用偏好写入本片 brief，再按镜头安排人物、场所与背景；样板不固定全部镜头 | [风格基调](../modules/style/ART-DIRECTION.md)、[人物库](../modules/library/CHARACTERS.md) |
| 场景从内容出发，素材随后匹配 | 保持可识别的视觉语言，开放场所、尺度、视点和构图；已有图库供合适时复用，不以换房间数量或新图配额代替创作 | [开放式场景设计](../modules/style/ART-DIRECTION.md#background-design) |
| 视觉选型文档提供可看的参考 | 组件等视觉能力的指南应有实际效果图、适用场景与使用边界；关键状态给对照，并能追溯到可运行源 | [组件参考图与更新](../modules/components/INFORMATION-COMPONENTS.md#参考图来源与更新) |
| 工作台剪辑并独立分轨交付 | 视频制作必须进入工作台，镜头、字幕与其他文字、转场、音效、配乐分别成轨，有旁白时另轨；最终从工作台导出 MP4 并配对该次项目 JSON。选用能力不能编辑或导出时先补齐并验证，不静默回退直接出片 | [工作台](workbench.md)、[制作流程](production-workflow.md) |
| 如实记录能力与验收 | 区分参考素材、已实现能力、当前技术核验、实际视听审片和用户认可；未检查项保留未审 | [制作合同](contract.md)、[交付运行](runtime.md)、[历史认可范围](iteration-history.md) |

32 秒、特定人物、某次配色、某个转场或技术栈，只有在其适用项目中生效；示例不自动成为所有视频的默认值。

## 怎样积累经验

一次反馈按“**日期／版本 → 现象或用户原话 → 可复用结论 → 适用范围 → 处理与状态 → 示例或证据**”记录。简短事项可以使用迭代记录中的表格；复杂问题再附完整条目。

- 用户明确提出的要求可直接记录为要求；新实现尚未得到认可时，分别写清已做的验证与待确认的效果。
- 当前仍适用的系列偏好更新到系列文件；通用方法在本页保留简短结论，具体规则由实际所属模块维护。
- 失败或撤回的方案保留原因、范围和替代方向，避免下次重新踩坑；一次单片禁用不扩大为所有项目禁用。
- 新要求替代旧要求时，更新当前生效的说明，并在历史中保留变更原因；不只追加互相冲突的条目。
- 历史经验用于指导下一次创作，不能代替当前修改的运行验证、播放或听音。成片交付、测试通过或用户暂未反馈，都不等于审美已获认可。

每次复盘结束，应能说明：新增了什么经验、影响哪个范围、更新了哪个唯一归属文件，以及下次制作如何使用它。
