> **读取钩子：必须回执。** Agent 读到本页后，须在本轮面向用户的回复最末一行写：**“已读取《核心要求与常见踩坑》，本次吸收：……”**，点出与当前任务相关的 1–3 项具体要求或建议；同一轮不重复。无相关项时如实说明。回执确认阅读与取舍，不能代替实际执行或验收。

# 核心要求与常见踩坑

生成/修改脚本、制作、续作或复盘前先读本页，只应用当前任务涉及的要求。参数按需查模块，历史仅在追溯时读取。

**优先级：本次明确要求 → 本片已确认的方案与适用系列约定 → 本页通用要求 → 参考案例。** 冲突按此处理；能力和完成状态仍须如实记录。

**后续制作必须继承已确认要求。** Agent 主动把本页及相关模块要求落实到本片设计、实际调用和交付检查，无需使用者逐次提醒。普通字幕按 [后续制作默认](../modules/text/SOFT-HIGHLIGHT.md)执行；未落实或例外无具体依据时先修复，不以样片、读过规则或导出成功代替本片执行。

## 当前制作原则

### 项目文件放在哪里

从工作区根目录为每个项目使用 `work/<项目>/`。编剧稿、导演源、素材、预览、工作台工程、导出和审片证据都随项目保存。沿用已有工程目录及相对路径。新版本在同一项目里留当前入口和必要的回退基线。临时渲染、浏览器资料和可重建缓存放 `.tmp/` 或项目内忽略的构建目录。

`skills/` 维护规则、共享执行器和有明确复用用途的样例。把当前项目路径作为参数传入工具。案例在技能内保留可迁移的方法、验证范围和必要的最小样例。技能说明、样例及执行器不引用 `work/` 或 `outputs/` 中的具体历史工程。迁移后验证构建、播放、素材引用及导出，再清理没有依赖的过时派生物。

**新视频先确认方向：** 与使用者讨论“帮谁、解决什么具体问题、提供什么价值”，记录摘要与实际确认依据后再进入叙事、文案、分镜或制作。续作沿用有效确认，仅在三项改变时重新确认受影响方向；基础技能独立使用也适用。选题与文案规则归 pixel-video-writer，视听设计与创作审片归 pixel-video-director，执行与技术核验归 pixel-game-video；按当前任务读取，不因角色交接重复确认。

1. **如实说明能力与结果。** 调用前查 [能力目录](capability-catalog.md) 的字段、后端和编辑边界，缺口先实现核验。设计、参考图、独立试样不等于工程已支持；姿态和排练节奏不等于嘴型。未检查记 `not_reviewed`，未兑现记 `failed`；已知失败先修复，受阻版本标未完成试样。
2. **兑现本片方案。** 逐镜核对文案、对象变化、结果与承接。关键过程实际可见，静态定义有明确阅读任务；不擅自替换已确认的画面或动作。新机制先做起态、过程、末态完整的可播放试样，再扩片。
3. **按内容设计。** 先构思适合本段的对象、组件和空间，再判断复用、组合或定制；已有能力真正贴合时复用，不为定制而硬造。参考只提炼机制，不照搬独特表达。见 [组件设计](../modules/components/DESIGN.md)、[原创转化](../modules/text/EXPRESSION.md#参考转化与原创检查)。
4. **美术协调、主次清楚。** 人物、物种、背景、道具按 [有效画风](../modules/style/ART-DIRECTION-CONTRACT.md) 统一；组件按 [独立规范](../modules/style/COMPONENT-ART.md)，与背景协调位置、接触及阅读。保持比例、身份和光源，突出解释对象；规范与实际参考随项目保留，旧图与旧执行器另行核对。
5. **节奏服务理解。** 离散动作短促、落稳后留阅读；字幕重音与对象反馈引用同一事件。预估时长用于规划，制作后按实际讲述、必要动作和阅读任务重新收镜，不为填满预算空等；具体按 [按内容收镜](production-workflow.md#按内容收镜不填满预估时长) 执行。按文意决定强调，音效少而精准；阅读期保持主要信息稳定，不让辅助动效持续抢眼。
6. **交付可继续编辑。** 用到的镜头、文字、转场、音效、配乐分别成轨，旁白按需另轨；从 [工作台](workbench.md) 导出 MP4 与同次项目 JSON。技术成功只进入审片，不代替视听或用户认可。

**按阶段核验：** 脚本核对设计及实现依据；素材/试样查看真实图和可播放片段；成片正常速度连续观看、核字，有音轨时听音。抽帧用于定位布局问题，不能代替动作与整体视听检查；证据对应实际编辑分支和当前版本。

### 人物结构与新动作

- **结构检查贯穿制作与验收。** 按角色所属物种和已确认造型检查肢体数量、左右归属、连接、比例、关节活动、重心与支撑。检查原图和关键姿态，并连续查看动作过渡与最终合成。风格化比例和像素简化仍须保有可信的结构与接触关系。发现多肢、断接、关节反折、异常拉伸或穿插时，先修正再复核。详细判据见[整幅插画](../modules/scenes/whole-illustration.md#人物素材先过比例检查再编动画)。
- **新片可以制作库外动作。** 现有动作不适合镜头时，先提出具体动作、用途和预期结果，询问用户是否制作。本片可以先保留可播放的单片试样。通过结构及动作检查后，拿实际效果询问用户是否收入共享库。确认用于本片和确认共享入库是两项决定，已明确确认的事项沿用。获准入库后，记录动作的适用条件、素材来源、可播放示例和已验证的执行范围。动作目录与示例的归属见[人物表演库](../modules/scenes/character-performance/README.md)。

## 常见踩坑：本次必须规避

以下是已有明确要求的摘要；只检查本次相关项，不要求每镜都动、每片都换景或堆满效果。修复是否获认可见历史。

| 踩坑与适用场景 | 规避及复核标准 |
| --- | --- |
| 讲述推进，画面仍空、像课件 | 对照关键转折，能指出对应操作、关系变化或新增阅读内容；换背景、标题和粒子不能补缺失的过程。见 [场景](../modules/scenes/GUIDE.md)。[17秒关联案例：原片与两次迭代](../examples/narration-visual-progress/case.md)（反例/迭代材料，修正版尚未确认满意） |
| 案例结束后原界面仍抢焦点，辅助符号难以辨认 | 转入方法时，让已讲完的示例退场，把焦点交给能演出方法的物件和动作。使用辅助符号或粒子时，明确它提示的对象、情绪或事件，实际播放时含义看不清就先移除。见 [实片复盘](iteration-history.md#20261110--提问的艺术正式片中的三处踩坑)。 |
| 画面文字堆叠，像在读课件 | 让对象及状态承担过程，删去字幕、标签、总结之间的同义复述，按理解顺序显露。见 [文字与对象分工](../modules/text/EXPRESSION.md#信息密度文字与对象分工) |
| 认可字幕只留参考，出片仍用临时简化版 | 明确本片字幕方案并调用相应执行器；导出核对实际组件及画面，采用其他设计时说明本片依据。见 [字幕调用与检查](../modules/text/SOFT-HIGHLIGHT.md#实现边界与使用方式) |
| 精简画面或定制组件时丢失已确认风格 | 先继承本片组件风格，再按内容设计对象和机制；复用与定制均核对材质、动作及同框效果。见 [设计与认可对照](../modules/components/DESIGN.md#少字与组件风格延续) |
| 选型总套卡片，场所反复复用 | 先从本段关系设计形态与空间；旧素材不适合就补素材，不设场所菜单或新图配额。见 [空间设计](../modules/scenes/SPACE-DESIGN.md) |
| 人物比例不协调、重复肢体，物体贴片、穿插或变形 | 母图与基准并排比比例；先核对肢体数量及左右归属，逐侧追踪肩肘腕手，不以“被遮挡”跳过无法解释的连接；再查起态、触点、末态的身份、遮挡与承载，卡片保持比例。见 [整幅插画](../modules/scenes/whole-illustration.md)、[组件美术](../modules/style/COMPONENT-ART.md) |
| 固定机位的对话插画中，像素五官因插值发糊或变形 | 在镜头说明中写明表情切换的事件。可用同机位的清晰定格按话轮直接切换，保持角色轮廓、比例和光源。需要演出连续动作时，先准备接触点与完整姿态。按正常速度检查切点与像素边缘，分别记录观感和播放指标。见 [整幅插画](../modules/scenes/whole-illustration.md)。 |
| 屏幕朝向反常，界面看起来斜贴在实物上 | 先确定谁在读屏、屏幕朝向与握持或承托关系。持机者读屏时让正面朝向持机者，观众需要读细节时可切近景。画在实物平面屏幕内的界面、卡片和光标共用内沿四角的透视映射，核对机位变化前后的边缘、比例和遮挡。 |
| 组件离散动作慢、一直漂 | 分别记录触发、触点、收束及后续阅读区间，正常速度查看实际导出；不把动作均摊到整句旁白。环境循环和有解释任务的整体相机另看任务。见 [动作预算](../modules/motion/TIMING.md) |
| 字幕读不连贯、半句话悬空 | 语义成组保留/追加，读完完整状态再替换；检查小屏和动作同屏时的阅读，不用固定每句秒数代替判断。见 [阅读连续性](../modules/text/EXPRESSION.md#阅读连续性按完整语义切换) |
| 连续冲入、缩放出现台阶跳变 | 保持同一对象与锚点，逐帧求值；正常速度看实际导出，不用少数静态字号拼接连续动画。见 [个体冲击](../modules/motion/IMPACT.md) |
| 音效太密、连续叮咚或抢话 | 先删触发再调音量，同画面做删音对照；理解与必要表现力无损就删，听跨镜连接及尾音。见 [声音取舍](../modules/audio/details.md#先减触发再调强弱) |
| 用相近效果冒充指定过程 | 对照试样的起态、过程、末态和接镜是否兑现要求；按结果判断，不按是否用了蒙版等技术判定。指定连续运镜未实现时先修复，不以切图近似交差。见 [试样与回退](production-workflow.md#新动作失败时先回退不带缺口扩片) |

## 怎样积累经验

**吐槽 → 记录本片问题 → 修复复核 → 用户明确满意 → 提炼并更新。** 在收到认可的本轮主动处理，不要求另开复盘任务。

- **先区分要求与解法。** 用户明确的新要求立即生效；新解法先在本片验证，原因未证实保留假设，不因效果变好就声称找到了根因。
- **只沉淀已确认范围。** 记录原话、版本/区间、现象与预期，修复后保留实际证据；用户对相关修复明确表示满意后，提炼“适用条件 → 规避动作 → 复核方式”。局部认可不等于全片通过，沉默或技术成功不算满意。
- **合并现行规则，保留历史。** 通用摘要更新本页，细节归模块，系列/单片限制留原范围；同类项合并，失效项替换并记录原因。有复用价值才沉淀，不推广本片道具、片长或一次禁用。
- **留下出处。** [迭代记录](iteration-history.md) 保留日期、原话、修复版本、满意依据/证据、结论、范围及状态，失败和撤回记录不删。更新后简报沉淀内容及归属；新片仍需核验。

## 动态规范与实际效果是持续核心要求

导演写镜头描述时，先结合 motion 的[可执行HTML规范](../modules/motion/lab/index.html)和共用曲线决定焦点、运动层级、起态到落点及阅读；制作按采用的真实配方、参数和事件实现，审片对照同次工作台 JSON 与 MP4。关键效果不符先修复，不用静态参考、形容词或导出成功代替兑现。导演的描述／交接／审片细则唯一维护在其 `references/motion-direction.md`；基础参数和执行器仍归 motion，不复制到导演层。固定镜头照其任务保留，不要求每镜都动。

## 要求分别记在哪里

通用摘要在本页；系列/单片要求留项目或相应系列文件，基础技能不强制依赖导演。参数、素材和核验细则归模块，视觉指南须有 [实际效果与来源](../modules/components/INFORMATION-COMPONENTS.md#参考图来源与更新)。原话与版本证据归历史，本片检查归 review/问题记录；仓库维护归 AGENTS.md。
