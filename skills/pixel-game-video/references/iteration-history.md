| 文档脱敏高亮口播，2026-10-19 | 用户指出书页铺屏“这个转场还是太奇怪了删掉吧”。本片两处同类效果移除，改为直接切镜；后续修改本片不得自动恢复。此反馈限定于本片，不覆盖此前跨空间影片的认可范围。 |
| 组件指南缺少图片，2026-10-19 | 用户指出“咋没图片参考，这个组件指南做的不合格啊”。经验：视觉组件选型需要看到实际效果，指南应配图片、用途与边界，关键动态状态给对照，并可追溯到运行源。已补十二类大图、四组状态对照、两种组合和独立示例，完成当前引擎逐帧运行、图片链接及独立副本核验；补图后的审美认可尚未收到。适用于本视频体系的视觉选型文档，不要求非视觉模块也用图片替代其验收方式。见 [组件指南](../modules/components/GUIDE.md)。 |
| 背景选择过窄，2026-10-19 | 用户指出背景“来来会会回回这几张”，限制整体想象力。现有素材接入能力本已开放，但 AI 全栈片仍直接复用既有房间，文档中的“可变”未落实为创作顺序。调整为先按内容设计空间、尺度和主体变化，再选取或制作素材；样板只参考质感，不作场所白名单，不新增背景数量或新图比例限制。创作空模板移除赛博夜城预选，采用中性排版底等待项目设计；旧工程与运行示例保留原设置。本次更新为流程、文档和模板修正，尚无新背景素材或重制成片的审美验收。见 [背景设计](../modules/style/ART-DIRECTION.md)。 |
| AI 全栈路线 32 秒片，2026-10-19 | 用户指出人物不能只站着微笑，明确要求低幅度动态，并提出按文案用现有人物形象插入动态情境插画。该计算机口播系列的站立讲述包含自然表演，也允许内容驱动的情境演绎；五人身份继续保留。本记录是需求确认，不是对新动画实现或样片的认可。 |
| 人物微动态与情境双样例，2026-10-19 | 用户同意把镜头脚本、可复用能力与参考图按层落地。已新增 `scenes.character-illustration.v1`：阿棕侧边讲述 / 电脑输入→等待→回答→头部回应，13秒可运行样例、独立快照、素材元数据和实渲染对照图；该版随后被用户否定，拆分资产和执行器已撤回；不再是可选能力或推荐案例。 |
| 完整插画纠偏，2026-10-20 | 用户指出人头分离、比例不协调，要求合并完整人物并按参考图制作情境。撤回拆头拼身试样；以整幅书桌插画制作疲惫、抬手、抱头、俯身、趴下、专注和眨眼姿态，编成片段接入原32秒片开头。新试样仍待审美反馈；有限关键姿态动画不等于逐帧连续表演。 |
| 8秒能力展示片的插画布局，2026-10-21 | 用户指出第一幕应整屏插画，不能左侧还有额外内容。原版把情境图放入右侧窗口，并将侧边主持人和大字烘焙进媒体；即使 actor:null，最终仍是口播配图。经验：分别检查图像的解释职责与镜头形态，验收最终全画幅而非只看原图或结构参数。此系列的整屏定义、构图提示词及例外边界维护在导演层 references/character-illustration.md，其他图片用途不一概强制全屏；本反馈是要求确认，不代表后续修正版已获审美认可。 |
| 脚本未明确插画片段，2026-10-21 | 用户要求后续出脚本的 skill 强化插画标注，并按现有插画规范制作片段。此前脚本把情境镜头笼统写为画面，需追问才能辨认插画。曾在导演入口与创作合同接入逐镜呈现标注，但把口播、插画、场景和组件混列，并在新版脚本中把大段普通操作讲解标成插画；该分类方式被用户继续纠正，现由下一条的分类规范替代。素材、动作、落稳与承接要求保留；本次记录不是新插画或成片生成、播放或获认可的证明。 |
| 普通内容与特殊插画混淆，2026-10-21 | 用户明确插画是“铺满画幅的完整情境”的特殊片段，普通内容可以用纯画面＋组件，也可以有旁白。上一版把正常下单、日志排查和验证交付的连续讲解全标为插画；文档将口播、插画和组件混作同层级，并反复默认插画旁白继续，放大了误读。现将唯一分类定义、独立声音安排和正反例写入导演层 character-illustration.md，脚本在 visual-storyboard.md 分别标注片段类别、画面呈现、声音，入口、系列要求、创作合同与 review 路由一致；基础接入说明不再默认延续旁白。适用于本计算机口播系列，不把本片插画时长或静音选择推广为默认。文档修正及脚本设计不代表新素材、成片或审美验收已完成。 |
| 插画缺少讲解，2026-10-21 | 用户认可32秒音效版整体，但指出插画没有字幕、只看画面缺少解释，强调“插画的含义是通过主要的图片元素来体现一些含义”，要求保证插画也有具体讲解。此前虽区分声音和画面，却把无人声的插画留成只有图片与音效，缺少图像含义到观点的连接。现将配套讲解与字幕规则集中写入导演层 character-illustration.md，脚本、创作合同及 review 接入；sfx-only 仅关闭人声，不取消讲解字幕。用户本轮明确只修改 skill、不调整已有视频；整体认可不扩大为对缺字幕片段的认可。 |
| 插画主角连续性，2026-10-21 | 用户要求“插画里的尽量还是主角小棕来承担”，多人情境或明确条件需要时例外。当前系列在 character-illustration.md 维护主角优先及例外；小棕仍指现有 actor.azong.v3／00-lead，不改素材 ID，不显示内部姓名。基础人物指南和选角提示词改为先遵守项目连续性，再参考配角职责，避免按“提问／演示／核对”机械换人。此偏好不推广到其他项目，也不回改本片既有素材。 |
| 工作台剪辑与独立轨道，2026-10-21 | 用户要求“把这些能力真正接入工作台，验证镜头、字幕、转场、音效和配乐都能独立编辑和导出，再把强制工作台剪辑写进 skill”。经验：保留可修改源 JSON 不能替代真实多轨编辑交付，制作流程必须进入工作台并从当前项目导出；实际使用的五类内容不能合并为整片，有旁白时另轨。适用于本像素视频体系；仅交付视觉方案或局部调试不强制出片。执行边界与验收集中在 [工作台](workbench.md)，上层规则见 [制作总则](production-principles.md)；Canvas 复用同源 runtime，原生后端与剪映保留自己的能力白名单。本条记录用户要求与流程纠偏，不把实现接入、单元测试或文档修改写成本片视听及审美验收通过。 |
