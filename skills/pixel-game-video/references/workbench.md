# 本地工作台：多轨编辑与成片导出

本 skill 的 `workbench/` 复用 video-shotcraft 的浏览器工作台，提供多轨时间线、属性面板、Remotion 实时预览和 MP4 导出。制作视频必须在这里完成剪辑并导出最终成片；Studio 和源合成的直接渲染用于调试、审看和一致性对照。迁移代码的许可与署名保留在 [LICENSE](../workbench/LICENSE) 和 [NOTICE](../workbench/NOTICE)。

## 1. 启动与交付

在本 skill 根目录执行；`PROJECT` 是 VideoSpec 工程目录，导演工程使用 `PROJECT/video`：

```text
python scripts/video.py workbench PROJECT --port 5208 --no-open
```

命令构建当前工程，生成同源清单，再把工程连接到工作台。首次使用按 `workbench/package-lock.json` 安装 Node 依赖；Node.js 需 18.18+，Remotion 固定 4.0.534、React 固定 19.2.0。默认端口 5208，仅监听 `127.0.0.1`；终端打印的实际地址是入口。省略 `--no-open` 时自动打开浏览器；交付时主动打开实际地址供用户编辑。

`renderBackend=canvas` 继续使用现有 Canvas 绘制器，在 React Canvas 单元内按指定帧执行同源 runtime；不把整条 MP4 作为导入片段，也不要求将全部场景重写为 React。原生 `remotion` 使用其已有 React 场景执行器，能力边界仍见 [Remotion 后端](remotion.md)。Canvas 的场景、十二类组件、背景/replacement、物体、人物事件姿态与现有转场通过 runtime 桥接；叙事进度作为独立叠加单元。两种执行器都由工作台管理最终剪辑和导出。

工作台的「保存工程 JSON」立即保存当前状态并下载快照，「导入」恢复该 JSON 分支；「导出成片」完成后下载 MP4。每次导出还会在 `workbench/exports/` 持久保存与 MP4 同名的 `.project.json`，顶栏「导出版本 JSON」下载该次提交的时间线。导出期间继续编辑后，「保存工程 JSON」得到的当前状态可能不同，交付 MP4 时必须配对「导出版本 JSON」。

每条轨道头部的向下箭头用于单轨导出，输出该轨 MP4 与配对 `.project.json`；视觉轨沿用工程背景色，不是透明视频。音频轨也导出带工程底色画面的 MP4，只包含所选轨音频，当前不输出 WAV。逐轨导出与最终成片都使用已提交的项目快照，下载时核对配对 JSON。

界面语言可在顶栏切换为中文。工作台导出不会覆盖原工程 `outputs/`。浏览器自动保存按连接工程隔离；迁移、备份和交接仍需下载项目 JSON、保留对应源码和素材，并实际测试重新导入。

## 2. 五类独立轨道

`build/resolved-timeline.json` 是初始运行时间线；生成的 `build/remotion/src/workbench.ts` 从同一编译 payload 派生，不手抄另一份 `SHOTS` 或秒数表。`build/workbench-manifest.json` 记录支持状态、单元清单和独立音频核验。

| 轨道 | 内容与时间来源 | 独立编辑内容 |
| --- | --- | --- |
| 镜头 | shot 起止、场景、参数、素材和运动 | 起点、时长、裁入、变速；场景参数、组件、物体、人物与背景/replacement 配置通过属性面板编辑 |
| 字幕与其他文字 | cue 区间、文字角色及参数，含独立 `role=title` | 起止、文案、字号、颜色和位置；不会留在镜头内重复烧录 |
| 转场 | motion 的事件区间、配方及前后镜状态 | 单独移动、裁剪、调速和修改转场参数；保留遮挡、切换与落稳阶段 |
| 音效 | 各事件的起点、素材、长度与增益 | 各条音效分别移动、裁剪、调音量或替换素材 |
| 配乐 | BGM 的素材、区间与混音设置 | 与音效分轨，分别移动、裁剪、调音量或替换素材 |

有旁白时另设独立旁白轨。未使用的类别不要求创建空轨；用到的类别不能合并，也不为凑轨道添加无意义素材。镜头内部人物、背景和信息组件通过镜头 props 编辑，不把它们称为逐元素独立轨道。叙事进度等全片叠加项有自己的单元；局部相机运动仍随镜头源时间运行，跨镜转场作为独立片段。

每个单元引用实际组件、props 与 schema。Canvas 的复杂配置可用 JSON 属性编辑；必须保存合法 JSON 并确认画面实际使用该值。文本字段、数值、颜色、开关和枚举按工作台支持的字段类型声明，面板不能只显示一个不会影响渲染的副本。新增参数先补合同、校验和执行器。

素材和人物的属性编辑限于本次 payload 已编译并载入的资源。新增磁盘文件或改为未载入的人物时，先回源工程注册引用并重新 build，再显式导入工作台；在 JSON 属性中填一个新路径或 ID 不代表素材已载入。原 Canvas 合同的组合限制仍有效：含视频素材的工程不能同时使用全镜头场景卡墙后拉 `motion.mosaic-pullback.v1`，应选择直接切镜或其他已支持转场。

代码道具也受已加载绘制器限制：工作台会拒绝没有绘制器的道具 ID，并提示回源工程重建；运行层同样拒绝，不用普通任务方块替代。已加载同一绘制器提供的其他道具可以正常切换。重建前保存当前剪辑 JSON，再显式导入新构建。

### 导出性能与诊断

普通视频卡在导出启动时由 FFmpeg 取出时间线需要的画面，保留源帧时间戳，并把逐帧合成用的图像暂存于本次导出快照。渲染标签页直接读取准备好的帧，避开 Remotion 原生取帧缓存逐出和浏览器视频解码等待。临时帧随任务结束清理，耗时报告的 `videoPreparation` 记录准备耗时。工程 JSON 和声音仍从原素材读取，裁入、变速、音量和静音随剪辑生效。

默认渲染并发为 4。启动工作台前可设置 `PIXEL_RENDER_CONCURRENCY` 为 1–32 的整数；导出请求固定本次并发值，不在任务中途改变。较高并发会增加浏览器内存占用，比较 2、4、6 的实际耗时后再为当前机器和工程选择，内存紧张时退到 2，不按并发比例承诺提速。

导出时显示准备素材、打包、渲染和编码收尾阶段，渲染阶段显示采样平均帧率与画面渲染剩余时间估算；估算不包括后续编码、音频和封装。渲染与编码可能重叠，阶段文字只是当前日志状态，不是互斥阶段的精确计时。

每次任务结束在 `exports/` 写入同名 `.metrics.json`，界面「耗时报告」可下载。报告记录分辨率、工程帧率、并发、渲染帧数、素材复制耗时、渲染子进程总耗时和任务总耗时；`renderAndEncode` 包含 Remotion 打包、渲染、音频与编码，不将重叠工作虚拆为可相加的耗时。剪映另记依赖检查、草稿生成和打包耗时。失败任务也尽量保存报告。

Canvas 转场复用静态场景配置，源帧号、变换与转场参数仍按当前帧更新；场景参数或关联镜头改变时使缓存失效。时间线关联索引按工程对象重建，隐藏镜头仍可作为独立转场导出的引用。升级引擎后通过正常 `workbench PROJECT` 启动流程重新构建生成源码；不要直接修改 `build/remotion/src`，也不要为更新引擎覆盖工作台已保存的编辑 JSON。

素材仍复制到任务独占的 `.render-public/<id>/`，结束后清理；本轮未引入共享可变素材目录、增量素材缓存或已渲染视频缓存，避免导出期间的修改污染素材快照。并发调整不会改变工程分辨率、帧率或编码画质设置。

独立 title cue 会影响源镜头 heading 的显示；首次导入必须保持原合成的标题显隐，编辑标题轨后也应避免旧标题区间仍在镜头内隐藏或重复显示。转场使用关联前镜的当前内容；修改镜头内文案或场景参数后，还要看转场覆盖帧是否同步。

镜头为当前帧的确定性函数，暂停、跳帧和重放须得到同一画面。源时间由裁入点与 `speed` 决定：缩短片段裁掉后续源动作，延长超过源动作末尾时停留在最后一帧；时长修改不会把完整动作重新压缩或拉伸。`speed` 单独控制播放快慢，分割前后源帧连续。转场沿源动作进度播放，超过源时长后保持完成态。

Canvas 视频素材按当前镜头、转场两侧及其引用的历史快照选择解码，不为每个单元打开全片所有视频；镜头退场后释放对应解码器。实时预览在异步寻帧完成后先显示该帧，再处理最新请求，避免寻帧稍慢时持续空白；暂停与最终导出仍等待准确源帧，不能用预览追帧的速度代替逐帧导出核验。

## 3. 独立音频与一致性

源合成使用一次全片预混音；工作台按音效、旁白和配乐独立片段播放与导出，不能再叠加原混音。独立 WAV 保留本次源混音的采样率、起点和增益口径，超出片尾按总长裁切。初始分轨重组与本次 `animation.wav` 的最大 PCM 误差须不超过 1；未通过时先修复，不能以近似音轨冒充一致或回退直接交片。

事件音量、声像、归一化、旁白压低、淡化和 master 包络按本次源版本烘焙，工作台初始 `volume=1` 是相对倍率。编辑后不会动态重算其他轨道的压低；移动、增删或调音量后重新听音，需要重算时回改源工程并重新构建。

## 4. 编辑存档与原创作源

首次导入由当前有效构建派生。开始编辑后，工作台项目 JSON 是这条剪辑分支的创作源，包含轨道、片段时间、props 和音频设置。

- 工作台不会自动回写 `project/timeline/text/audio.json`，也不会绕过导演 `source-map.json` 修改 `script/storyboard/production-plan`。
- 沿原导演方案继续制作时，回改导演源并 handoff、build，再显式导入；沿工作台分支继续时，加载已保存 JSON。
- 上游重建、切换工程或重新导入原合成前，先下载当前工作台 JSON，不能静默丢弃用户编辑。
- 最终成片从工作台当前项目导出。原 `render PROJECT` 得到原 VideoSpec 分支，只能作为调试或一致性对照。
- `build/remotion/src/workbench.ts` 及生成 TSX 不是持久修改入口，下次构建会重写。

移动一个片段不会自动移动全部关联字幕、转场和音效。镜头重排、拉长、删改后逐轨检查关联片段和总片长，再保存新的剪辑决定。

## 5. 必须实际验证编辑与导出

在工作台应用目录执行 parity，帧号按当前片长选择，覆盖首帧、镜头稳定态、转场前中后和尾帧：

```text
npm run parity -- --frames 0,150,300,327,354,474,600,780,899
```

示例帧号适用于 900 帧工程。parity 对照未编辑导入与原合成，同帧 PNG 差异像素低于 0.1% 才算一致；不以越界帧代替有效检查。视觉 parity 不证明音频一致，另核对分轨 PCM、实际播放和听音。

交付前用真实 UI 完成以下操作，记录当前输入版本、保存 JSON、导出 JSON 与 MP4：

1. 打开工作台连续播放，核对总长、全部场景/组件、人物、素材、文字、转场和声音。
2. 独立修改字幕和一处镜头属性，确认即时生效；分别调整镜头位置、裁入或长度，检查源动作与关联轨道。
3. 独立移动或调整一段转场，查看前、中、后帧与连续动作，确认未同时移动字幕或声音。
4. 分别调整音效和配乐的位置与音量，实际听音；有旁白时也检查旁白，确认无旧全片混音重复播放。
5. 保存刷新，下载 JSON 后重新导入，逐轨确认修改仍在；分别导出使用中的视觉和音频轨道，检查导出只包含所选轨道；再从工作台导出成片 MP4，下载同次「导出版本 JSON」。
6. 检查真实 MP4 的帧数、时长、修改后画面、字幕、切点和音频；需要保留原版时先恢复原 JSON，验收改动另存。

只检查 Studio、只导出源合成、只生成清单/schema 或只通过单元测试，均不能记为工作台剪辑交付通过。未完成的画面或听音检查记为 `not_reviewed`。任何选用能力不能独立编辑、保存或导出时，先补齐实现与验证，不能静默绕过工作台。

## 6. 可迁移交付与边界

用 `export-project` 导出源码、锁文件、同源生成逻辑、素材和运行说明，再单独保存工作台 JSON 与匹配 MP4。排除 node_modules、缓存、浏览器和渲染临时目录，保留上游许可和署名。平台支持以当前真实运行证据为准，不因路径兼容或上游说明扩大范围。

匀速变速、裁入与片段时长不能替代动作阶段重设计。工作台也不提供把剪辑自动反编译为导演源或四份 VideoSpec 的往返同步。需要剪映时按 [剪映草稿导出](jianying-export.md) 另行导出与验收；剪映中的内部动画可编辑程度不等于工作台 props 能力。

## 7. 字幕方案与实际组件检查

有可见字幕时，顶部“字幕方案”可选柔边重音或保留本片设计。前者会把字幕轨的实际片段换为 `soft-highlight-caption`，保留文案与剪辑区间，转换可撤销；关键词由编辑者按语义填写。后者需说明本片选用依据，保留原组件。保存 JSON 中的 `captionDesign` 与实际卡 ID 一同核验，工作台和服务端均会阻止缺少选择或声明不符的导出。旧工程不自动替换外观，导出前补齐选择；不自动检测镜头内烘焙文字或判定审美。具体参数与支持范围见 [柔边字幕](../modules/text/SOFT-HIGHLIGHT.md)。
