# 本地工作台：多轨编辑与成片导出

本 skill 的 `workbench/` 复用 video-shotcraft 的浏览器工作台，提供多轨时间线、属性面板、Remotion 实时预览和 MP4 导出。Remotion Studio 仍用于检查原合成；工作台用于直接修改文案、镜头和音效。两者不是同一个界面。迁移代码的许可与署名保留在 [LICENSE](../workbench/LICENSE) 和 [NOTICE](../workbench/NOTICE)。

默认 Canvas 和现有四份 VideoSpec 合同保持不变。工作台当前面向原生 Remotion 的书桌场景和已支持运镜；不能由此推断 Canvas 场景或能力目录全部已接入。独立音轨现包括事件音效、PCM 旁白和 BGM；导入前按本次构建核对分轨重组与原混音的 PCM 一致性。

当前桥接也拒绝含独立 `role=title` cue 的工程，避免标题片段移动后仍按原区间隐藏镜头标题。每个书桌镜头的 `heading`、标题字号、颜色和位置仍可在属性面板编辑；独立 title cue 的原 Remotion 构建与导出继续可用。

## 1. 启动与交付

在本 skill 根目录执行；`PROJECT` 是 VideoSpec 工程目录，导演工程使用 `PROJECT/video`：

```text
python scripts/video.py workbench PROJECT --port 5208 --no-open
```

命令先构建原生工程，生成同源清单，再把工程连接到工作台。首次使用自动按 `workbench/package-lock.json` 安装 Node 依赖；当前 Node.js 需 18.18+，Remotion 固定 4.0.534、React 固定 19.2.0，不沿用上游另一版本。默认端口 5208，仅监听 `127.0.0.1`；终端打印的实际地址是入口。省略 `--no-open` 时可自动打开浏览器；交付时主动打开地址供用户编辑。

工作台的「保存工程 JSON」立即保存当前状态并下载快照，「导入」可恢复该 JSON 分支；「导出成片」完成后可下载 MP4。每次提交导出时，还会在 `workbench/exports/` 持久保存与 MP4 同名的 `.project.json`，记录该次导出实际采用的时间线；顶栏的「导出版本 JSON」下载这份快照。导出期间继续编辑后，「保存工程 JSON」得到的是当前编辑状态，与已提交的导出版本可能不同。交付 MP4 时配对下载「导出版本 JSON」；重启工作台后，已保存的文件仍可从 `workbench/exports/` 取回。

界面语言可在顶栏切换为中文。工作台导出不会覆盖原工程的 `outputs/`。浏览器自动保存按连接工程隔离，迁移、备份和交接仍需下载项目 JSON、保留对应源码和素材，并实际测试重新导入。

## 2. 首次导入必须与原合成同源

`build/resolved-timeline.json` 是初始运行时间线；生成的 `build/remotion/src/workbench.ts` 从同一 payload 派生，不手抄另一份 `SHOTS` 或秒数表，也不把成片 MP4 作为唯一可编辑片段。

清单按原始帧率、画幅、总帧数和背景拆出：

| 单元 | 内容与时间来源 | 编辑方式 |
| --- | --- | --- |
| 镜头 | 编译后的 shot 起止、场景 params 与运动 | 时间线起点、时长、裁入、变速；属性面板中的文案与受支持样式 |
| 字幕与文字 | 编译后的 cue 区间及文字参数 | 独立文字片段与属性面板 |
| 转场 | 编译后的 motion 及前后镜状态 | 独立转场片段；保持遮挡、切换与落稳阶段 |
| 音效、旁白、配乐 | 编译后的各音频起点、长度、素材与增益 | 分别放入独立轨道，可调整位置、时长、音量或替换素材 |

每个片段引用组件及实际 props，并声明可编辑 schema。文本字段可用 `text`/`textarea`，数值、颜色、开关和枚举按工作台支持的字段类型声明。镜头 heading、labels 与字幕要指向画面真正读取的 props，不能只在面板中显示字段。新增输入参数先补合同、校验和执行器。

镜头组件应为当前帧的确定性函数，暂停、跳帧和重放得到同一画面；补间必须处理边界。镜头的源时间由裁入点与 `speed` 决定：缩短片段会裁掉后续源动作，延长超过源动作末尾时停留在最后一帧；时长修改不会把完整动作重新压缩或拉伸。`speed` 单独控制播放快慢，分割前后的源帧保持连续。转场沿原动作进度播放，超过源时长后保持完成态。修改后核对动作末态、字幕区间与声音落点。

Studio 原合成使用一次全片预混音；工作台按独立音效片段播放和导出，不能再叠加原全片混音，否则会重复发声。独立素材必须保留原混音的采样率、时点和增益口径，超出片尾按合成长度裁切。

`build/workbench-manifest.json` 记录支持状态、清单与独立音频核验。事件音量、声像、归一化和 master 软限幅已烘焙进独立 WAV，工作台初始 `volume=1` 是相对倍率。初始独立混音与原 WAV 的最大 PCM 误差须不超过 1；重叠音效经过非线性 master 后可能不能逐条精确相加，此时工作台明确拒绝，原 Remotion 制作与导出继续可用。不能以近似音轨冒充已通过一致性检查。

## 3. 编辑存档与原创作源的边界

首次导入的工作台项目由当前有效构建派生。开始编辑后，工作台项目 JSON 是这条剪辑分支的创作源，包含轨道、片段时间、props 和音频设置；清单仍是可重新导入的原版入口。

- 工作台不会自动回写 `project/timeline/text/audio.json`，也不会绕过导演 `source-map.json` 修改 `script/storyboard/production-plan`。
- 沿原导演方案继续制作时，回改导演源并 handoff、build；沿工作台分支继续剪辑时，加载已保存的工作台 JSON。
- 上游重新构建或切换工程前，先下载当前工作台 JSON。重新导入原合成属于显式的版本操作，不能静默丢弃用户编辑。
- 工作台改过的片子用工作台当前项目导出；直接运行原 `render PROJECT` 仍得到原 VideoSpec 分支，不能声称两个版本自动同步。
- 生成的 `build/remotion/src/workbench.ts` 及 TSX 不能作为持久修改入口；下次构建会重新生成。

片段拖拽遵循工作台的时间线操作：移动一个片段不等于自动移动全部关联字幕、转场和音效。镜头重排、拉长、删改后，检查相关轨道和总片长，再决定是否一起移动关联片段。新的剪辑决定应保存在工作台 JSON 中。

## 4. 导入一致性与实际操作验收

在工作台应用目录执行 parity；下例帧号适用于 900 帧的 15 秒/60fps 示例，其他工程按实际片长选择：

```text
npm run parity -- --frames 0,150,300,327,354,474,600,780,899
```

parity 对照未编辑导入与原合成，同帧 PNG 的差异像素低于 0.1% 才算一致。覆盖首帧、镜头稳定态、转场前中后和尾帧；超出总片长的帧号不应被当成有效检查。视觉 parity 不证明声音一致，另核对独立音效混音的时点、音量和实际听音。

交付前完成以下实际操作，记录当前输入版本、存档与导出文件；命令通过不能代替 UI 验证：

1. 打开真实工作台，导入后连续播放，检查原总时长、镜头、文字、转场与声音。
2. 在属性面板改一句字幕和一处镜头内文案，确认画面即时改变；保存、刷新后仍保留。
3. 移动或拉长一个镜头，检查裁入、动作、停留、关联字幕/转场和声音；不产生越界或意外空档。
4. 单独调整一条音效的位置与音量，实际听音；确认修改没有同时播放旧全片混音。
5. 下载项目 JSON，重新导入并验证内容；随后从工作台导出 MP4，下载「导出版本 JSON」，核对同名 `.project.json` 与该次导出配对，再检查真实成片的帧数、时长、文字、切点和听音。
6. 用户要保留初始成片时，恢复原始项目 JSON 后再交付；操作实验另存，避免把验收改动当成用户默认版本。

只检查过 Studio、只导出过原合成或仅声明了 schema，均不能记为可视化编辑交付通过。未运行项目继续标为 `not_reviewed`。独立工程导出需包含工作台源码、锁文件、同源生成逻辑与运行说明，排除 node_modules、缓存、浏览器和渲染临时目录；迁移的代码保留仓库中的上游许可和署名。

## 5. 已知边界

- 工作台是额外的本地应用，不把原 Remotion Studio 的播放头当作保存剪辑的工具。
- 当前不提供把工作台编辑自动反编译为导演源或四份 VideoSpec 的往返同步。
- 当前桥接不导入独立 `role=title` cue；镜头 `heading` 仍可编辑，原 Remotion 的 title cue 制作流程不受影响。
- 匀速变速、裁入和片段时长不能替代动作阶段重设计；修改后需重新看完整转场与字幕阅读时间。
- 需要在剪映中继续剪辑时，按 [剪映草稿导出](jianying-export.md) 使用「导出剪映草稿」。字幕与音效分轨，镜头内部动画和 heading 烘焙。导出中立包与本机安装分开，目标版本需实际验收；剪映配音素材流程仍单独维护。
- 当前真实验证环境以本轮实际记录为准，不能仅凭路径兼容或上游说明扩大平台支持范围。

## 旁白与配乐分轨

原生书桌工程可拆分旁白与 BGM。初始分轨共享原混音的 master 增益包络，并按采样分配整数舍入误差；重组后与本次 animation.wav 逐样本核对。每段 WAV 保留自己的起点与长度，不另叠加全片混音。旁白压低、淡化和 master 包络在本次源版本中烘焙；移动、增删或调音量后不会动态重算其他轨道的压低，需重新听音；需要重算时回改源工程并重新构建。此扩展不包含 Canvas 场景或独立 title cue。
