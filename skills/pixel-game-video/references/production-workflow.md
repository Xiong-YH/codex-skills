# 制作与可编辑时间线

分镜先落实为 [制作合同](contract.md) 的四份 VideoSpec，再从同一编译结果进入 [本地工作台](workbench.md)。制作视频必须在工作台完成剪辑并从当前项目导出最终成片；镜头、字幕与其他文字、转场、音效、配乐分别独立轨道，有旁白时另设旁白轨。Canvas 和原生 Remotion 共用这个交付流程，直接 `preview`/`render` 只用于源合成调试或一致性对照。

## 1. 把分镜落实到唯一初始创作源

先明确每镜表达、主体初态与终态、动作、文字、前后承接和声音。按脚本为动作落定、阅读和预估讲述留出帧数，再在工作台粗剪；已有旁白作为素材导入后按实长精调。配音生成不属于本流程，不自动打开剪映或调用 TTS。时长、画幅和风格遵循当前项目。

| 剪辑决定 | direct 工程修改处 | director 工程修改处 |
| --- | --- | --- |
| 镜头顺序、时长、事件 | `timeline.json` | `storyboard.json` |
| 字幕、注释等文字 cue 的文案 | `text.json` | `script.json` |
| 场景内文案 | `timeline.json` 的 params | `script.json` 的 labels，经 storyboard 引用 |
| 字幕起止 | `text.json` 中的事件引用 | `storyboard.json` 的文字区间 |
| 场景机制、参数、组件与物体 | `timeline.json` | `storyboard.json` |
| 人物、素材、运镜、转场及事件绑定 | `timeline.json` | `production-plan.json` |
| 画幅、帧率、风格与后端 | `project.json` | `production-plan.json` |
| 音效、旁白、BGM、增益及事件绑定 | `audio.json` | `production-plan.json` |

director 工程按 `source-map.json` 回改创作源再 handoff；`video/` 是生成物。direct 工程直接编辑四份 VideoSpec。`build/resolved-timeline.json`、`build/remotion/` 均为派生物，不能手改生成 TSX 作为持久编辑入口。

## 2. 编译唯一整数帧时间线

镜头按顺序和 `durationFrames` 累计；本镜事件使用局部整数帧，字幕、动作和声音通过事件引用对齐，例如 `{"event":"s01.choose","offsetFrames":0}`。

运行 `validate`、`build` 后，检查 `build/resolved-timeline.json`：

- 镜头、字幕和运动遵循 `[startFrame,endFrame)`；相邻镜头连续，最后结束帧等于总片长。
- 动作开始、落定、字幕阅读时段和声音落点使用同一事件时间线。
- 转场从后镜 `enter` 开始，占用后镜时长；按执行器检查前镜末态、遮挡切换和后镜落稳。
- 上游镜头长度修改后，检查下游事件、文字、旁白和配乐边界，修正源引用并重新构建。

分镜表记录设计意图，运行只消费编译结果。不能另写 `SHOTS`、`timeline.ts` 或秒数表覆盖现有合同。

## 3. 同源拆成工作台轨道

运行 `python scripts/video.py workbench PROJECT --port 5208 --no-open` 并打开实际地址。`build/remotion/src/workbench.ts` 从编译 payload 生成镜头、文字、转场与音频单元；`build/workbench-manifest.json` 记录支持状态和音频核验。

Canvas 路径在 React Canvas 单元内运行现有逐帧绘制器，保留场景、组件、背景/replacement、物体、事件姿态与转场；叙事进度独立为叠加单元。原生 Remotion 路径按 [能力边界](remotion.md) 使用已有 React 场景。Canvas 桥接不扩大原生场景白名单，也不把整片 MP4 当作镜头源。

每个镜头有自己的 props/schema，场景参数、组件、人物与素材配置须由实际渲染读取。字幕和独立标题从镜头画面移出为文字单元，跨镜转场也独立为片段；镜头内部对象与相机运动仍通过镜头参数、源时间控制。暂停、跳帧、重放应呈现同一帧状态，不用真实时间或未固定随机数驱动画面。

先运行 parity，核对未编辑导入与源合成同帧一致；选帧覆盖各类实际使用能力与转场前中后。再做真实 UI 操作，不能以 schema 已生成代表编辑已生效。完整验收见 [工作台](workbench.md#5-必须实际验证编辑与导出)。

## 4. 在工作台完成剪辑与声音对齐

分别编辑镜头、字幕、转场、音效和配乐。镜头长度变化遵循裁入与源时间：缩短裁掉后续动作，超出末尾保持末态，`speed` 单独改变播放快慢。移动镜头不自动移动关联字幕、转场和声音；逐轨检查切点、动作落定、阅读时间与总长，再保存。

原合成的 Python 混音器生成一次全片 WAV；工作台使用独立音效、旁白和 BGM，不再叠加旧混音。初始分轨共享本次源混音的增益口径，逐样本重组核对，PCM 最大误差须不超过 1。各条音效、配乐和旁白可分别调整位置、裁入、时长、音量与素材。

淡化、旁白压低与 master 包络按源版本烘焙；后续移动、增删或调音量不会动态重算其他轨道的压低。改动后实际听音，需要重算时回改源并重新构建，再显式导入。未使用的类别不要求创建空轨，也无需添加无意义素材；实际用到的类别必须分轨。

工作台修改后，项目 JSON 是剪辑分支的创作源，不自动回写 VideoSpec 或导演源。上游重建、切换工程前下载当前 JSON；继续该分支时从 JSON 恢复，不能用重新导入原合成静默覆盖剪辑。

## 5. 预览、导出与视听审查

在工作台连续播放全片，检查状态变化、所有文字、转场承接与声音。必要时用 Canvas 的 `build/film.html` 或原生 Remotion Studio 排查源执行器，但这些查看操作不保存剪辑决定，也不代替工作台验收。

交付前实际完成：分别修改五类轨道、确认画面/声音改变、保存刷新、下载并重导入 JSON，逐轨导出并检查所选内容，再用「导出成片」导出当前时间线。导出期间继续编辑会产生新状态，必须把 MP4 与该次「导出版本 JSON」配对；文件持久保存在 `workbench/exports/`。

检查真实 MP4 的帧数、时长、修改后文案、切点、转场解码帧和听觉同步。首次导入 parity 只能证明原版拆解一致，不能替代编辑后成片审查。技术核验、实际播放、文字核验和听音分别记录，未检查项保持 `not_reviewed`。

不能用额外 FFmpeg 拼接、变速、烧字幕或挪声音形成未保存的最终剪辑版本。发现某个选用能力不能进入工作台、独立编辑或导出时，先补齐并验证；不能回退直接 `render` 后声称工作台交付完成。

## 6. 交付可继续编辑的工程

最终交付包含 MP4、同次导出项目 JSON 与实际核验证据，并主动打开工作台、提供当前地址。需要独立工程时使用 `export-project`，包含四份输入、运行源码、素材、工作台与依赖说明；director 工程另存原始创作源、源映射和 Review。浏览器自动保存不是可迁移交付物，必须下载项目 JSON 并实测重导入。

需要剪映工程时，按 [剪映草稿导出](jianying-export.md) 另行生成和验证。该可选交付不替代工作台剪辑及最终 MP4 导出，也不把程序动画称为剪映可逐元素编辑。
