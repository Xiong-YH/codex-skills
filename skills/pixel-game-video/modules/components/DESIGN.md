# 自定义组件：从脚本到可复用能力

自定义组件根据当前片段的内容与解释任务设计实体、局部状态、形变或关系机制；已有组件很贴合时直接复用。目标是让本段观点可见，不是为每镜发明装置，也不是把脚本塞进固定仪表。基础组件选型仍按[基础规则](BASIC-COMPONENTS.md)；执行与接入按[实现协议](CUSTOM-RUNTIME.md)。

## 当前创作偏好

优先从片段内容构思适合的自定义组件表达，再判断已有能力是否贴合；不以“基础组件勉强能装下内容”为停止设计的理由。已有组件在语义、形态和行为上已经很贴合时直接复用；没有合适且有解释增益的自定义方案时，采用合适的基础组件、组合或场景表达，不为自定义而硬造。无需自定义数量、比例或每片段配额。脚本明确本次选择和理由，沿下面的五维与实际能力边界制作。

## 先从脚本提炼需求

先用一句话写清“观众通过哪个可见变化，理解什么”。提取主体、关系或数量、初态、触发、动作、末态、需要保留的东西及前后镜承接。缺失的视觉决定由制作 agent 按内容补齐并说明假设，不要求用户先写组件代码。只有影响观点、事实或已确认风格的歧义才追问。

静态定义、组成和比较也可使用自定义组件；没有变化时写清阅读关系，不凭空添加破坏、充能或人物。解释“风险”不必碎裂，解释“比较”也不必天平。

| 判断 | 选择 | 交付深度 |
| --- | --- | --- |
| 现有 kind 的语义、形态、布局与事件已经很贴合片段 | 基础组件 | 引用 kind、内容及本次变化，不重复五维 |
| 多个现有单元只是摆放或按事件显露 | 组合配方 | 组件引用、锚点与事件关系；不复制绘制器 |
| 同一主体需要新的形变、状态联动、接触或遮挡 | 自定义组件 | 对变化部分写五维、最小试样和实际调用边界 |
| 涉及独立对象的业务因果、完整空间、人物表演或跨镜承接 | scenes 编排 | 场景引用组件；不把整镜做成巨型组件 |

从片段关系构思后，查能力目录和[已有物体实例](OBJECT-COMPONENTS.md)，按表达关系、动作机制、视角、输入范围、接入状态比较，不仅按名称或截图相似度。能够复用的保留；形态可适配但机制不符时重设计机制。新组件可先留在当前项目，实际有复用价值时再收纳。

## 根据内容选择形态

先问什么关系必须看见，再决定用什么载体。以下是思考方向，不是类别白名单：

| 内容关系 | 可探索的画面 | 设计时要回答 |
| --- | --- | --- |
| 数量或状态变化 | 刻度、堆积、队列、液位、仪表 | 是真实数量还是示意？单位、基线和上限是什么？ |
| 转移与归属 | 容器、轨道、交接、装入 | 同一对象从哪里到哪里？何时换归属？谁遮挡谁？ |
| 组成与拆解 | 实体分层、展开、剖面、模块装配 | 层数有无事实依据？拆开后如何对应原位置？ |
| 限制与取舍 | 容量、瓶颈、门槛、天平 | 哪个约束导致结果？隐喻是否误导成定量证据？ |
| 连接与传播 | 端口、通路、接点、分支 | 起点、终点与方向？传到哪里才算完成？ |
| 修正与反转 | 替换、断开、回退、失效、重组 | 哪些保持身份？哪些真的被移除或产生？ |

选择最直接的表达；只有存在实质取舍时才比较少量候选。审查理解增益、语义准确、风格同框、动作可读、素材可得，以及实现成本是否与项目范围相称。不能因实现方便把所有内容做成面板，也不以新奇或特效强度代替解释作用。

新组件的形态与素材生成遵循 [组件共同画风](../style/COMPONENT-ART.md)，五维中的形态、素材与动作应指认材质分工、相对厚度、受光、接触和主次；不按 kind 各维护一套美术规则。

## 五维设计

<a id="组件五维"></a>

在项目设计附件中按下面五维写一份短约定；轻量任务可在分镜意图中写完。已有组件仅展开本次变化，不逐项等待审批。较长记录用[需求记录模板](custom/design-template.md)，由镜头 intent 指认；这是设计附件，不是第五份可执行创作源。

| 维度 | 必须明确 |
| --- | --- |
| 表达 | 本段问题与可见答案；主体及子对象身份、真实值/示意值；初态、触发、末态；什么保留、转移、替换或消失 |
| 形态 | 按对象选择外形、视角、比例、材质、光源、像素密度、主次与阅读区；与本镜背景同框成立 |
| 动作 | 状态及转换，起动→路径/形变→触点→收束→保持；用工程事件绑定；连续身份、数量与结果不丢失 |
| 素材 | 最小必要图层、初末态及中间态、锚点、接触点、容纳平面、真实遮挡轮廓；来源、缺口与制作方式 |
| 能力 | 复用/组合/新增的理由；参数与合法范围；当前后端、试样入口、工程适配方式、未实现项和验收范围 |

自定义不必选风格；选择机械或能量时仍遵守互斥及 stack 继承约定。不强塞基础组件的 open/inset/relay 外形。动作与阅读分开，时长按[motion 节拍](../motion/TIMING.md)；概念演示里的慢放、长增长或停留不直接成为正式视频节奏。

## 设计必须落到可观察的状态

给需要跟踪的子对象稳定 ID，写清变化触发和结果。状态可很简单，不要求复杂状态机。对每个关键变化问：关闭字幕后是否仍能看出关系？状态停住后是否仍有意义？倒拖回来是否恢复同样的画面？

例如“长期平安不保证下一次安全”：仪表的天数和示意状态一起增长；risk 后原条块失效并脱离，settled 后保留碎块和天数。这是候选隐喻，不是风险事实的测量，也不是所有组件的默认剧本。可运行范例见[状态仪表](examples/state-meter/index.html)，其设计记录见[本例约定](examples/state-meter/design.md)。

## 试样、接入与沉淀

1. **最小完整表达**：必要的起态、变化和末态，支持播放/暂停、逐帧或拖动。静态组件验证完整阅读状态。先看真实结果，再扩展装饰和布局。局部任务到试样即可，不强制整片制作。
2. **核验声明范围**：连续播放和关键帧；倒序/跳帧后与同帧一致；对象无意外重复/丢失、触点对齐、遮挡可信、结果保持。声明支持位置/尺寸/数量/标签变化时，测试对应变化及合理边界；不宣称任意容器或视角可用。
3. **按实际路径接入**：自定义试样不是新的 shot.components.kind。内部参数可编辑需求选已注册场景适配器；烘焙素材仅适合明确接受内部不可编辑的情况。具体步骤和工作台约束见[实现协议](CUSTOM-RUNTIME.md)。设计未实现时补齐，不用相近基础组件静默降级。
4. **沉淀已形成的能力**：保留设计、参数合同、状态/绘制源码、可播放例子、来源与验证范围。登记在现有 object-components.json，补 capabilities 引用；不能因收纳而把 standalone 改称 registered。第二次真实使用时再抽共用机制，避免提前搭全能框架。

复盘只把可复用结论写回所属规则；本片文字、事件帧、人物和配色留项目。设计质量、代码测试、视觉审查、工作台接入、成片审查与用户认可分别记录，未检查保留 not_reviewed。旧筹码和供能装配实例按原入口继续使用，不强制迁移或扩大其验证范围。
