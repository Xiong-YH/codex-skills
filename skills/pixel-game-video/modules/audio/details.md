# 声音与混音

常用库为九种固定 WAV 原子，ID、用途与试听见 [ARCADE](ARCADE.md)。旧 G2 只保留历史工程兼容；废弃扩展和持续蓄力不进入常用库。旁白和配乐按项目选择，不自动生成配音或调用 TTS。

## 使用顺序

### 先减触发，再调强弱

1. **默认留白。** 先安排画面、旁白与配乐，再选需要听觉强调的关键变化。有动作、匹配音色或能卡点，都不是必须发声的理由；允许连续多镜没有音效，不设固定次数或音色覆盖率。
2. **按动作组选择。** 需要声音时，优先只留关键结果：搬起→移动→落位→计数通常只考虑落位；受阻声取代点击声，完成声取代同一结果的落位/确认声。起落各有解释任务时才考虑双触点，整组也可以无声。
3. **普通变化安静。** 字幕、标题、普通入场、焦点浏览、待机、装饰与连续进度默认不响。重复操作只挑值得强调的一项或组结果，不逐项复制 cue。
4. **强弱服务主次。** 轻提示交代输入，中等触点交代状态，奖励只强调真正完成。重要声音之间留安静间隙，尾音不能持续接力；旁白和阅读优先。配乐已强调同一动作时可省去音效。先删多余触发，再调音量，不能只靠全局降音量解决嘈杂。
5. **审片做删音对照。** 同画面、旁白、配乐下比较移除次要 cue 的版本；理解或必要表现力没有明显损失，就采用删减版。分镜或 review 简要写清保留触点的作用，无需为每条声音新增字段或长篇说明。听整段及跨镜连接，仍有重复确认、连续叮咚、抢话或尾音侵占留白就继续修；未实际听音保留 `not_reviewed`。

声音是否必要由创作与实际听音判断。同步准确、音量小、间隔达标不等于听感通过；编译器和混音器不会自动判断嘈杂、按语义去重或限频。

## 工程配置与执行边界

- 基础工程在 `timeline.json` 定义镜头事件，`audio.json.cues` 引用；导演工程在 `storyboard.json` 定义事件、`production-plan.audio` 选声音，由 handoff 生成基础工程。保留无声动作的视觉事件，只删多余音效条目；工作台剪辑分支直接修改其音效片段。
- cue 字段为 `id / sound / at / level / x / variant`。`at` 使用 `{event, offsetFrames}`，表示声音开始时间；九种正式原子只支持 `variant=0`。`level` 和 `x` 均为0–1，默认0.5；`x`仅做轻度声像平衡。catalog 中的主触点和建议间隔不自动调整 cue。
- `arcade.py` 读取固定母版并校验哈希；`mixer.py`逐 cue 混入。双声道母版不先归一化，随后仍受 cue 增益、声像、旁白压低和总线处理影响，因此最终混音不与母版逐字节相同。旧 G2 单声道沿用原归一化逻辑。
- 输出为48kHz、16-bit、双声道 PCM，按成片帧数定长；超出片尾的尾音会被截断，需预留收尾。`sfx-events.json`记录实际事件、采样点、时长、增益策略与混音峰值/RMS。

## 旁白与配乐

`project.audioMode="narration+sfx"`配合 `audio.json.narration` 的 `id/file/at/gain` 导入现成旁白。文件须在项目内，48kHz、16-bit、单或双声道 PCM WAV，不得重叠或越界；编译绑定素材哈希。旁白先归一化再乘自身 gain，音效的 `speechDuck` 不压低旁白，但最终总线仍处理全部声音。[历史音色](VOICES.md)只作参考，不代替当前台词，也不意味着已有 TTS 或口型对齐。

顶层 `audio.json.speechDuck` 是旁白期间音效保留比例，默认0.28；导演在 production-plan 设置同名字段。可选 `bgm` 有独立的 gain、淡化、循环和 `speechDuck`（默认0.25），见 [配乐工作流](MUSIC.md)。`silent` 模式不输出音轨。实际 MP4 仍需听音核对，素材认可与成片验收分别记录。
