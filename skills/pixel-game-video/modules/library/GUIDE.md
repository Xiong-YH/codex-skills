# 素材库

只维护素材身份、形状、锚点、变体和来源；不维护镜头时间。人物以 [已确认人物库](CHARACTERS.md) 为当前入口，完整素材随本 skill 独立分发。

| 文件 | 用途 |
| --- | --- |
| `catalog.json` | 素材 ID、原生尺寸、锚点、哈希 |
| `characters/` | 已确认 V3 五人、人设、30 张动作参考、使用规则和生成提示词 |
| `prepare.py` | 校验原图哈希与实际尺寸，裁取声明的预览范围，不重画像素 |
| `runtime.js` | 放置人物、缓存三种像素物体 |
| `actor-performance.js` | 旧叙事路径的整图放置适配；不再切分旧角色关节 |
| 完整人物与情境插画 | 新姿态作为完整画面制作，按镜头导入；[流程与可运行样例](../scenes/whole-illustration.md) |

当前人物：`actor.azong.v3`（主角阿棕）、`actor.amo.v3`、`actor.lizi.v3`、`actor.laomai.v3`、`actor.chen.v3`（半身专题配角）。身份、主配角、人设和动作参考均已确认；各人的脸型、眉眼、鼻口与衣服须锁定。
既有场景使用 `reference-static` 单张基准图，保持原始像素和透明度；动作参考不是连续动画。拆头像/躯干试样因人头分离、比例失衡被用户否定，已经退出运行和分发。动态插画优先保持完整人物和场景，以相邻姿态或片段接入；不宣称五人都有动画适配。
物体：`prop.task-block.v1`、`prop.book.v1`、`prop.core.v1`。
计算机物体在 `computing.js` 独立维护：请求端终端、原始数据仓、缓存副本盒与带 A/B 身份的数据块；场景只编排这些物体，不复制它们的绘制代码。
`education.js` 独立维护学位帽、公文包、项目电脑与目标图标，均为代码绘制的 64×64 像素物体；文案和镜头时序不进入素材绘制器。
这些文件从原始工程保留；构建过程不读取历史目录。

项目放置物体：`{id,asset,x,y}`；坐标按画幅归一化，范围 0–1。
物体 ID 供运动引用；素材 ID 供查库。同一素材可以生成多个物体。
书封是二维正面图层，没有三维书脊或封底；翻转不会产生镜像字。

新增静态人物需声明原始尺寸、哈希和预览边界；要实现口型、眨眼或骨骼，再提供对应脸部/关节适配与完整变体，并更新能力状态。
换角色前核验静帧比例、半身/全身构图和场景使用规则。模拟语音节奏仍由 [scenes/performance.py](../scenes/performance.py) 管理，但当前 V3 图片不会消费该节奏生成嘴型；位移归 [motion](../motion/GUIDE.md)。

`P.library.perform` 现在只放置完整基准图并提供道具布局参考点，供既有叙事路径预览；它不实现跑步、伸手、抱持或逐帧表演。需要这些动作时，用已确认动作图生成并核验新素材，再接入，不恢复已删除的旧角色切片。
