# 游戏反馈细节库

用于把已经设计好的选择、资源变化、操作结果做得可感知。先确定发生了什么，再组合局部反馈与声音。转场仍从 [转场库](../motion/TRANSITIONS.md) 选型，这里的细节不增加转场种类。

目前收纳 **6 类反馈细节**，在 [竞赛场景](competition-routes.md#游戏反馈) gameplay 模式中有执行示例。用户认可与各版本边界统一见 [迭代记录](../../references/iteration-history.md)。表中声音保留最初设计语义，当前项目按 [ARCADE](../audio/ARCADE.md) 使用六种已确认原子；新内容另定数量、强度和节奏。

| 设计索引 | 触发与可见动作 | 声音与节奏 | 检查重点 |
| --- | --- | --- | --- |
| `detail.focus-lock.v1` 焦点锁定 | 目标已出现；四角标记靠近边缘并固定，形成选中状态 | 标记落定时用 select；可试0.25–0.45秒进入，之后保持 | 目标身份清楚；标记避开正文，不持续闪烁 |
| `detail.contact-response.v1` 触点回弹 | 物体抵达后，局部轻抬或回落，短边框强调，随后稳定 | 接触帧用 lock / node-connect；可试0.15–0.25秒收尾 | 不压扁卡片或文字，不震动整个房间；阅读时停止 |
| `detail.resource-transfer.v1` 资源转移 | 源槽腾空；同一枚有编号的筹码沿短弧线移动；落槽后目标计数增加 | 提取时 extract，落槽时 lock；飞行可试0.4–0.6秒，下一枚等前枚落稳 | 搬运不是复制：源、途中、目标始终只出现一份；总量和编号守恒 |
| `detail.state-confirm.v1` 状态确认 | 操作逐步完成；检查点亮起；全部条件满足后出现一次完成标记 | 单点使用轻 node-connect，最终用 verified；只奖励实际完成的状态 | 完成标记不提前出现；粒子、光效不遮住数字与结果文字 |
| `detail.milestone-progress.v1` 阶段进度 | 可见项目分组完成；计数和进度条随实际完成项更新 | 每组结束用 stage-done；组内视觉可连续，声音不逐项轰炸 | 计数等于完成格数，保留阶段停顿；时间推进是示意，不虚构真实成果 |
| `detail.quest-settle.v1` 任务结算 | 任务完成后给出下一步，如检查结果、回看投入、选择路线；轻落定后保留 | 结算触点用 commit；入场可试0.2–0.4秒，随后留阅读时间 | 结算推进下一步；不凭空生成能力分数、奖励承诺或多余弹窗 |

表中时长是设计起点，实际帧数只写在 storyboard 事件中。短片通常挑几个有语义的触点组合；长内容可以放宽停顿。当前项目保留32秒、站立口播与固定比例镜头，不把这些具体条件推广到其他工程。

## 使用与复用

分镜先记录“触发对象 → 状态变化 → 可见反馈 → 稳定结果”。再决定是否需要声音；轻提示、接触、阶段完成使用不同强度。主运动、局部反馈、标题出现应分出注意力先后。

`detail.*` 是设计索引，不能写入 VideoSpec 的 motion recipe。可复用的短弧线、缓动、位置回弹、角标和粒子辅助位于 [motion/game-feedback.js](../motion/game-feedback.js)；它只接受几何与归一化进度，不拥有业务文案、镜头时间或资源规则。

`competition-feedback.js` 拥有当前项目的路径、十二枚筹码、十四天进度与结算画面。其 `feedbackCues` 引用同镜头的 start/hit/end 事件，音效引用同一 hit 或 start；新场景应自行定义对象与规则，再调用运动辅助。不要复制“12筹码/14天”的内容作为其他主题的固定模板。

目前没有覆盖所有场景的通用游戏 UI 或自动套用器。要复用某项细节，需确认目标场景有对应绘制与参数校验；仅在分镜里写效果名不能使其自动生效。

## 实际审看

逐项检查入场、接触、收尾和稳定帧；同时检查密集状态变化与原有全局转场是否争抢注意力。粒子若穿过小字号数字，改为外围角标或减少强调。资源计数需包含在途物体，跳帧与顺序渲染的结果应一致。

最终查看实际MP4并听动作同步。技术测试、解码静帧与用户主观反馈分别记录；未连续观看或未听音的类别继续保留 not_reviewed。试样好看后再按用户认可的细节与强度收敛。
