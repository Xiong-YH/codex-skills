# 项目主画风与片段画风透传

用户确认的当前规则：项目先选主画风，特殊片段可明确另选画风；片段内人物、其他物种、背景、场景道具必须使用同一个有效画风。组件是独立个体，不接受本合同的颗粒、造型、配色、材质或投影覆盖。字幕排版由 text 管理。

## 唯一规范与解析顺序

### 常用画风与主题选型

2026-11-01 用户确定 **可爱比例 cute** 与 **粗像素 chunky** 为两种常用画风。新项目没有明确选型时，先在两者中按主题建议：人物互动、轻松故事和情绪表达优先考虑可爱；日常知识解释、动作演示和直接的情境比喻优先考虑粗像素。它们是优先候选，不意味着同片混用，仍须先确定项目主画风。

**等距空间 isometric** 优先关联游戏模拟、模拟经营、物流和资源调度、空间布局与协作系统；先判断空间关系是否帮助解释，不因出现“游戏”一词就强制使用。其余五类继续可选，适合时可作为主画风或片段特选。项目已有确认画风或用户明确指定时优先沿用。选型元数据与具体建议唯一记录在 art-profiles.json 的 selection / usage，画廊由同一目录生成。

八类通用描述和四个分支的细化要求唯一维护在 [art-profiles.json](art-profiles.json)。[看图与提示词入口](references/index.html)展示同一份目录；[PIXEL-STYLES](PIXEL-STYLES.md)说明选型与边界。本目录是创作美术规范，不是引擎的 `style.*` 预设，不得将这些 ID 直接写进 production-plan.style。

八类保留为完整画风方案，其名称强调的维度不同：粗细强调颗粒，可爱强调造型，限色强调色表，等距强调投影。v2 将每类明确为颗粒、形状、细节、色阶与配色、轮廓、光影、投影七项描述；这些维度用于解释同一方案，不提供分支各自选型的开关。新组合仍先在项目或片段层写齐整套规范并验证，再统一交给四分支。

v3 进一步细化八类核心描述与人物、物种、道具分支：人物写身份剪影、整体比例、表情与手势的概括方式；物种按自身结构写识别、支撑与操作，不能复制人类身体要求；道具写用途、开口、材质、操作和承托。具体姓名与身份色块从所选角色参考取得，画风不默认绑定小棕。可爱不要求所有物种都长人类手脚，超粗继续保留符号化比例例外。此次是文案细化，现有图片和认可范围按原来源保留，新图与动画仍单独验收。

`片段有效画风 = 该片段明确指定的画风，否则为项目主画风`。片段覆盖只对明确列出的镜头有效，结束后回到主画风；不能沿用“上一个镜头最后用了什么”。一个片段跨多个镜头时，逐镜列出同一个选择，不新增秒数时间表。

不提供人物、物种、背景或道具各自覆盖画风的入口。选择物种、身份、场所和道具内容不改变画风；人体和动物的结构差异由分支提示词处理。需要调整某类画风的共同定义时更新规范版本，不在分支里私改。

## 在现有创作合同中记录

不扩展当前引擎或导演 JSON schema。brief.constraints 保存项目级决定，例如 `主画风 classic；使用 art-profiles v3，规范及样板快照位于 media/art-direction/；组件独立。` storyboard.shots[].intent 写本镜决定，例如 `画风：four-tone（片段特选，回忆段）；主体、背景、道具均遵循；下一镜返回项目主画风。` 没有特选的镜头写继承主画风。相同信息不在四份创作源重复维护。

进入素材制作前，用解析器展开有效规范：

```text
node modules/style/resolve-art-direction.cjs classic
node modules/style/resolve-art-direction.cjs classic four-tone
```

输出携带规范版本、目录哈希、项目主画风、片段选择、最终有效画风、通用要求、各分支完整提示词和样板相对路径。路径相对 style 目录；项目交接时复制实际使用的规范快照与参考图到项目 media/art-direction/，记录来源和哈希。解析结果是已有选择的派生产物，不是第五份创作决策源；时间仍只在 storyboard。

解析器本身不读 brief 或 intent，不宣称自动从自然语言提取选择；使用 skill 的 agent 按项目记录传入对应 ID、核对镜号后执行。也不改变或重绘已存在的素材。未选择画风的新项目先完成选型；旧项目续作先读取其已确认美术，不擅自换成八类中的某一类。

## 各分支必做的提示词展开

**超粗像素的造型例外（2026-11-01）**：用户指定参考 [《元气骑士》](https://soulknight.chillyroom.com/) 游戏内小精灵的概括方式，不再关注细致头身比例。使用 ultra-coarse 时，下文以及人物/插画模块中的头身比、颈肩解剖、四肢尺度检查改为“身份剪影、色块、动作和对象关系可辨”的检查；不强行还原 V3 完整身体比例。允许头身压缩、手脚符号化和细小结构省略，但同一角色的关键身份特征与动作状态仍须连续。该例外只属于超粗像素，不推广到其他七类。原超粗狐狸仍作历史颗粒参考，未宣称已按最新要求重绘主角。

每次生成必须携带“有效画风通用描述与七项维度＋对应分支要求＋身份/内容＋本镜空间光源与动作＋连续性＋对应样板”，不能只传风格名称。通用描述只放场景共同画法，身体比例与结构要求归人物/物种分支；背景分支取得完整画法而不接收人物身体指令。画廊与命令行统一调用 art-direction.js 展开，不各自拼接提示词。八类逐分支描述在目录与画廊可复制。

可爱与粗像素背景分支现附完整干净工坊对照，旧书架裁片保留为历史观察，不再作为这两类的默认背景参考。新背景及完整提示词见 [对照入口](references/index.html#background-comparison) 与 [来源记录](references/background-comparison/sources.json)；属于待用户审美确认的静态候选，不继承人物样板的认可，也不宣称完成成片合成。其他六类仍按实际参考状态使用。

| 分支 | 本分支必须补齐的内容 | 不得省略的检查 |
| --- | --- | --- |
| 人物 character | 已确认身份参考、头身与颈肩、服装和手脚尺度、景别、完整姿态、重心与接触 | 不把新画法当新身份；不拆头拼身；母图与基准按相近可见范围比较 |
| 其他物种 species | [物种结构](../library/CHARACTER-DESIGN.md)、自然/拟人程度、肢体数、吻喙翼尾、运动和操作规则 | 不套人类嘴型或手；不同姿态足数一致，遮挡不能替代核对；多足样板仍须解剖清稿 |
| 背景 background | 场所、景别、相机、前中后景、主光、主体落点和动作区、字幕避让 | 不把样板场所当白名单；纯背景素材不烘焙人物和字幕，场景延伸到画面边缘 |
| 道具 prop | 物体用途、视角、相对尺度、材质、抓握/承托点、分层遮挡与状态 | 场景实物受画风约束；以组件身份独立设计的对象归 components，不能仅凭“像实物”混淆职责 |

通用负面要求：不使用马赛克滤镜替代像素造型，不混合不兼容的颗粒与投影，不烘焙讲解文字，不让装饰压过解释对象。依动作备齐真实素材和代码；提示词不能证明素材已完成或动画可用。

人物身份仍以 [已确认人物库](../library/CHARACTERS.md) 为准。可爱、粗像素人物分支已补 [小棕新画法试样](../library/characters/style-variants/README.md)，待用户确认；其他六类暂展示 V3 小棕身份基准并明确变体尚未制作，不把狐狸观察图标作人像。其他物种继续引用相应画风的狐狸观察图，按需要另附具体物种结构参考。画风参考与身份/结构参考分别标明用途，不相互替代。

## 导演、制作与审片的读取责任

导演先选项目主画风，逐片段决定是否另选，说明切换原因、转换承接与回归镜头；选择原因可以是情绪、回忆或表达需要，不规定每片必须换风格。脚本表格逐片段写有效画风。

素材制作分支先取得解析结果，再添加内容与动作，不重新决定画风。production-plan 仍只记录真实素材与已有运行能力；替换媒体按 MEDIA 合同接入，不能用一个新画风名称声称引擎已支持。

交接逐镜核对有效画风、版本/哈希、样板和四分支要求是否传到制作；缺项先补。审片按完整母图、实际占画尺寸与最终合成核对颗粒、造型、色阶、投影、受光和接触。组件只检查自身合同与位置、遮挡、阅读配合，不以“未跟随场景画风”判失败。

技术检查仅证明解析与资源完整，审美仍需看图；新人物、场所与动作不自动继承八类画风方向的认可。四色和固定网格需另外做实际像素检查，不能由提示词推断。
