# 像素视频发布包装

随片任务从当前项目的文案、画风和可用素材开始，沿用已确认的受众、主张与事实限定。随片使用且 `pixel-game-video` 可用时，读其 `references/production-principles.md` 中适用的要求。单独做封面或发布文案时，直接使用用户提供的主题、素材和用途。

## 封面和标题从痛点切入

先找出观众想完成什么、卡在哪一步，以及继续卡住会付出什么代价。要做出焦虑感，先让人看到为什么等不起，再说已经试过什么，把眼前的后果留给封面上最大的一行。用临近交付、马上要返工或眼看就要错过机会这类观众认得出的处境，选本片能回应的痛点。发布标题可以用反问或反差加重冲突，标题提出的承诺要能在视频里找到回应。

## 出图与交稿

完整任务交付封面成图、可复制的发布标题和介绍文案。用户点名某一项时，按该项交付。

| 交付 | 做法 |
| --- | --- |
| 封面 | 按 [固定封面母版](references/cover-design.md) 填写三行标题和三条任务卡文案，对照原图出图和检查缩略图。 |
| 发布标题 | 写清封面一眼带出的冲突具体发生在哪，或让人看到视频能帮自己解决哪一步。按目标平台限制收紧字数。 |
| 介绍文案 | 从观众遇到的情况接下去，说清视频讲了什么、看完能试哪一步。沿用正文的适用范围，把交付给观众的具体办法写出来。 |

在本仓库随片交付时，封面和发布文案保存到当前 `work/<项目>/`。需要给观看入口登记封面时，在现有项目记录的对应链接中填 `poster`，路径相对于 `work/`。独立图片任务和试稿使用用户指定位置，在本仓库没有指定时用 `scratch/<任务>/`。

## 示例

一条视频讲如何问出下一步，正文有先查卡点、说清一件事、试过再问三个动作。封面从明早要交东西、求助后仍卡住的观众处境切入。

- **封面三行**写「明早就要交 / 问了一圈 / 零进展」，把末行「零进展」排最大。左下卡片依次显示发问「这怎么做？」、高亮的回复「你先想想」和空待办「第一步未开始」。右下人物带着母版里的自然微笑。
- **发布标题**写「求助只换来一句『你先想想』？先把问题缩到对方能答的一件事」。
- **介绍文案**写「先查清自己卡在哪，再说清情况、只问一件事。拿到建议就动手试，带着结果回来问。这期拆开这三步，帮你把下一步问具体。」
