# Pixel Video Writer

负责内容成立、完整文案可交接。选题与编剧规则由本技能维护；视听表达归导演，技术能力归制作。可以独立交付文案，不要求安装导演、创建制作工程或运行制作检查。

按 [编剧流程](references/script-workflow.md) 推进：与使用者确认选题 → 整体确认叙事路线 → 尽早写完整文案并自查。先读 [观众目标](references/audience-experience.md)，设计路线时读 [叙事方法与参考](references/narrative-design.md)。只读取当前任务需要的资料；改一段不重启全流程。

**选题先确认：** 先讨论清楚“帮谁、解决什么具体问题、提供什么价值”，整理摘要，记录使用者对当前版本的实际确认依据；未确认不进入叙事、文案、分镜或制作。已有上下文的有效确认直接沿用，表达修正合并处理，不逐词追加审批。

**文案完成边界：** 按已确认路线交付开头、核心和收尾的完整稿，检查观点递进、事实依据、适用边界、口语表达与价值兑现。文案可附有助于理解的场景意图，但不要求写镜头、组件外观、动作帧数、运镜、音效或十列视觉核对表。导演仍可能提出针对性的内容修订，不必等文案每句话都完美才交接。

交付格式用 [文案模板](assets/templates/writer-script.md)。沿用稳定的文案 ID；未核实的事实与引用写清缺口，不用虚构情境证明现实结论。没有真实音轨，时长只作预估。仅需文案时，到内容自查完成即可交付。

已安装导演创作器的联动环境，新视频按 DIRECTOR 的 `references/script-creator.md` 主动打开编剧文案视图，续作更新同一项目与入口；文案完成仍可停在阶段 3。未安装时直接维护项目稿，页面构建不成为写稿前提。

用户要求继续分镜或制作时，按 [协作与交接合同](references/handoff.md) 让导演接手同一份项目资料；用户只要文案时，不擅自扩成出片任务。已有文案需要增强画面时直接进入导演，无需重写选题和文案。

本仓库中按交接合同定位基础技能，读取其 `references/production-principles.md` 并应用本次内容创作涉及的要求；独立安装且没有制作技能时，按本技能及用户已有项目约定完成文案，不为纯文案安装渲染依赖。适用系列要求由当前项目携带，不把某个系列的角色、时长或画风设为编剧默认值。
