# 开头

用于单独写、改或诊断首句、前五秒，也用于全片路线设计。先从当前材料拿到目标观众及其处境、本片要解决的问题、正文已有或能给出的依据。已有路线或稿件时沿用确认，只改授权范围。正文还没写时，标出候选依赖的后续内容。

## 让观众先拿到一条信息

首句先交付一条观众当下就能理解的判断、行动、结果或具体处境。用这条信息引出观众自己的追问，再让正文接住。设计对照 [观众目标](audience-experience.md)，用 0–2 秒判断相关性，用 2–5 秒判断继续看的理由。结合首屏对象与可读时间预估，已有预览时按实际播放复核。

| 开法 | 选用条件与写法 | 正文最早的兑现点 |
| --- | --- | --- |
| 反常识断言 | 观众有一个熟悉的判断，稿内已有依据动摇它。首句亮出相反判断或被忽略的条件，引出「为什么」 | 给出反例、机制或条件。首句主张的范围与证据一致 |
| 直接指令 | 观众能认出正在做的事，也确实有可执行的下一步。先点出动作并给出改法，引出「怎么做」 | 在具体场景里示范这一步，说明它解决了什么 |
| 结果前置 | 有可核实的结果、前后差异或明确标注的演示结果。先亮出结果，引出「怎么做到」 | 补足起点、条件和关键过程，区分实测、示意与可迁移的结论 |

具体问题也可以开场。判断它是否已经交代处境与待解决的冲突，观众能否立刻认出这件事。诸如「你知道为什么吗」的空泛问法应先补对象、动作或结果。题材无需硬套三种写法，可以从适合本片的情境直接切入。

## 交付与检查

默认给两条可上屏的候选、推荐及理由。指定写法或只改一句时按任务收窄。每条候选写清以下内容，已有文案 ID 时直接引用。

1. **屏幕主句与时间任务。** 标出预计 0–2 秒和 2–5 秒各给了什么，以及对应的对象或状态。已有画面时记录播放复核结果。
2. **观众已获得的信息与接下来会问什么。** 把这个追问写成一句具体的话。
3. **正文的第一个兑现点。** 指出具体例子、证据或操作及其位置。还没有正文时注明要补什么。已有正文接不住时，收窄开头或指出需一并确认的调整。
