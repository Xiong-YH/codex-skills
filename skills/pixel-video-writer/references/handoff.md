# 编剧、导演与制作的协作合同

本页唯一维护编剧到导演的交接、技能定位和内容修订分工。导演到制作的工程交接由导演的 `references/handoff.md` 维护；制作字段、能力和工作台由基础技能维护。这里不增加运行时 API。

## 按任务加载与定位技能

| 技能名称 | 定位变量 | 加载时机 |
| --- | --- | --- |
| pixel-video-writer | PIXEL_VIDEO_WRITER_SKILL | 只有创意、写稿或修改内容 |
| pixel-video-director | PIXEL_VIDEO_DIRECTOR_SKILL | 文案画面化、视听设计、制作统筹或审片 |
| pixel-game-video | PIXEL_VIDEO_SKILL | 查询实际制作能力、建工程或出片 |

文档中的 WRITER、DIRECTOR、FOUNDATION 都指实际定位到的技能根目录，不是项目配置值。对每个名称按“用户明确指定目录 → 对应变量 → 当前技能的同级目录 → `$CODEX_HOME/skills/<名称>`（未设置则 `~/.codex/skills/<名称>`）”定位，检查 SKILL.md 的 name 和所需文件。用户显式指定或变量指定无效时报告错误，不静默换另一份版本。不同安装位置用各自根目录解析内部相对路径，不假定永远同级，不记录个人机器绝对路径。

仓库内的跨技能 Markdown 链接用于浏览；独立安装时按上述规则定位后读取对应文件。纯文案可独立完成；缺少导演仅影响继续视觉设计或联动页面，缺少制作仅影响执行，不因此否定已经完成的文案。确需缺失技能时说明名称和缺失阶段，保留当前产物，不自行安装或复制另一技能的实现。

## 交接同一份项目资料

交接时传递当前资料路径与版本，至少包含：

- 选题三项及真实确认依据，适用的用户限制与系列要求。
- 已确认的开头、核心推进和收尾路线，授权范围及确认依据。
- 带稳定 ID 的叙事段和完整文案。每段交初态、变化、可见结果、给下一段的对象或判断，并引用自己的主句 ID。另附对象标签、事实依据与必须保留的限定。
- 本片观众目标、预期认知/情绪变化，以及未关闭问题和负责角色。

可以是一份 Markdown 项目稿或已有项目中的对应字段，不强制新建 JSON。导演直接消费当前文案，不重新走选题问卷。已有用户稿件无需先由编剧重写；缺少会改变方向的信息时才补问，现有有效确认沿用，文件存在本身不算已确认。

使用导演工程时，段落和文案分别映射到 `script.beats`、`script.cues`、`script.labels`；分镜用 `beatId` 和 `cueId` 接稿。无口播主句可直接用完整语义的字幕，`phrases` 留空。逐短语排练仅供有旁白的项目。

默认尽早交完整、逻辑成立的稿件，导演接手画面和声音细化。不得将分镜、动作、转场、组件外观或音效清单设为文案完成前提。用户已要求全流程时沿已授权范围连续交接，不为技能切换另加确认；仅要文案时完成文案即交付。

## 唯一来源与修订

| 内容 | 负责者 | 修订方式 |
| --- | --- | --- |
| 选题、主张、论据、叙事路线、逐字文案 | 编剧 | 修改项目中的唯一内容源，保留文案 ID，说明影响范围 |
| 画面、构图、动作、声音、接镜与观看节奏 | 导演 | 自主细化并自查；发现内容缺口时提出针对文案 ID 的修改 |
| 能力实现、素材接入、运行工程与导出 | 制作 | 按导演决定执行；不能实现时反馈缺口与可选方案，不静默改表达 |

导演可在授权范围内调整停顿、字幕断句和视听编排；改逐字文案须回写唯一内容源，尊重已确认原文与用户授权。观点、事实、关键承诺或叙事路线变化由编剧处理，并按影响范围向用户确认；日常视觉细化、检查修复不增加逐镜审批。一个 agent 可以切换角色完成工作，不要求另开聊天或启动子 agent。

未建工程时项目稿是内容源；已建工程时文案以既有 script.json 为唯一源，brief.json 保存目标与约束，storyboard.json 和 production-plan.json 归导演。创作器状态只同步展示，不能维护冲突的第二稿；工作台 JSON 仍是独立剪辑分支，不自动回写导演源。

## 现有创作器的兼容映射

DIRECTOR 的 `scripts/build-workspace.cjs`、项目 JSON 路径、projectId、revision 和 activeStage 保持兼容。activeStage 的 0–5 保留旧兼容：0 为空项目，1–3 属编剧，4–5 是导演旧信封。导演实际进度以 stages.director.phase=1–4 表示，页面按“模块 → 大白话/草图 → 结构化设计/动态白模 → 正式制作/审片”导航。文案自查完成可停在 3，独立编剧不依赖页面安装。

`stages.brief` 增补 problem、value、confirmed、confirmationEvidence、confirmedRevision；已有 topic / audience / takeaway 保留。旧 takeaway 可作记忆点参考，但不能自动推断 problem、value 或用户确认。`stages.narrative` 的确认同样需要真实依据。缺项先从当前项目补齐，浏览、复制或手动切页不会完成确认。

同一项目继续使用原来的展示入口，不因角色交接复制项目或清空未合入意见。每次形成实际内容变化后更新对应字段、递增 revision 并设置实际阶段；仅浏览或纯讨论不伪造进度。工程映射、源哈希和成片证据沿原导演/制作合同，不因新技能而失效。
