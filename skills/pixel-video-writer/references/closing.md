# 收尾

用于单独写或修订片尾，也用于全片路线设计。先读开头承诺和核心实际得到的结论，找出观众此时还需要确认什么。只有结尾需求时直接沿用已有路线，拿不到前文时把回收对象列为假设。

| 正文完成的事 | 收尾落点 |
| --- | --- |
| 解释一个疑问或纠正一个判断 | 用一句话回答开头，补上会改变判断的条件。仍有疑问时交代未知范围 |
| 教会一个方法或帮助做选择 | 给出观众现在能做的最小一步，说明对象、触发时机或完成标志 |
| 让观众经历一段情境或换位 | 回到前文同一个人、选择或结果，点出现在如何理解它，把适用的判断带回现实 |

交付一条可上屏的收束句，并指出回收了开头哪项承诺、沿用正文哪条依据、观众会带走什么。把必要的限定写进结论。正文已交付完整时可以短收，再视题材决定是否接一个收口动作。

读完正文最后一段再接片尾。若结尾突然提出需要新证据的主张，先判断正文能否支撑；如果需要重构正文，标出影响范围。适用时保留情绪落点，如解释一个失败后，让观众分清什么可以改变、什么受条件限制。

## 收口动作与评论区留言

2026-11-11，用户明确偏好引导评论区留言。适用于本视频体系的编剧收尾。需要互动时优先考虑一条与本片内容直接相关的留言邀请。情绪已经落稳、没有值得问的问题或本片另有要求时，可以直接结束。

先完成内容收束，再问「谁适合做、只要做哪一步、做完能知道或得到什么」。尽量让观众用一个词、一个选项或一句具体的话就能留言。互动题写成一项明确的任务，例如请观众留一个卡点或一个验证结果。优先保留一个主要动作，给观众足够的时间读完。

| 写法 | 适用场景与交付 |
| --- | --- |
| 关键词留言 | 有与正文相关的配套资料时，说明关键词、能收到的内容和领取方式。仅在资料与交付路径已落实时许诺领取 |
| 按处境邀请留言 | 用本片讲过的身份、阶段或卡点，让适合的观众认出自己。只请他留一项和问题有关、适合公开的信息 |
| 验证后留言 | 请观众拿自己的页面、代码或问题做一次小检查，给出判断标准，再邀请他留下一个结果。动作本身也应对观众有用 |

交稿前连读正文结果和最后一屏，核对正文承诺已经兑现、留言要求一眼能读懂、动作能在观众的处境下开始。按实际安排写明资料、回复或后续内容的交付范围。
