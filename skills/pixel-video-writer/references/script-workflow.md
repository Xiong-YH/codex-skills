# 编剧流程：选题、路线与完整文案

本页是选题讨论和编剧流程的唯一维护位置。先读 [观众目标](audience-experience.md)；按 [协作合同](handoff.md) 记录当前版本、有效确认与后续交接。仅有文案需求时无需打开制作工具。

## 1 · 聚焦需求

选题阶段必须先与使用者讨论清楚并确认三件事：

- **这个视频帮谁：** 具体受众及其所处情境，不只写“所有人”“小白”等泛称。
- **解决什么问题：** 受众当前遇到的具体困惑、困难或需求；题目或知识点不能代替问题。
- **提供什么价值：** 看完后能理解、判断、做到什么，或获得什么具体体验；“有用”“涨知识”不能代替具体收获。

先从用户已有信息整理候选摘要，指出不确定处，围绕缺口讨论，不要求用户从头填问卷。讲什么作为选题背景保留，“看完记住什么”可补充价值，但不能代替问题与价值。时长等明确硬限制原样记录，其余制作偏好沿用适用记录。

产物为“帮谁 / 解决的问题 / 提供的价值”三项选题摘要，记录待确认或已确认、用户实际确认依据及对应版本。**三项明确且使用者确认当前摘要后，才能进入叙事设计；未确认只继续讨论选题，不先生成叙事、文案、分镜或制作。** 只给题目、查看页面、提交修改或沉默都不算确认；没有明确摘要时，笼统说“继续”也不能代替确认。用户已在上下文中明确认可三项时，记录依据即可，不重复询问。

续作沿用已有有效确认，不重启选题；后续改变受众、问题或价值时，先确认受影响方向，再同步后续内容。叙事、文案和 Check 均对照三项：开头让目标受众识别自己的问题，核心回应问题，收尾兑现承诺的价值。


确认时针对当前完整摘要整体收敛；措辞与细节修正合入同一轮，只有方向仍不清楚才继续追问。确认后不为每句表达重复请求批准。

## 2 · 确认全片叙事逻辑

读 [全片叙事设计](narrative-design.md)，调用开头、核心推进与收尾模块组装成一条路线，写一行情绪与认知变化。给一条推荐与一个有实际差异的备选，已有明确方向时不强造选项。参考写清借鉴点及已观察范围。

用简短开头候选、关键转折与结尾落点让用户理解整条路线，集中一次确认；已经确认或明确授权自行选择时直接沿用。此时不要求分镜、素材表、动作预算或声音方案。用户确认具体路线后立即展开全稿，不增加逐段批准环节。

## 3 · 尽早交付完整文案

按确认的开头、核心各段和收尾一次写出完整稿。每段给稳定 ID，写出对象初态、发生的变化、观众能确认的结果，以及后段具体接住什么。因果和判断写在段落说明中，屏幕主句每次呈现一个完整意思。对象名、读数、限定和状态写成独立标签，需要准确复述的句子原样标明。格式见 [文案模板](../assets/templates/writer-script.md)。

做一次静音连读。先按顺序只读主句，再对照每段结果和对象标签。检查观众能否说出前一步怎样带来下一步，以及开头的问题在哪里获得兑现。组件已可见地演出步骤时，主句可以专门交代原因或读完应有的判断。删去开场寒暄、口播过渡词和重复标签。标明哪些主句须等结果出现、哪些词需留屏供比较，交导演决定具体时序和节拍。

交付前由编剧自查并直接修订。连读开头、正文第一个兑现段和片尾，核对实际文案是否沿同一个问题推进，能否指出第一次兑现的位置。再逐段检查新增理解、依据与限定、虚构与事实的区分及表达衔接。检查说明只写实际范围、关键修订和未关闭问题。

全稿自查时读 [编剧常见踩坑](script-pitfalls.md)，先校字，再按观看顺序连读主句和标签。按文案 ID 对照贯穿案例的「问了什么 → 答了什么 → 拿答案做什么」。发现断点时给出可直接上屏的补句或替换句，连同前后段复核。

完整稿逻辑成立、事实缺口已明确、用户约束得到保留，即可标“文案可交接导演”；若关键论据缺失，标“待补内容”并说明缺口。未生成或未播放视频不影响文案交付，也不能据此声称观众效果、精确时长或视听通过。

用户要求继续视觉设计时，交出同一份选题/路线/文案与依据，按 [交接合同](handoff.md) 让导演接手。导演可据此设计画面并尽早试播；需要文案调整就按 ID 返回对应内容，不重写未受影响部分。用户仅要文案时在本阶段结束。

## 现有项目与创作器

已有文案、路线或确认从当前项目继续，不重复问卷，不因启用编剧技能而重置进度。已安装导演工作台时，新视频从其中的编剧视图开始；旧 activeStage=1–3 对应本流程，导演另按四阶段推进，按 DIRECTOR 的 `references/script-creator.md` 更新同一 JSON 与入口，不生成重复项目。独立编剧未安装创作器时直接维护项目稿。
