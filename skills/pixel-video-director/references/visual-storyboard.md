# 视觉分镜与工程映射

**镜头描述必须结合动态规范。** 按[运镜设计与兑现合同](motion-direction.md)说明焦点、运动层级、起态到落点、采用的曲线／预设、事件和阅读停留；阶段二用大白话，阶段三映射实际能力，阶段四按同一决定出片。静态箭头、线性白模和“自然衔接”不能替代正式动效的播放与验收。

用户只要画面方案时，交付设计稿；需要制作时，将决定写入既有四份创作源，再沿 [创作合同](authoring.md) 交接。本文件维护正式分镜与工程映射，不增加正式工程字段或第二条执行时间线；前期构思/白模另按 [导演四阶段](director-workflow.md) 使用设计数据。以下细则在阶段三细化和阶段四交接时落实，不要求阶段二大白话全部填完。

## 按任务范围交付

- 新文案：说明理解目标、情绪走向、视觉母题、构图光影、主体动作、运镜与接镜，列出必要素材。
- 已有两镜或局部问题：只展开受影响镜头及交接，保留既定文案、风格与时间约束，不重写整片。
- 已有工程：按稳定镜号和事件解释设计，实际修改回到拥有该内容的源文件。

保留用户已确认的角色和表演职责，不用“像某作者”代替项目基调。参考中的黑金、Q 版、富豪、城市和游戏界面均由新主题重新选择。分析新参考需查看真实画面，未见到的部分不当成原片事实。

## 纯设计稿

按 [设计格式](script-format.md) 随阶段交付：先大白话与可弃用的构思草图，再细化结构化决定与动态白模；需要完整文字交接时展开六列主表，每镜一行。补充设计与制作备注并入本阶段，复杂组件按需附局部说明。使用 [模板](../assets/templates/segment-script.md)，参看 [示例](../examples/script-format.md)。关键设计缺失标待补设计，不能留给制作猜。

没有音轨或实际时长时，只写建议区间或事件顺序。已有工程按原镜号和事件展示；多镜片段逐镜说明变化与边界。局部修改仅更新受影响片段及相邻交接，不重写整片。下列分类、组件、字幕和工程映射是表格各维度的细则，不另输出一张重复的超宽表。

## 镜头数量与合并原则

- 默认输出精简分镜，保留当前项目的片段分类与形态要求。同一解释任务中，主体、空间和因果连续的内容，优先合并为一个镜头。
- 同镜可承载多句讲解，通过物体状态变化、局部强调和信息逐步显露组织节拍；避免按每句话、每个名词或每个动作分别建镜。合镜后的分拍与对应台词按顺序写在该片段详情的对应维度中。
- 新增镜头应有明确收益，例如转换解释任务、改变必要视点、跨越时间或空间，或减轻信息负担。仅更换标题、字幕或装饰不作为拆镜依据。
- 交付前在本次允许调整的范围内检查相邻镜头，合并重复建立场景、重复展示主体和可以连续完成的步骤，删去没有新增信息的镜头；保留理解内容所需的过程与差异。
- 合镜后按完整表达重新估时。下节的时长建议是创作起点，连续过程可适当延长，并按下节规则说明时长依据；不要为了满足单镜短时长再把连续内容拆回多镜。

## 紧凑节奏与估时

新脚本与分镜默认采用紧凑节奏；用户指定的节奏、单片总时长与已有工程约束优先。先确定需要独立成镜的解释任务，再按镜头预算安排信息量，设计文案与动作。

- 普通单一信息镜头优先按 **2–3 秒**设计，多步过程或复杂比较优先按 **3–5 秒**设计；超过 5 秒时，在时间依据中简要说明台词实长、阅读负担、必要过程或情绪停顿。这些是创作起点，实际旁白与可读性优先，不设统一的镜头时长上限，也不要求每隔固定秒数切镜。
- 在预算内精简可改写的文案、减少无必要的动作，让讲解与相关动作同步发生。用户要求保留的文案按实际讲述时间安排；不要只缩小秒数、切断完整表达、截断旁白或通过强行加速凑时长。
- 能同步完成的讲解、动作与阅读共用时间，必须按因果先后发生的步骤才依次计时。新字幕和新旁白按所选转场的落稳条件进入，密集新增信息在焦点稳定后显露；随后可边讲解边演示，不再为已完成的同一信息安排一整段重复阅读或固定停顿。
- 转场占用接入镜头的时间，镜头预算包含这段交接，不在镜外重复追加。动作完成后仅保留理解结果所需的停留，不为填满预算拉长运动或空等。
- 有旁白音频时按真实语音区间校准；没有音频时以试读或阅读负担估计，给建议区间与简短依据，不能宣称已实测。纯字幕镜头仍需完整可读；工程内帧数只在 storyboard 维护，长镜依据写入既有 intent，不新增时间线或模型字段。

## 脚本中的呈现类型标注

面向用户的脚本按 [脚本表格规范](script-format.md) 在片段总览中概括类别与呈现，在逐片段两列详情表中分别填写类别与呈现、旁白与讲解文案、字幕与场景文字、声音等维度。多镜片段在对应维度内按镜号逐项说明；不以镜头标题代替详情，也不另建重复的逐镜宽表。以下内容分别交代，不混成一组“呈现类型”：

**转场／接镜是必填内容。** 每个相邻镜头边界写明“前镜交出什么 → 切换方式及过程 → 后镜接住什么 → 何时落稳、开始阅读”。直接切镜、同镜继续或淡入淡出也要明写，不能留空或只写“自然衔接”；名称之外至少有一个可见动作或切点依据。第一镜写入场，最后一镜写收束。来源与实现状态一并说明，不把设计候选写成现成 recipe。

示例：`S02→S03：旧面板向左退出，新面板从右侧接入；背景和口播人物保留；新面板落稳后显示步骤标题。` 工程内设计意图仍写入已有 `visual.continuity` / `intent`，时间与事件归 storyboard、recipe 归 production-plan，不新增第二条时间线。

- 片段类别：本计算机口播系列明确写“普通内容片段”或“插画（特殊片段）”。判断按 [分类定义与正反例](character-illustration.md#先分片段类别再安排声音)，不由有无旁白、主持人、完整背景或是否全屏推断。
- 画面呈现：普通内容可选纯画面＋组件、界面演示、场景／物体展示、主角出镜等；插画写“整屏完整情境”并设计独立情境。主角口播和组件是普通内容的可选形式，不与“插画”作为同层级类别混列。
- 旁白／声音安排：独立写台词，或明确“无旁白，配乐／环境音／音效”。普通内容可以有旁白，也可以没有；插画不默认延续旁白，声音按具体脚本决定。
- 配套讲解／字幕：本系列每段插画必须写出主要图片元素表达的含义和实际讲解文案；无人声时仍用字幕讲清关系或结论，不能只填“无旁白”就漏掉解释。细则按 [插画讲解要求](character-illustration.md#插画必须有具体配套讲解)。

选用插画时，再按 [整屏定义与插画片段设计](character-illustration.md) 写明处境与主体、触发→动作→结果，以及入镜、落稳和出镜承接；选角遵守 [主角优先](character-illustration.md#插画选角主角优先)，使用配角时写清条件。相邻镜头属于同一插画片段时注明连续关系；返回组件、演示或口播讲解时明确切回普通内容。数量、位置和时长由内容决定，不强制每片包含插画，不把连续讲解改名为插画来凑数量。

这些分类、呈现及声音栏是设计稿标注，不是新增工程字段。进入工程后，片段职责写入既有 `visual.subject/action`，理解目标和承接分别写入 `visual.question/result/continuity`，构图与较长片段说明由 `intent` 引用；`visual.form` 仍选择已支持的场景／组件表达，不能把渲染机制当作片段类别。台词与音频沿用 script 和 production-plan 的合同；镜头及动作时间仍只在 storyboard 维护。

## 脚本中的组件需求

使用组件的镜头，应写清它在本段解释什么；动态组件补主体初态、触发、动作、末态、保留/归属关系，以及与人物、场景和前后镜的连接。静态组件写清阅读关系即可。已有组件引用名称和本次变化，并按 [组件外观与空间约定](script-format.md#组件外观与空间约定) 明确风格、组织样式、堆叠、形态材质和背景适配；复杂或多个组件给出可引用的外观表。新机制按定位到的 FOUNDATION 的 `modules/components/DESIGN.md` 提炼需求、选型和五维设计，制作接入读 `modules/components/CUSTOM-RUNTIME.md`。不要求用户先写组件定义，不因库里没有就删掉关键表达，也不让每镜都必须定制。

脚本写可见行为即可，例如：“天数增长，安心条逐格填满；风险发生后，原条块变红并散落；天数保留，安心值归零，碎块停在地面。”这描述意图，不自动生成可执行组件。只有确有取舍时再比较候选，避免把每次创作变成组件目录问卷。

工程沿已有四份源文件：文案在 script，视觉与机制意图在 visual/intent，时间在 storyboard，真实能力与素材选择在 production-plan 的受支持字段。复杂五维记录可作为项目设计附件由 intent 指认；不新增自定义 kind、visual 字段或第五份执行时间表。设计中的新机制应注明实现缺口；先做试样、补适配与核验，再交接正式工程。

## 脚本必须描述字幕形式

每段面向用户的脚本除实际文案外，必须写明字幕形式；精简脚本可合并为一条说明，不得只填“有字幕”“强调关键词”或只提供台词。根据本段的理解任务选形式，读取定位到的 FOUNDATION 的 `modules/text/EXPRESSION.md`，再遵守本系列的开场偏好。

普通讲解字幕默认继承 FOUNDATION `modules/text/SOFT-HIGHLIGHT.md` 的已确认要求，Agent 说明本片关键词、强调等级、阅读和避让安排，并在交接中指认实际调用；采用其他设计写明本片具体依据。画面大字、标题与对象标注按任务另行设计，不能将普通字幕默认扩大到全部文字。

每镜有文字时交代：

- **形式与作用**：稳定字幕、画面大字、分步累积、对象旁标注、对照、动态数字、替换／否定、场景内文字或文字接镜；为何用于本段。
- **位置与关系**：上方、侧边、中央或底部的实际区域；屏幕固定、对象跟随或场景内文字；需要避让的主体，不能只写“放在合适的位置”。
- **层级与重点**：哪些词重点、警示或普通，字号／颜色／字重关系，以及底板有无及形态；由本片风格确定具体视觉值。
- **出现与收束**：按 FOUNDATION 的 `modules/text/EXPRESSION.md` 阅读连续性规则，写出完整语义单元、主句／追加内容、前文保留范围、整体替换依据，以及整组可读后到替换前的阅读区间；说明与主要画面动作错开还是同步。阶段名不能自动增加一次字幕切换。已有工程只引用 storyboard 事件，不另建秒数表。
- **制作状态**：现有参数可执行、需项目定制或待补素材／实现；文字分组与对应 cue/label ID 保持可追溯。无字幕时明确无字幕及理由，场景内标签另说明。

示例（设计，未声明通用能力）：`S01｜上方留白的画面文字，无底板、屏幕固定；先出现“一千次【平安，】”，再追加“积累了【安心。】”，重点词用本片金色并放大；rupture 事件替换为“直到，【例外出现。】”，警示词红色；conclusion 事件仅保留一句结论。避开面板与火鸡；混排和分步揭示需项目定制。`

形式名称是设计词汇，不是新的 role、kind 或 recipe。设计意图写入现有 intent，文案仍在 script，事件仍在 storyboard，受支持的文字执行选择归 production-plan.text。更复杂的编排可由 intent 指认项目附件；附件不能凭文字描述直接驱动运行。生产和 Review 按此说明核对，不能静默套回底部字幕。

## 写回现有工程

| 设计决定 | 唯一源或写入位置 |
| --- | --- |
| 项目基调、角色职责、母题含义、范围约束 | `brief.constraints` 的字符串条目；不新增结构字段 |
| 旁白、字幕、短标签与句意 | `script.cues` / `script.labels` |
| 本镜疑问、形式、主体、动作、结果、承接 | `storyboard.shots[].visual` 既有六字段 |
| 本镜构图、光线、情绪与复杂接镜的文字意图 | `storyboard.shots[].intent`；较长内容可在项目设计附件中按镜号说明，由 intent 指认 |
| 镜头时长、事件、对象位置、文字起止与组件 | `storyboard`；具体字段遵循既有模型与场景合同 |
| 角色/物体素材、背景/替换素材、风格、运镜配方与声音选择 | `production-plan`；对象放置、场景参数仍按创作合同填写 |
| 审片问题、实际证据和修复影响 | 按 [Review](review.md) 使用现有问题与源映射合同 |

工程模型拒绝未定义字段。不要直接给 `visual` 加 `lighting`、`camera`、`motif` 等字段，也不为设计表增加一份可编辑秒数时间线。已有工程的表格只能引用或展示 `storyboard` 的镜号、时长和事件；时间变更先回写 storyboard。

设计附件表达意图，不能驱动运行；素材选择、动作事件、运镜参数仍须写入受支持字段。需要新场景或效果时标为待实现，先补能力和验证，不把普通文字当 recipe。只做分镜不要求运行 doctor；工程交接/出片依赖基础 skill。

## 关系设计摘录：缩短会议，留下连续时间

输入：“把一小时会议压缩到半小时，留出完整的一段时间，做真正需要投入的事。”下表仅摘录约 12 秒方案的关系与承接，无旁白音轨，不是效果统计、完整脚本交付或可运行工程；完整输出格式见 [填写示例](../examples/script-format.md)。

项目选择明亮像素书房，蓝色表示会议占用，橙色表示可自行安排的时间。主持人在桌旁一侧站立讲述，桌面纸张承担动作；人物与整个空间随取景共同变化。这里的颜色、场所和片长仅属于本例。

| 镜号 / 建议区间 | 理解目标与状态变化 | 构图、动作与承接 | 所需素材 / 状态 |
| --- | --- | --- | --- |
| A / 约 0–4 秒 | 会议从一小时缩至半小时：日历中蓝色纸条折回一半，露出“30 分钟”的橙色区间 | 中景给日历和站立主持人；右上柔光、纸张有接触阴影。镜头固定，纸条停稳后标签更新 | 日历、独立可折纸条和标签 / 设计 |
| B / 约 4–8 秒 | 空出的时间可以自己安排：橙色区间展开成一张待写方案纸 | 整体接近桌面，保留同侧主持人；折边遮住内容切换，纸张落稳后显露“写方案” | 独立纸张、对应近景、遮挡层 / 待实现 |
| C / 约 8–12 秒 | 让一件事连续推进：笔写完一部分后停下 | 笔是主运动，随后整体拉远回到日历与任务的关系，留停顿，不加效率倍数 | 书写动作和完整环境 / 待实现 |

B 的交接：A 交出可支配的橙色纸面，B 接住同色、同方向的工作纸。折边经过焦点时遮住内容切换，保持纸张身份，落稳后才读任务。主持人的职责不变，场景不裁成局部运动窗口；这属于视觉隐喻，时间标签保留现实关系。

本例没有检查基础能力目录，不能据此声称纸条折叠、书写或空间运镜已经实现。实际制作先定位基础层并选择可用能力，再准备素材、事件与参数。

## 素材与核验

素材清单写明用途、画幅/裁切、主光、必要分层、来源和状态。依据实际动作分离背景、人物、可动道具、遮挡层和文字，不为了拆层切断完整环境。遮挡层要能覆盖所需范围，跨镜同一对象要可识别。

需要生成图片时，读取当前可用图像生成指引并实际调用工具。提示词写项目固定基调、本镜主体及动作初态、景别/视角、构图主光、留白与必要分层；文字单独排版。动态输入另写主体动作、镜头路径、速度变化、落点与停留，并准备相接的首尾状态。提示词只是输入，查看真实结果后才能标已生成。

只有方案时核查因果、隐喻、构图、动作、承接和素材需求，标为设计审查。静帧、动态和声音分别需要真实图片、连续播放和听音证据，按 [Review](review.md) 保留未审项。

修复写为“镜号＋可观察问题＋原因＋最小改法＋复查片段”。例如切后主体突然移到另一边，先改落点或给出有动机的视线引导，不直接增加全屏闪光。
