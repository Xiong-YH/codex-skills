# 用画面与转场推进讲解

信息关系、组件家族、风格基调与人物自然感先按 [视觉表达方法](visual-system.md) 判断。卡片是有效的组织形式，检查内部层级和解释职责，不能仅凭使用卡片判定表现弱。样板用于说明风格，实际背景随本镜任务生成或替换。

先确定每镜的解释任务，再选择场景和运镜。延续本项目的计算机知识口播时，先读取 [已确认的表达方向](computing-voiceover.md)，避免新一轮修改丢失人物职责与画风要求。

分镜 intent 简短写清四件事：概念对应什么物体；物体发生什么状态变化；观众从变化中理解什么；下一镜继承哪个主体或位置。时间和参数继续在 storyboard/production-plan，不另写一份 prompt 时间线。

| 解释关系 | 可以采用的画面 |
| --- | --- |
| 一个与许多个 | 完整场景拉远成为其中一格，再显露数量 |
| 从群体讲到个体 | 选中目标、压暗周围、推入目标内部 |
| 同一物体换环境 | 保留形状、颜色和视觉焦点，切换景别或背景 |
| 副本、传递、积累 | 明确展示复制前后、运动路径与保留状态 |
| 条件、命中与失败 | 同一世界中改变事件结果，不只换说明文字 |
| 抽象概念进入具体情境 | 用书页、屏幕或实体入口接入承担该概念的空间 |
| 两条路线或两种方法 | 用不同场所与道具状态区分；结尾可将真实镜头收成图卡对照 |

转场设计先写清“前镜交出什么 → 转场中发生什么 → 后镜接住什么”。同一物体、完整遮挡、相邻空间和场景收为图卡，都可以建立承接。按 [基础依赖定位](handoff.md) 找到 foundation 后，先读其 `modules/motion/TRANSITIONS.md`，再按已实现的 catalog 选择配方。库里的 `design.*` 是参考设计，需补实现与核验后才能作为能力交接；只写效果名不能代替画面设计。定位、运动、落稳和阅读用 storyboard 事件安排，避免切到新画面立刻堆上新句。

判断变化是否成立：暂时忽略字幕，是否仍能看出研究与实践、选择与结果等关系？如果只剩同一房间反复放大缩小，应回改场所、主物体或状态。缩放幅度、特效数量与场景数量本身不能证明叙事更好；变化需有解释任务，稳定段需有阅读时间。

动作只在信息需要时强调；落位后留出理解和阅读时间。同一场景可承载数句讲解，以道具变化推进；不要求每句都换背景或全屏转场。人物按脚本需要出现，旁白可配无人场景、物体或组件；安排主角出镜口播时，应另外做出与话语呼应的说话感。插图集合只参考风格与演绎方法，不套用样例结构和布局，详见 [人物出镜与参考用法](character-illustration.md)。

需要游戏感的细节时，按基础依赖定位其 `modules/scenes/GAME_FEEL.md`。让反馈对应实际状态，例如选中后锁定、筹码离槽后源计数减少、抵达后目标增加、完整校验后确认。局部动效与声音围绕同一触点安排；前一版构图已获认可时，可以只试用这些细节，保留稳定的全局节奏。试样效果与用户认可分别记录。

“人物不必常驻”是逐镜构图选择，不应整片删掉已确认形象。先按文案确定人物处境、触发、姿态与结果；完整人物或完整场景在一张画里建立比例、透视与接触关系，再制作相邻姿态。用户已否定独立头像拼接与手臂局部变形；代码有像素变化不能证明表演可信。统一运镜可以带人物进出视野，不能裁断连续房间。本系列要求、失败原因和新完整插画试样见 [人物动态与情境插画](character-illustration.md)。

背景负责场所与气氛；图像风格、实体道具、信息标签和字幕分层维护。保持主体在跨镜头中的身份，例如缓存样例里始终用青绿 A 表示同一份数据，用金色 B 表示另一次不同请求。

完整示例：[cache-journey](../examples/cache-journey/brief.json)。它把取数往返、保留副本、命中短路径和未命中回源分别演出来；时长和主题仅是这个样例，不是永久模板。

[跨空间叙事实例](../examples/cs-postgrad-narrative-18s/brief.json)用书页、书架与真实镜头图卡承接不同解释任务。其他样例保留供机制或人物表演参考；当前项目的角色职责与偏好见 [计算机知识口播](computing-voiceover.md)，历史取舍统一按基础依赖读取 `references/iteration-history.md`。
