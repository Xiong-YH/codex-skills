# 用画面与转场推进讲解

先确定每镜的解释任务，再选择场景和运镜。延续本项目的计算机知识口播时，先读取 [已确认的表达方向](computing-voiceover.md)，避免新一轮修改丢失人物职责与画风要求。

分镜 intent 简短写清四件事：概念对应什么物体；物体发生什么状态变化；观众从变化中理解什么；下一镜继承哪个主体或位置。时间和参数继续在 storyboard/production-plan，不另写一份 prompt 时间线。

| 解释关系 | 可以采用的画面 |
| --- | --- |
| 一个与许多个 | 完整场景拉远成为其中一格，再显露数量 |
| 从群体讲到个体 | 选中目标、压暗周围、推入目标内部 |
| 同一物体换环境 | 保留形状、颜色和视觉焦点，切换景别或背景 |
| 副本、传递、积累 | 明确展示复制前后、运动路径与保留状态 |
| 条件、命中与失败 | 同一世界中改变事件结果，不只换说明文字 |
| 抽象概念进入具体情境 | 用书页、屏幕或实体入口接入承担该概念的空间 |
| 两条路线或两种方法 | 用不同场所与道具状态区分；结尾可将真实镜头收成图卡对照 |

转场设计先写清“前镜交出什么 → 转场中发生什么 → 后镜接住什么”。同一物体、完整遮挡、相邻空间和场景收为图卡，都可以建立承接。再按已实现的 catalog 选择配方；只写效果名不能代替画面设计。

判断变化是否成立：暂时忽略字幕，是否仍能看出研究与实践、选择与结果等关系？如果只剩同一房间反复放大缩小，应回改场所、主物体或状态。缩放幅度、特效数量与场景数量本身不能证明叙事更好；变化需有解释任务，稳定段需有阅读时间。

动作只在信息需要时强调；落位后留出理解和阅读时间。同一场景可承载数句讲解，以道具变化推进；不要求每句都换背景或全屏转场。人物按叙事需要出现，口播可以由场景与物体完整承担。

“人物不必常驻”是逐镜构图选择，不应自动变成整片删掉用户已确认的形象。角色职责优先于动感：侧边口播使用站立、嘴型与眨眼，依靠物体状态、图文关系和场所转换推进。统一运镜可以带人物进出视野；不要为了固定其屏幕坐标而裁断连续房间。只有用户选择剧情表演时，才安排取物、放置等角色动作。

背景负责场所与气氛；图像风格、实体道具、信息标签和字幕分层维护。保持主体在跨镜头中的身份，例如缓存样例里始终用青绿 A 表示同一份数据，用金色 B 表示另一次不同请求。

完整示例：[cache-journey](../examples/cache-journey/brief.json)。它把取数往返、保留副本、命中短路径和未命中回源分别演出来；时长和主题仅是这个样例，不是永久模板。

历史角色表演实验：[cache-adventure](../examples/cache-adventure/brief.json)。同样六句旁白，以跑动取数、抱持 A、近景复制与伸手命中替换虚线路径。用户随后明确当前方向为侧边站立口播，因此该实验不作为当前项目的人物表现默认值。

历史侧边口播实例：[cs-postgrad-18s](../examples/cs-postgrad-18s/brief.json)。完整画幅解决了背景裁片割裂，但反复在同一房间推拉，没有推进视觉叙事，用户要求重新设计。

获得正向反馈的实例：[cs-postgrad-narrative-18s](../examples/cs-postgrad-narrative-18s/brief.json)。书页铺屏进入研究档案馆，前景书架跨到开发工坊，再把实际镜头收进俯视路线桌。每个空间承担不同解释任务，结尾保留前文的真实图像作为判断材料。前三镜保留站立人物，末镜让图卡关系主导。复用的是这些关系，不固定复制此片的场所、镜头数或配方顺序。
