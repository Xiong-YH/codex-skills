# 用动作解释概念

用户希望像素游戏画风服务知识口播时，先确定每镜的解释任务，再选择场景和运镜。像素颗粒与游戏素材可以保留；避免把“减少游戏感”误解成写实风。

分镜 intent 简短写清四件事：概念对应什么物体；物体发生什么状态变化；观众从变化中理解什么；下一镜继承哪个主体或位置。时间和参数继续在 storyboard/production-plan，不另写一份 prompt 时间线。

| 解释关系 | 可以采用的画面 |
| --- | --- |
| 一个与许多个 | 完整场景拉远成为其中一格，再显露数量 |
| 从群体讲到个体 | 选中目标、压暗周围、推入目标内部 |
| 同一物体换环境 | 保留形状、颜色和视觉焦点，切换景别或背景 |
| 副本、传递、积累 | 明确展示复制前后、运动路径与保留状态 |
| 条件、命中与失败 | 同一世界中改变事件结果，不只换说明文字 |

动作只在信息需要时强调；落位后留出理解和阅读时间。同一场景可承载数句讲解，以道具变化推进；不要求每句都换背景或全屏转场。人物按叙事需要出现，口播可以由场景与物体完整承担。

“人物不必常驻”是逐镜构图选择，不应自动变成整片删掉用户已确认的形象。人物适合承担犹豫、取物、放置和结果反应时，让他与道具发生接触；避免人物只是贴在角落，而其他内容始终是同一排设备或卡片。动作编排写清预备、执行、落稳，景别变化配合解释重点。

背景负责场所与气氛；图像风格、实体道具、信息标签和字幕分层维护。保持主体在跨镜头中的身份，例如缓存样例里始终用青绿 A 表示同一份数据，用金色 B 表示另一次不同请求。

完整示例：[cache-journey](../examples/cache-journey/brief.json)。它把取数往返、保留副本、命中短路径和未命中回源分别演出来；时长和主题仅是这个样例，不是永久模板。

角色表演版：[cache-adventure](../examples/cache-adventure/brief.json)。同样六句旁白，以跑动取数、抱持 A、近景复制与伸手命中替换虚线路径；保留前版供比较，不把此片的出场比例推广为所有视频要求。
