# 用画面与转场推进讲解

信息关系、组件家族、风格基调与人物自然感按 [视觉表达方法](visual-system.md) 判断。卡片是有效的组织形式，不能仅凭使用卡片判定表现弱；样板用于说明风格，实际背景随本镜任务生成或替换。延续本项目的计算机知识口播时，先读取 [已确认的表达方向](computing-voiceover.md)。

## 概念、动作与视觉母题

按观点、证据、操作、选择和情绪转折拆节拍，不机械地逐句换场景。分镜用既有 visual 六字段记录观众疑问、表达形式、主体、动作、理解结果与承接；intent 补充本镜设计细节。时间和执行参数仍在 storyboard/production-plan，不另写 prompt 时间线。

动作写到“主体初态 → 动词 → 可见结果”。隐喻先保留真实关系，再选载体；定义与结论可以保持稳定，不强迫所有内容变成情节。

| 解释关系 | 可以采用的画面 | 要保留的关系 |
| --- | --- | --- |
| 一个与许多个 | 完整场景拉远成为其中一格，再显露数量 | 数量是示意还是实际数据；各项比较条件一致 |
| 从群体讲到个体、稀缺 | 选中目标，降低周围对比，再接近目标 | 稀缺不自动证明现实收益，强调要有内容依据 |
| 同一物体换环境 | 保留形状、颜色或焦点，切换景别与背景 | 身份、方向、状态能对应；含义改变要有转换过程 |
| 副本、传递、积累 | 展示复制前后、移动路径与保留状态 | 来源、去向、剩余量，原件与副本不能混同 |
| 条件、边界、命中与失败 | 同一世界中改变事件结果，用门、截止线或计划约束动作 | 哪个条件生效、限制什么，保留必要例外 |
| 抽象概念进入情境 | 通过书页、屏幕或实体入口进入承担该概念的空间 | 入口与概念有意义联系，不突然出现无关道具 |
| 方法与执行、成长 | 先选择或完成动作，再显示勾选、属性变化，回到场景展示差异 | 反馈对应可见事件，无数据时不加精确增长百分比 |
| 两种方法、路线或不确定选择 | 用场所、道具状态和有限资源区分，结尾可收为图卡 | 能力提升不等于方向必然正确；对照图像来自实际镜头 |
| 空白与机会 | 空出的区域可以写入、打开或进入 | 空白代表可自行安排，不默认它必须填入更多工作 |

选少量贯穿段落的母题，记录其稳定含义和状态轨迹。例如同一段时间先被切碎、再收拢、最后由角色安排；换主题时重新选择实物与动作。若同一发光对象从“时间”变成“赞数”，需演出交换或转换，不能无提示改义。母题无需每镜出现，证据、空镜和停顿可以穿插。

## 节奏与情绪

新场所、主物体或状态的变化应推进理解；缩放幅度、特效数量和场景数量本身不能证明叙事更好。同一场景可承载数句讲解，用道具关系变化组织节拍，不要求每句换背景或全屏转场。

情境建立处境，证据帮助理解，操作带来掌控，停顿给反思留空间；按本片需要取用。稳定构图中逐步增加信息，与景别或空间的明显变化交替。连续强动作后，可让人物反应、宽景或落稳的物体恢复观看余量。

保留“定位—主运动—落稳—理解”的过程，阶段可按语义重叠，不固定切镜频率与转场时长。密集信息在落稳后显露；提问、命名和结论可以减少动作。旁白密时帮助聚焦，不因一句话包含多个名词而同时增加多个动画。

## 分清四类运动

| 层级 | 变化与作用 | 设计边界 |
| --- | --- | --- |
| 镜头 | 改变取景、位置、尺度或视角，引导注意或揭示信息 | 2D 整体缩放不冒充有真实透视变化的物理推轨；切特写也不必伪装成连续推镜 |
| 空间图层 | 前中后景不同位移和遮挡，建立纵深与穿行 | 连续桌面、墙面不能无依据裁成漂浮贴片 |
| 主体 | 递出、拿起、打开、转移、破裂，演出文案动词 | 明确触点、起止状态和结果；接住、释放、落位确实发生 |
| 文字/UI | 标签显露、条形增长、选项确认，组织信息与反馈 | 不干扰同一时刻的密集阅读，变化有状态依据 |

每镜确定主运动，其他层级配合；固定镜头也是有效选择。推近的落点应带来新细节或重音，拉远揭示规模、环境或来源，横移/竖移逐步发现新信息。俯视有助于比较布局，仰视可突出尺度压力。运动写清起点、路径、速度变化、落点与停留，素材分辨率和空间结构要支持它。

“站在一侧讲述”约束角色表演，不自动锁死屏幕坐标与相机；统一运镜可带人物进出视野。固定屏幕的叠加主持人需明确独立层，不能为了固定人物而裁断连续房间。人物按脚本需要出镜，不因无人镜头而取消脚本明确安排的主角口播。当前 V3 仍是静态基准图与动作参考，不把嘴型、眨眼或骨骼写成已实现；剧情表演按真实能力选择触发与收束。

## 先设计交接，再选实现

每个关键交接写清：前镜交出什么（对象、来源镜头、状态、位置）→ 主运动如何组织 → 切点发生在哪个遮挡或动作阶段 → 后镜接住什么 → 新焦点何时落稳、何时开始阅读。

| 交接关系 | 设计与核验要点 |
| --- | --- |
| 同一动作或物体接续 | 先建立持有者、触点与方向，在递出或接触时换景，后镜从对应状态接住；物体身份、数量和朝向不跳变，解释避开触点 |
| 形状与亮度呼应 | 明确共同轮廓、位置或亮度中心，换景后尽快交代新对象；可用短切或暗场，有黑场不称为无缝变形，叠化和概念接续分别描述 |
| 道具揭晓 | 先建立容器与开合动作，隐藏内容属于同一空间；核对开合轴、手势、遮挡、落点与光影，揭晓后留反应或理解时间 |
| 空间穿行或翻折 | 先画清前后场景、过渡面和可见边缘，用真实前景遮挡或透视变化接到新坐标；检查露底、镜像字和落位跳变。素材不足时重新准备或明确切镜，不用模糊掩盖结构错误 |
| 场景收进书页、图卡或屏幕 | 以前镜真实画面保留可辨细节，拉远或揭示边框，再让实体转动、合上或被接住；核对比例、厚度、遮挡与内容来源，书封显露、翻页、拉远分别说明 |
| 状态 UI 接回场景 | 场景动作引起面板变化，或面板选择引出执行；退场后保留行动结果，避免回到完全没变化的旧场景 |

有完整遮挡、相邻空间或同一物体时可建立连续交接；没有叙事收益时直接切换即可。镜头源图身份保持稳定，例如缓存样例始终用青绿 A 表示同一份数据，金色 B 表示另一次请求。

上表是导演设计关系，不是第二份运行配方目录。实际制作按 [基础依赖定位](handoff.md) 找到 foundation，读取其 `modules/motion/TRANSITIONS.md` 和所选配方，以 catalog 为准。`design.*` 仍是参考设计，补实现与核验后才能交接；纯设计阶段可标待实现，不虚构 recipe ID。

动作只在信息需要时强调；落位后留出理解和阅读时间。同一场景可承载数句讲解，以道具变化推进；不要求每句都换背景或全屏转场。人物按脚本需要出现，旁白可配无人场景、物体或组件；安排主角出镜口播时，应另外做出与话语呼应的说话感。插图集合只参考风格与演绎方法，不套用样例结构和布局，详见 [人物出镜与参考用法](character-illustration.md)。

## 强调与游戏反馈

闪白、冲击线、震屏和短暂放大可作为揭晓、纠偏、碰撞或确认的视觉重音；同一场景内的强调不计作换景。避免连续重音强度相同，也不靠持续冲击代替动作因果。

“人物不必常驻”是逐镜构图选择，不应整片删掉已确认形象。先按文案确定人物处境、触发、姿态与结果；完整人物或完整场景在一张画里建立比例、透视与接触关系，再制作相邻姿态。用户已否定独立头像拼接与手臂局部变形；代码有像素变化不能证明表演可信。统一运镜可以带人物进出视野，不能裁断连续房间。本系列要求、失败原因和新完整插画试样见 [人物动态与情境插画](character-illustration.md)。

RPG、卡牌和 HUD 需表达选择、资源、进度、反馈或结果。用户要安静的像素画面时保留像素质感，减少任务和升级包装。具体游戏反馈按基础层 `modules/scenes/GAME_FEEL.md` 选择：选中后锁定，筹码离槽后源计数减少、抵达后目标增加，完整校验后确认。局部动效与声音围绕同一触点，试样效果和用户认可分别记录；已认可构图可只改局部反馈。

## 交接与核验

纯设计稿与工程的映射见 [视觉分镜](visual-storyboard.md)。设计阶段可用首帧、交接帧、落稳帧说明需求；有素材时暂时遮掉字幕，检查主要动作与关系是否可辨。静帧正确不能证明中间没有露底、重影、遮字或节奏问题，实际转场仍需完整画幅连续播放和相应听音，按 [Review](review.md) 保留未审状态。
