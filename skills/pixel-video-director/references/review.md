# Review 与定向修复

**运镜与动效的首要核对是是否兑现镜头描述。** 先按[动态规范与兑现合同](motion-direction.md#制作与审片按同一要求验收)逐镜对应采用的关注点、图层范围、曲线／预设、事件窗口、落稳阅读和接镜，检查当前工作台 JSON 的实际调用及同次 MP4；效果不符先修复，不能因已用相机或导出成功而放行。

导演阶段三的构思/白模检查按 [共同检查](segment-check.md) 执行，验证范围只覆盖当前样板。以下 Review 用于阶段四的正式工程与成片，不能用白模导出或草图认可代替。

## 工作台剪辑分支的正式检查入口

最终工作台成片使用下列命令，路径均相对 PROJECT，项目 JSON 必须是与 MP4 同次导出的版本：

```text
python scripts/director.py workbench-review-init PROJECT --project-json workbench/exports/film.project.json --video workbench/exports/film.mp4
python scripts/director.py workbench-review-check PROJECT
```

基础技能按既有依赖定位规则查找；需要 Node 与 ffprobe，支持 PIXEL_NODE / PIXEL_FFPROBE。
初始化及复查均复用工作台输入与字幕选型校验，拒绝缺少字幕方案、声明与实际组件不符或其他设计缺少原因的项目；再核对实际 MP4 尺寸、帧率和解码帧数，绑定两份文件的 SHA256。
哈希只锁定本次选定文件，不能单凭哈希证明画面来自该 JSON；仍须对照实际内容。
六类检查初始全部 not_reviewed，实际核验后填写 evidence；问题以 clipId 和成片全局 timeRange 定位，记录 expected、category、evidence、status。
检查命令拒绝过期文件绑定、缺少证据、未关闭问题和越出片段的区间，退出码沿 review-check。
它核对报告与文件，不自动识别画面质量，也不能证明 checked:true 所声称的观看确实发生。
原 review-init / review-check 只用于导演源合成分支，不用于工作台编辑后的最终成片。

场景美术先按基础层 [画风透传合同](../../pixel-game-video/modules/style/ART-DIRECTION-CONTRACT.md) 逐镜核对项目主画风或片段特选、规范版本/哈希和实际参考，检查人物、物种、背景、道具是否统一执行，片段结束后是否回归。组件按自己的合同独立审查，不以未跟随场景画风判失败。目录解析成功、参考存在不等于新素材或成片审美通过。

导演按 [逐片段 Check](segment-check.md) 检查并修订同一视觉稿，十列视图按需展开，七模块辅助对象定位；内容问题返回编剧，工程与实际视听检查分别记录。

脚本交付前按 [表格规范](script-format.md#交付前审查与工程交接) 核对分阶段文案与六列视觉主表的覆盖、ID、文案、事件和接镜一致性；遗漏维度、含糊组件行为或未说明的实现缺口先补齐，草稿不能标可制作交接。该内容审查由 agent 执行，不宣称现有 check/handoff 已自动校验表格完整性。

只有视觉方案时做设计审查：检查因果、隐喻、构图焦点、动作承接和素材可行性，未生成的静帧、动态与声音保留未审。无需为纯设计调用 review-init，也不能把设计审查通过记为成片 Review 通过。记录方式见 [视觉分镜](visual-storyboard.md)。

逐镜对照 [屏幕文字与阅读](visual-storyboard.md#屏幕文字与阅读)，核对主句与对象的对应、重点词、显露与收束。正常速度和小屏复看稳定阅读区间，检查动效时的避让、裁切及旧文字残留。工作台有字幕设计记录时，对照实际导出核验采用的样式。

新增两项前置审查，执行细则沿所属模块，不另设固定阈值：

- **阅读连续性**：脚本阶段先对照 FOUNDATION 的 `modules/text/EXPRESSION.md`，检查语义单元、主句保留／追加、替换依据及完整状态的阅读区间；预览时连同画面动作一起看，不能仅靠文字起止和无溢出通过。已发现过早换句、动作与新句争抢注意或结论闪过时，记录问题并回改编排。
- **人物整体比例**：动画制作前按 FOUNDATION 的 `modules/scenes/whole-illustration.md` 并排检查基准图与母图的头肩躯干、颈肩连接、四肢与手掌尺度及统一风格；最终合成再检查缩放和裁切。整图生成与角色身份一致不构成通过依据。已发现不协调记 visual failed，先修整体人物素材，不继续编码后当作待用户发现的问题。

组件镜头同时核对 [脚本组件需求](visual-storyboard.md#脚本中的组件需求)：可见关系是否兑现，身份/归属和结果是否连续，隐喻是否冒充真实测量；逐项对照 [组件外观约定](script-format.md#组件外观与空间约定) 核验风格、组织样式、堆叠、材质光影和背景适配，不能用动画正常替代外观符合；自定义组件按 FOUNDATION 的 `modules/components/DESIGN.md` 核验本次变化范围。独立试样认可不代表已接入或审过成片。

组件美术验收还须对照 FOUNDATION 的 `modules/style/COMPONENT-ART.md`；八组件认可确定共同画风方向，不免除本片背景同框、文字、触点和变化范围核验。程序校验不自动判定美术符合。

新工程对照 storyboard.visual 与 [视觉表达方法](visual-system.md)，核对组件层级、对象关联、背景构图和人物空间。替换素材后复核裁切、片段长度、文字遮挡与配乐触点。

```text
python scripts/director.py review-init PROJECT --manifest PROJECT/video/outputs/film-verification/render-manifest.json
python scripts/director.py review-check PROJECT
python scripts/director.py impact PROJECT --source script.json --id c1 --field /text
python scripts/director.py impact PROJECT
```

review-init 检查完整成片、当前源文件、基础输入哈希和 MP4 SHA256；技术指标可据核验报告赋值，内容、视觉、运动、文字与音频初始为 `not_reviewed`。review-check 不代替实际审片；退出码 0 为 passed，2 为失败或尚未完成，1 为合同/依赖/版本错误。

实际连续观看成片、查看关键静帧/转场并听音后填写 checks。证据路径相对 PROJECT，`checked:true` 只表示确实已检查。内容/视觉/运动通过必须有 playback 证据，文字可引用解码 frame，音频需 audio 或 playback，技术需 metadata。静音工程可用媒体报告证明没有音轨。未检查项不能通过，元数据不能证明视觉或听觉质量。

声音按 [Garden 审片](../../pixel-game-video/modules/audio/GARDEN.md#预览与审片) 对照声音 brief、同次工作台 JSON 与真实 MP4。核对实际重音、视觉接触或揭示帧、事件音效和段落曲线。用波形与频谱定位问题，按需单听分轨，并在修订后复听关联区间。审片记录时间码、技术结果与听感。未实际听音时保留 `not_reviewed`。

使用 Remotion 时，同时核对 Studio 与实际 MP4 对应当前 handoff 和有效构建，镜头起止、字幕区间、动作与声音落点保持一致。当前基础后端由 Remotion 采集画面帧、Python 预混音，再用 FFmpeg 编码封装；额外用 FFmpeg 裁切、拼接、变速或移动声音不会回写创作源。源合成调试发现差异时沿源映射修正并重新 handoff、build，再显式导入工作台；工作台剪辑分支的问题则修改其项目 JSON 并重新导出。最终 MP4 以工作台导出为准，绑定该次导出 JSON 与证据；只审过 Studio 不能将最终 MP4 标为通过。

## 工作台导入与编辑验收

### 推进、节奏与观看距离的复核

对当前导出正常速度连续观看并听音，按文案关键转折标出时间区间，逐项对应 [讲述与画面设计](visual-storytelling.md#把讲述推进落实到画面)。以下是问题定位方法，不预设每部片都有四类失败：

| 现象 | 可观察判据与最小修复方向 |
| --- | --- |
| 空 | 文案已推进到新的操作或结果，画面没有相应状态/关系变化，也无明确的新增阅读任务；先补缺失的可见过程或调整文画对应，不以换背景、换字或加粒子关闭问题 |
| 慢 | 分别记录触发、触点、收束和阅读区间；按基础层 `modules/motion/TIMING.md` 核对适用动作。先修运动段，再复看末态阅读与音画同步，不用整片加速代替定位 |
| 阅读与接镜 | 标出动作落稳、阅读完成及下一个能承接内容的实际切点。按基础层 `references/production-workflow.md` 收镜并连续播放相邻镜，复核稳读、接镜和切点上的配乐重音 |
| 乱 | 在实际画幅及小屏辨认首个焦点、下一阅读落点、对象归属；若竞争动作或遮挡使顺序无法辨认，错开触发、降辅助层或改分组后复看。必要多对象比较本身不判失败 |
| 隔了一层 | 关键判断/情绪只由口号、标签或无关象征物陈述，看不到相关过程或后果；回到该任务的具体输入、操作/限制与结果。定义与并列介绍按其任务核对，不强制改成人物情节或因果故事 |

每条问题使用下文既有 issue 合同，附文案/镜号、实际时间区间、看到的现象和修复后的复核证据。静帧可确认布局问题；仅有抽帧、位移分析或文档检查时，运动与整体视听保留未审。设计规则补齐不等于成片改善，未有实际效果证据不宣称提高留存。

视频制作必须读取基础 skill 的 `references/workbench.md`，完成工作台剪辑和最终导出，并独立记录以下证据：

| 对象 | 必须实际核对的内容 |
| --- | --- |
| 初始拆解 | 工作台清单与原合成同源；首帧、镜头稳定态、转场前中后及尾帧 parity，不能只比片长 |
| 独立音频 | 音效与配乐分别成轨。核对各片段素材、起点、长度、增益和分轨 PCM 重组，实际听音核对当前导出 |
| 文案编辑 | 属性面板修改字幕与镜头内文案后画面改变；保存、刷新及重导入仍保留 |
| 镜头编辑 | 移动或拉长镜头后动作、字幕、转场、音效和总片长合理；检查空档、越界和重叠 |
| 转场编辑 | 单独调整转场片段与参数后，连续动作及前中后帧采用新设置，不挪动其他类别轨道 |
| 音频编辑 | 分别移动、调音量或替换音效与配乐，核对预览与导出的新设置及受影响拍点 |
| 导出与交付 | 下载项目 JSON、重新导入、逐轨导出后核对只含所选内容、从当前工作台项目导出 MP4，配对下载「导出版本 JSON」中的同名 `.project.json`，再检查真实成片及听音 |

工作台首次 parity 通过只说明原合成拆解一致；用户编辑后要以当前项目 JSON 和导出 MP4 建新版本证据。工作台项目不会回写导演源，现有 `review-init` 绑定原 VideoSpec 的合同不能代表该剪辑分支。另存当前项目 JSON 的 SHA256、导出 MP4 的 SHA256、实际操作/播放/解码/音频证据和未审项，不把旧 Review 改成新分支通过。原导演分支继续按原 Review 合同运行。

操作验收使用的测试文案、镜头移动和音效修改应另存；交付默认片子前恢复用户确认的原版或明确标注修改版。没有实际打开、编辑、保存重开和导出时，工作台可编辑性保留 `not_reviewed`。

运镜检查要看完整画幅的空间关系：桌面、墙面与人物是否遵循同一镜头，是否出现局部背景贴片的硬边，切点两侧焦点物体的位置/尺寸是否承接。无透明边角、人物像素固定、首尾一致不能替代这些判断；已发现的静态割裂应记 visual failed，不能用尚未完整播放来淡化已发现的问题。

检查每个中间阶段的固有形状：同一张卡是否从扁宽变成窄高，文字是否被挤压，平面房间是否被当作可绕行的三维模型，多个动作是否同时争抢注意力。完整背景有变化、速度连续、首尾匹配都可能与明显扭曲同时成立；这些技术条件不构成视觉通过。参考方向被认可与本次实现被认可分开记录。

除了空间连续，还要检查转场是否推进讲解：

| 检查对象 | 本轮实际暴露的问题与复核方法 |
| --- | --- |
| 整段理解推进 | 对照开头问题、每段新增理解与结尾回应；检查前段的结果或疑问为何引出后段。定义/并列内容可独立，不把场景更换或字段齐全当作论证成立；虚构情境与示意动画不自动证明现实结论 |
| 叙事变化 | 并看各镜稳定帧及关键状态，确认场所、主物体或状态随观点变化；关键结果是否被下一镜使用。同一背景反复推拉可能通过技术检查，却仍单调；连续换标题卡也可能丢失案例与因果 |
| 母题与准确性 | 跨镜的实物、颜色与状态有稳定含义；含义改变有转换动作，隐喻不暗示未经依据的因果、统计或收益 |
| 场景适配 | 对照分镜意图检查为何选用该空间、尺度和视点。只是把工作台、机房、档案馆轮换一遍，不能证明内容有了视觉解释；不按新图数量或不同文件数量评分 |
| 交接过程 | 按脚本逐边界查看前、中、后帧并连续播放。核对上一段交出的对象或状态能否在下段辨认，转场揭示是否落到预期重音 |
| 人物职责 | 检查是否擅自加入跑跳取物、整片删掉角色，或把站立误做成不随相机运动的贴图 |
| 情境插画 | 用到插画时按 [动态设计](illustration-motion.md) 核对最终画面中的处境、动作结果、人物与道具连续性，以及屏幕文字的解释任务 |
| 插画局部动态 | 按 [静中有动](illustration-motion.md) 先检查独立物体的美术完成度及其与插画无融合关系；不允许外加物体塞入画中容器、落到桌面、被人物拿住或依赖画中遮挡，发现即判 visual failed 并回改方案。再检查人物持帧与局部动画的分工：触发、接触、遮挡和结果是否可信，有无重复物体、背景跳变或无关循环；阅读允许全静，不能只因有粒子/推拉或高编码帧率就通过 |
| 文字与图形 | 原尺寸和小屏都看；标题、主文字、细节、标签、字幕各自增加什么信息，重复复述是否占用阅读时间；除字幕与标签外，连接线、节点、边框、前景遮挡也可能碰字 |
| 组件特效 | 基础组件按 `modules/components/BASIC-COMPONENTS.md` 审看类型语义、风格分工和同一事件动作；自定义机制按 `DESIGN.md` 五维与最小核验审看。动作时长与配乐触点按 motion 指南核对，只记录本次检查范围 |
| 节奏与声音 | 核对选定接触、确认、揭示与实际配乐重音是否落在同一工程帧。正常速度检查回稳、阅读和相应音效 |

用户反馈单独记录原话、版本与适用范围，不自动改变未完成的 checks。已有历史反馈统一保存在基础 skill 的 `references/iteration-history.md`，通过基础依赖定位；本次工程仍保存自己的审片证据。

每条问题填写：

```json
{
  "issueId":"i1", "category":"text", "severity":"major", "shotId":"s1",
  "timeRange":{"startFrame":12,"endFrame":170},
  "evidence":[{"kind":"frame","path":"evidence/s1.png","description":"字幕遮住选项","checked":true}],
  "expected":"字幕保持可读，同时选项完整可见",
  "ownerModule":"text",
  "sourceRef":{"file":"production-plan.json","stableId":"c1","field":"/y"},
  "status":"failed"
}
```

timeRange 为最终影片的全局半开帧区间。sourceRef 的 field 是相对于稳定对象的 JSON Pointer。问题状态 failed = 待修复，not_reviewed = 已改待复核，passed = 有证据复核通过；所有问题和所有检查都通过才算完成。

### 修订定位与耗时

- **收到反馈就定位到制作源。** 在本片记录里把反馈原话、版本、时间码、镜头或剪辑单元 ID 和对应素材源连在一起，并列出受影响的前后镜和接镜。问题继续使用实际分支的 issue 字段。修订前据此确定需要更新及复核的范围，按当前执行器能力决定可复用的区间。
- **从开始处理时分段计时。** 分开记录定位、方案选择、制作实现、回改或重跑的实际起止，回改注明原因。另记导出转换、正常速度播放核验和入口集成。记录等待及重叠，汇总用墙钟时间，重叠区间计一次。只有文件时间时记为活动窗口，缺实测的阶段标为未知。

对单条局部内容/视觉静态问题，可以用实际解码 frame 确认修复并标 passed；这不使 content/visual 整类检查通过。涉及动作连续性的问题仍须 playback，声音问题仍须听音证据。

按 sourceRef 回改源产物 → impact 看影响镜头 → handoff/build → 显式导入工作台并剪辑、导出 → 以配对项目 JSON 和 MP4 建立新版本证据并复核。若单独检查源合成，可直接 render 并用 `review-init --output review-v2.json` 记录该分支；它不代表工作台剪辑分支已验收。保留旧 Review，不能把旧成片证据直接标成新版本通过。

| 改动 | 核验重点 |
| --- | --- |
| 字幕/短标签 | 排版、嘴型、阅读时间与对应场景 |
| 角色/物体/风格 | 相关镜头、锚点、遮挡与文字可读性 |
| 运镜/转场 | 相关镜头和交接连续播放、关联声音 |
