# 脚本阶段的视觉表达方法

写脚本时先判断信息关系：介绍、数量、比较、过程、条件或结论。随后选择场景、组件或二者组合，再安排动作和镜头；不要先选固定版式，再把所有句子填进去。

先确认要解释的真实关系，再选择视觉载体。隐喻不能增加原内容没有的因果、数量或效果承诺；示意量不冒充真实统计。定义、比较、提问和结论可用稳定图形、人物反应或留白，不强迫每个名词成为道具。

## 可检查的分镜决定

新分镜在 `shots[].visual` 写下六项决定，`intent` 保留一句整体意图：

| 字段 | 要回答的问题 |
| --- | --- |
| question | 这一镜回应观众什么疑问？ |
| form | scene / process 或已实现的组件家族名，主要表达形式是什么？ |
| subject | 观众首先应该看哪个人物、实物或信息？ |
| action | 出现、移动、比较、显露或保持什么状态？静态镜说明阅读对象，不强迫动画 |
| result | 观众多理解了什么？ |
| continuity | 下一镜继承哪个主体、关系或焦点？结尾写清回收方式 |

这些字段是创作决策，不能替代实际场景、组件和事件。旧工程可继续读取；`check` 返回 `visualIntentMissing`。新模板已有结构，空值会阻止交接。不要把具体题材、固定片长或切镜频率变成全局规则。

保留用户文案时，通过画面建立问题、改变景别与对象状态组织注意力；改写或重排时明确采用的文案版本。旁白时长是时间约束，不能代替视觉节奏设计。动作落稳后留理解时间，结论出现后再推进。

只交付视觉方案时可用 [分镜稿](visual-storyboard.md)；进入工程后，以上六项仍写入既有 `visual` 字段，不能另造 `lighting`、`camera` 等未定义字段。构图光影等设计细节通过既有 `intent` 字符串或镜号关联的设计附件描述，执行参数仍按场景和模块合同填写。

## 组件家族与场景

按基础依赖定位 pixel-game-video，读取 `modules/components/GUIDE.md` 与 `catalog components`。

| 内容关系 | 表达形式 | 选择依据 |
| --- | --- | --- |
| 人物、对象、概念介绍 | identity | 名称、形象、少量特征建立识别 |
| 数量、变化、结果 | metric | 数值突出，单位和解释保持次级 |
| 方案、时期、条件比较 | comparison | 固定结构，只改变要比较的变量；可嵌入前镜真实快照 |
| 指认与连接 | annotation | 标签紧邻对象，连接线不穿字 |
| 分段与内容承诺 | chapter | 给观看者结构预期，避免持续占据主画面 |
| 操作顺序、传递路径 | flow | 明确每步输入输出，当前步骤成为焦点 |
| 阶段、发展与历史 | timeline | 等距节点说明次序；标签表达时间，不暗示持续时间比例 |
| 校验条件、完成情况 | checklist | 条件可读，事件满足后勾选并保持 |
| 模块组成、分类与职责 | hierarchy | 一个主对象展开少量分支，避免一镜塞入深树 |
| 同尺度的数值比较 | bars | 相同单位、共同上界、从零起始；标明示意数据 |
| 程序与规则讲解 | code | 保留原样片段，依讲解逐行强调，控制行数与行宽 |
| 原则、总结与记忆点 | takeaway | 用开放式主句收束推理，让背景与主体保留空间 |
| 因果、操作、情境 | scene / process | 主体发生可观察的变化，组件辅助组织与总结 |

卡片可以容纳文字、数据、图像或前镜快照。家族统一色彩职责、边框、字号层级、留白和显露节奏，各类保留适合任务的内部结构。不要用一个矩形包住全部信息，也不要逐卡发明新风格。

场景建立情境，标签解释对象，卡片压缩与比较信息，再回到场景验证结果。组件数量和动作密度由阅读负担决定；大小、亮度和细节集中在当前解释对象。

组合时先定主次：流程配检查条件，代码配指认标签，数值证据配结论，从属关系配对象介绍。各组件使用同一镜的事件，并错开显露和强调；组件增多不能替代镜头拆分。新家族与组合源例见 [组件扩展](../examples/component-expansion/brief.json)。

## 视觉语言统一，场景开放

在 brief.constraints 记录实际需要延续的像素语言、色彩职责、阅读对比与人物职责；场所、观察尺度、景别、光源和构图逐镜决定。依基础层 `modules/style/ART-DIRECTION.md` 的开放式场景设计方法构思，样板按需说明质感，不把已有房间或空墙作为所有主题的起点。

## 构图、光影与尺度的设计决定

先确定第一眼焦点，再分配亮度、尺寸、细节、遮挡与留白。灯光既交代空间，也可以表达受压、安定或获得机会；光源、材质与接触关系遵循同一空间。

| 决定 | 写到可制作的程度 |
| --- | --- |
| 焦点 | 指定最先看的物体和次级信息；例如让双手间的对象最亮，降低边缘环境对比，而非全屏发光 |
| 光线 | 指定主光来源、方向和冷暖关系，人物脸、手和道具接受同一光源；不只写“电影感” |
| 空间 | 前景承担真实遮挡，中景承载动作，远景提供识别线索；道具有落点、透视与接触阴影 |
| 尺度 | 小人物面对巨大对象可表达压力，开阔空间可提供选择感；改变尺度需要新的理解目标 |
| 文字 | 字幕承载完整语句，短标签指认物体，大字少量承担重音；避开动作触点和转场遮挡 |

在灰度和小屏预览中检查焦点，再增加细节。像素簇组织轮廓、体积与材质，人物、道具、环境的颗粒和受光协调；不能用马赛克滤镜代替造型。具体美术样板和参数仍维护在基础 style 模块，黑金或 Q 版比例不成为全片默认。

## 按镜头准备素材

先在现有 visual.subject/action/continuity 中写清本镜空间、尺度、主体变化与承接，再判断已有素材是否合适。需要新的表达时生成或制作项目素材；实体场所、物体内部、界面空间和概念图解都可用，具体画面机制仍须真实落地。连续关系可以保留同一空间，不设背景数量或新图比例。

例如讲 AI 应用，可先设想页面交互的近景、请求进入数据存取空间、资料片段参与回答、实际使用情境，再决定哪些需要背景、哪些由组件或场景承担。这些是构思示例，尚非已生成素材或专用机制，也不成为下一支片的固定四镜。

生成位图时读取当前环境可用的图像生成 skill 并实际调用工具，不能把提示词当作已生成素材。文字、标签和角色通常独立制作；样板仅在有助于像素质感一致时使用，不连同原构图、场所复制。

项目图片/视频放 media/，在 production-plan 按镜头选 background 或 replacement。背景不嵌入字幕；更换素材不应迫使改写文案。用户提供素材时按意图适配裁切、留白与风格，记录来源。见 [素材替换](media-replacement.md)。

## 人物自然感

分别描述身份特征、像素造型、表情姿态与环境融合。身份稳定不要求每个姿态的身体像素相同；变化仍须使用已准备的素材与已实现的表演能力。先看静帧重心、视线、面部结构、光影和接触关系，再看表情姿态是否回应内容。

用户要求侧边讲述时保留职责，不擅自添加跑跳剧情。站立不要求屏幕坐标、尺寸或相机固定，完整场景可连同人物整体运镜；确需固定屏幕主持人时，明确独立叠加层，不把连续房间裁成运动窗口。新人物候选、待适配素材和已接入素材应明确区分，参考片的生动不等于当前库已有同样能力。

## 验收问题

- 忽略字幕后，主体和关键变化是否可辨？静态卡是否有阅读顺序？
- 组件是否关联对象或比较条件，结构和色彩职责是否一致？
- 最亮、最大、最细致的区域是否对应当前重点？小屏是否读得清？
- 背景是否符合本镜任务，同时延续基调？
- 隐喻是否保留原内容的关系和限制，而没有暗示未经依据的数量或收益？
- 场景是否从本镜解释任务出发？若复用已有图，是否确实适合，而不只是图库里恰好有它？
- 人物是否在静帧中成立，并与空间光影、遮挡和重心一致？
- 动作、阅读时间、旁白和声音是否实际播放核验？未检查项保留未审。

这些是审美判断的依据，不是自动评分承诺。完整示例见 [组件表达样例](../examples/component-system/brief.json)。


## 插图、表演与顶部导航的执行边界

用户要求插图时，需实际制作或选择插图素材并接入镜头；流程卡、矩形图标和提示词不能代替插图已经落地。让场所、物体、光影和空间关系承载主要解释，图形只补充必要状态。图像生成遵循当前 imagegen skill，素材和来源保留在工程内。

先区分口播讲述者与插图人物；不能因为配角出现在开场就把它填入侧边讲述者槽位，或自动给它分配旁白和姓名条。计算机口播按系列规则固定一个主角、一个身体姿态，只做局部开闭嘴；storyboard.performance 的整图姿态切换只适用于明确需要动作的剧情，不能代替口型。顶部导航通过 storyboard.progress 绑定脉络，画成连续填充的实心矩形；不叠系列名、页码或悬浮节点。

事件姿态与顶部进度当前仅由 Canvas 执行，Remotion 会在交接校验时明确拒绝。
