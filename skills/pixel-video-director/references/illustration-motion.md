# 插画的静中有动：关键姿态与局部动画

本页维护情境插画的动态设计。人物可逐张切换关键姿态，画面内其他元素按内容任务持续变化。按本镜处境、动作、结果与下一镜的承接决定使用范围。

## 设计目标

人物不必全程连续表演。姿态负责让观众读懂等待、注意、受阻、惊讶、释然等关键变化；独立物体、环境和反馈负责呈现变化的过程。人物保持某个姿态时，观众仍能看见事情正在怎样发展。

先为插画找一个能承载本段含义的可动元素，再决定是否需要辅助动态。例如等待中的日期、被遮住的内容逐渐显露、接触后的回弹、完成前后不同的灯光。不是给每张图统一加粒子和漂浮，也不要求每时每刻有运动；结果与讲解落稳时允许全静，避免用持续闪动抢走阅读。

## 分清哪些内容动、怎样动

| 内容职责 | 适合的表现 | 设计时写清 |
| --- | --- | --- |
| 完整人物 | 关键姿态持帧，到语义节点直接切换；动作跨度大时补必要过渡姿态 | 切换由什么触发，手/脚/视线与道具怎样对应，哪一帧保持供理解 |
| 叙事道具 | 纸张递出、物品落位、盖子开启、光流经过、物体被遮挡再显露 | 初态、运动路径、触点、末态；物体经过人物前还是后 |
| 场景内信息 | 日期推进、屏幕状态改变、少量提示累积或消失 | 表示时间、等待还是完成；变化的依据与终止状态 |
| 事件反馈 | 接触回弹、一次亮起、短促粒子或光线展开 | 对应哪个可见事件，峰值后如何收束，何时恢复阅读 |
| 环境与气氛 | 低幅度雨、烟、尘、光斑或窗外变化，按情境选用 | 为何适合此处、活动区域、明暗和幅度；可没有环境循环 |
| 整体相机 | 揭示关系的推近、拉远或跟随，也可固定 | 此次运镜新增什么信息，不用推拉替代道具行为 |

“持续”与“不断循环”不同。包裹从闭合到打开、纸张从递出到接住都是有终点的连续运动；不必到终点后继续摇摆。低强度环境变化可以跨越姿态持帧，主动作与强反馈应分出先后。

代码适合控制图层的位置、透明度、遮罩、光效、粒子、路径和事件状态；人物形体与复杂透视仍需要合适素材。不能从成片确认参考作者具体用了代码、合成软件还是其他工具，本页也不把代码等同于自动得到可信动作。

## 素材设计：完整人物不等于整幅画面只能烘焙在一起

先按下面的合成边界设计动作，再做构图、形体和空间成立的完整母图；不能先画容器或接触面，再用独立物体去凑合。

### 本系列：独立叠加物体不与插画融合

用户在 2026-11-01 的缓存样片反馈中明确要求：生成物体保持美观，插画与独立物体不能有融合关系。本系列后续制作按以下边界选方案：

- **分开呈现**：独立生成或代码绘制的物体可以作为清楚分离的讲解元素，在预留区域移动、显露和变状态；不能假装成为插画空间中的实物。不得放进图中的盒子、托盘，落到桌面，被人物拿住、递接，穿过家具，或依赖画中前景遮挡、接触阴影和透视对齐。换用图像生成工具制作漂亮物体，也不解除这条边界。
- **需要真实互动就整体制作**：人物拿书、书放进盒子等接触关系，由同一套完整情境姿态图或实际制作的完整动画片段承担；不把画中容器与外加物体分别制作后拼成互动。没有合适素材时改分镜，采用整幅状态切换，或切到独立图解讲机制；不靠临时几何贴片补动作。
- **叠加物体本身必须完成美术设计**：形状、比例、轮廓、像素颗粒、配色和明暗层次符合本镜视觉语言，缩小后仍可辨认。代码绘制同样适用，简单几何适合表达抽象图形；用作具象书本、包裹等道具时，不能用几块未经设计的多边形充当成品。先看物体单独效果，再看最终尺寸下的合成效果。
- **先检查关系，再写动画**：逐项说明“物体是什么／在哪里独立呈现／是否需要插画容纳、承托、抓握或遮挡”。只要需要上述融合关系，就改为整体情境素材或独立镜头；画风一致、路径平滑和技术校验通过都不能使该方案合格。

下文的接触、递接与遮挡设计仅用于整体情境素材内部；独立叠加层遵守上述边界。它不禁止字幕、独立图解或与画中实物无接触关系的气氛效果，也不把这一系列偏好推广成所有视频的限制。

在该边界内准备素材：

- 保持连续的背景底图；若人物或道具会移走，先补齐其背后会露出的区域。
- 人物按**完整身体或完整可见形体**准备相邻姿态，保留统一锚点、比例、服装和受光。可以独立于背景合成，不恢复被否定的独立头部、躯干和手臂机械拼接。
- 允许独立呈现的物体、光效与信息单独准备；需要接触互动的纸张、包裹和人物由整体情境素材承担，不通过补遮罩和阴影绕过融合边界。无需把不会动的每件家具都拆层。
- 同一物体只绘制一份。某对象要从母图移出来单独动画时，底图中不能还留一份；通知、光线若已烘焙进全图，也不能仅在上面叠一个透明层就声称能关闭或移动它。
- 导出层的透明边缘、像素密度和阴影需在实际背景上检查。跨姿态切换不能引起桌椅、窗框、道具位置和整幅光线的无意跳变。

已有整幅姿态序列仍可使用：背景确实稳定、动作不要求露出缺失区域时，可保持整图切换，并叠加符合上述边界的局部动态。若需要从母图中拿走物体、绕到人物背后或改变被烘焙的光照，应补整体情境素材，不用简单裁片或变形掩盖缺口。

## 一镜写到可制作

沿用既有 `visual` 与 `intent`，复杂设计可附按镜号关联的图层表。图层表至少说清“元素与含义／素材归属／运动或持帧／触发与结束事件／前后遮挡／结果状态”。它是设计附件，不是新增的通用动画 JSON 合同。

`visual.action` 写人物与道具的主要变化，`result` 写新增理解；`intent` 说明哪些元素持帧、哪些局部连续变化，以及主次和阅读停留。时刻只在 storyboard 维护，姿态切换、局部动画与声音引用同一组事件；不在附件、提示词或代码里再维护一套秒数表。

确定固定镜头下的图层关系后，按“初态 → 触发 → 过程 → 接触/揭示 → 收束 → 结果”检查画面。不是每镜都需要以上所有阶段。预览时可以暂时停用辅助环境效果，确认主变化依然成立，再决定是否加回。

### 具体提案：文件交出去了，使用者却卡住了

这是对《毕业前，别只练交作业》s06 的可选视觉改法，仅设计，未实现。涉及递纸和接住的部分按当前融合边界整体制作；表内图层描述不能作为分离生成插画与道具后拼接互动的许可。沿用原镜号、文案及既定时长；下表只引用建议事件职责，真正制作时在原 storyboard 中安排事件，不改成第二条时间线。若选为本系列特殊插画，须专门制作整屏情境，不以普通界面演示换名充数。

| 层与元素 | 初态与变化 | 需要准备与核对的内容 |
| --- | --- | --- |
| 场所 | 延续前段活动空间与同一台设备；镜头稳定，前段修改过的指引仍在场 | 连续空间底图、设备与桌面；不要突然换成无关书房 |
| 完整人物 | 主角递出指引后保持；使用者从接住、阅读切到困惑，再指向卡住的步骤 | 多人情境允许配角；完整人物姿态，手与纸的接触对齐；不要求人物在持帧期间晃动 |
| 指引纸张 | `handoff_start` 后沿可辨路径递出，`handoff_contact` 到手停稳，随后保持可读 | 递出、接住及手部遮挡由同一套完整情境素材承担；接住时不再重复出现在递出者手中 |
| 场景内状态 | `try` 后设备只亮到当前步骤；`blocked` 后停在未完成状态 | 把纸面说明与设备上同一步骤对应；未完成不能先给成功标记 |
| 反馈 | `blocked` 给一次局部提示，人物在该节点切到困惑姿态；随后提示落稳 | 反馈局限在卡点，不震动整个房间、不反复红闪；声音引用同一事件 |
| 阅读与承接 | 纸张、卡点、人物视线形成关系；字幕讲清“收到文件，不等于能够执行”，再将卡点交给下一段 | 保留结果，接到原来的“体验指引需要修改”；讲解可按已定文案表达，不擅自替换台词 |

这里的静中有动来自纸张传递与设备状态的过程；人物只在有理由的节点换姿态。环境动画可以省略。若另加低强度光尘，也必须远离手、纸面和字幕，不让它承担本不存在的叙事作用。

其他内容可采用相同方法重新设计：

| 本段含义 | 人物可保持的状态 | 负责推进的局部变化 | 停下后的结果 |
| --- | --- | --- | --- |
| 信息不断打断注意力 | 阅读→注意到→疲惫，按事件换姿态 | 设备通知在限定区域逐次累积；收拢注意后实际停止新增 | 干扰减少，当前任务仍在；不能让已关掉的设备继续弹通知 |
| 外观完成不等于内部接通 | 检查者保持观察，再切到发现问题 | 检修盖打开，显露中断的连接；能量只能走到断点 | 断点保留供讲解，不凭空宣称已修好 |
| 获得之后的新鲜感减退 | 期待→惊喜→平静 | 日历推进、开箱、一次暖光，随后物品留在角落、光效收束 | 同一物品在获得前后的区别；不编造精确情绪分数或持续时间 |

这些是创作提案，不是已有能力清单或固定镜头模板。具体图像与动作仍需制作。

## 执行与能力边界

| 路径 | 当前可确认的内容 | 不能据此声称 |
| --- | --- | --- |
| 现有完整插画脚本 | `scripts/render-illustration.py` 按 storyboard 事件编排整幅姿态图，输出无声片段 | 该脚本已有通用的任意图层、遮罩、粒子或骨骼动画接口；目前计划只接受事件与图片映射 |
| 项目自定义 Canvas 合成 | 当前项目的 `source/plates.cjs` 有事件驱动的整个人物姿态、纸张、道具与状态绘制实例；可为新镜头编写合成逻辑 | 项目代码已成为可选 catalog 能力，或所有新动作无需适配就可用 |
| 基础运动辅助 | `modules/motion/game-feedback.js` 有路径、位置回弹、角标与短粒子辅助；由具体场景调用 | 写一个效果名称即可自动应用到任意插画 |
| 媒体接入 | 基础层可通过 replacement 接入实际编好的插画视频 | 导入视频就能在工作台逐层编辑其中的纸张、人物和光线 |

本系列制作仍进入工作台完成剪辑与最终导出。按 replacement 接入时，插画内部的图层已合成在镜头视频中；字幕、转场和声音按原合同独立。内部修改应保留原始图片层、姿态、代码和事件映射，回到项目源修改再生成，并显式更新工作台素材。若要求工作台直接编辑内部图层，需另外实现可编辑单元、props/schema 与导出验证，不能用保留源代码代替该能力。

编写动画时按当前帧与事件计算状态，环境粒子使用固定种子和可复现规则，不依赖播放过程中累计调用。跳转、逐帧、保存重开与导出应得到相同画面。像素画的轮廓和颗粒应稳定，低速位移不能产生无意的亚像素抖动；人物与道具的接触及遮挡在中间状态也要成立。

## 审看重点

- 按上述边界，独立物体是否被当作画中实物塞进容器、落在桌面、拿在手里或依赖插画遮挡？发现即判视觉不合格，回改方案，不以补阴影继续拼接。
- 叠加物体单独看和按成片尺寸看是否都完成美术设计？粗糙色块、轮廓失衡或与本镜颗粒和明暗明显不一致时，不得作为成品交付。

- 人物持帧期间，所选局部变化是否有内容或气氛作用，还是只有无关闪烁？必要的全静阅读是否保留？
- 人物姿态变化是否由事件触发？背景、脸型、比例、受光和接触是否无意跳变？
- 动的物体是否重复、穿帮或露出底图缺口？前后遮挡、纸张接触和阴影是否对应？
- 主运动与反馈是否有主次？字幕、脸、手和关键道具是否被雨、粒子或光效干扰？
- 动作是否收束成可理解的状态，后文是否保留它？应关闭的通知、应停止的等待是否真的停止？
- 实际素材、连续片段、工作台与最终导出分别核验；静帧、代码和编码帧率都不能单独证明静中有动的效果成立。未检查项按 [Review](review.md) 记未审。
