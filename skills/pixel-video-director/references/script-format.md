# 面向制作的脚本表格规范

写新脚本、视觉分镜或更新片段时使用。默认输出“项目基调＋片段总览表＋逐片段详情表”，组件有多项或独立行为时附组件表。格式模板见 [segment-script.md](../assets/templates/segment-script.md)，完整填写示例见 [script-format.md](../examples/script-format.md)。这是对用户的设计交付格式，不是新增执行 JSON 或第二条时间线。

## 分段与总览

按一个完整理解任务划分片段，不按每句台词、每次动画或字幕切换机械分段。片段用 P01 等稳定 ID；已有项目沿用原 ID。一个片段含多镜时列出对应 S01、S02，每镜有不同构图/动作/接镜时，在详情中分行说明，不能只描述第一镜。

表前简述主题、受众、核心观点、视觉基调、角色职责、画幅/时长依据与已确认约束；未知音轨或时长标为建议，不假称已对齐。系列分类、选角与声音规则仅在对应项目适用。

总览一行一个片段，固定六列：

| 片段 / 镜号 | 时间依据 | 理解目标与推进 | 片段类别 / 画面呈现 | 核心可见变化 / 组件选择 | 实现状态与缺口 |
| --- | --- | --- | --- | --- | --- |

总览用来理解全片顺序，不替代片段细节。时间仅展示建议区间或既有 storyboard 的镜号/事件；工程修改先回写唯一源，再刷新表格。

## 逐片段详情

每个片段单独使用两列表，左列为下列维度，右列写本段具体决定。避免横向十余列和“按需、适当、自然衔接”等无法执行的说明。无此项明确写“无＋理由”，不留空或沿用模板提示；用户尚未提供的关键内容写“待确认＋影响”，不能伪称已确定。

| 维度 | 必须讲清什么 |
| --- | --- |
| 片段与时间 | 片段 ID、镜号、时间依据；多镜列明事件和各镜职责 |
| 理解目标 | 本段回答什么，较前段新增什么，后段承接什么 |
| 类别与呈现 | 分开写项目适用的片段类别和实际画面形式；是否出镜、有无旁白不能替代分类 |
| 旁白与讲解文案 | 实际逐字文案、说话者或无人声安排；有工程时引用 cue ID 并展示其当前文本 |
| 画面与构图 | 环境、景别、主体位置、主次、光源/材质、阅读留白；多镜分别描述 |
| 人物与物体 | 身份、职责、数量、位置及彼此关系；未出镜明确说明 |
| 组件选择 | 组件名称/项目 ID、表达作用、基础复用/组合/自定义判断与理由；现成能力标真实 ID，新设计标项目称呼及实现缺口 |
| 组件风格与样式 | 按组件明确风格、组织样式、堆叠开关及选用理由；共用约定可引用，差异逐项写出，不能只写“统一风格” |
| 组件形态与空间 | 外形、视角、比例、材质、颜色职责、受光、像素尺度、图层厚度/遮挡、文字区及与背景的同框关系 |
| 状态与动作 | 主体初态→触发→可见动作/路径/触点→末态；身份/归属/数量怎样连续，什么保留；静态组件写阅读关系 |
| 节奏与保持 | 触发、触点、收束、阅读开始/结束条件；区分短动作和阅读保持；工程只引用已有事件 |
| 运镜与图层 | 相机、背景、主体、UI 分别动不动，锚定/跟随及遮挡关系；不把图层运动冒充相机运动 |
| 字幕与场景文字 | 实际文字、位置/绑定、层级与重点、底板、显露/追加/替换/收束、可读区间；与旁白可相同但须明确，避免暗中改变文案 |
| 声音 | 旁白、配乐、环境声、音效分别说明有无；有声音时写用途和触发，音效默认留白，不因有动作就加声音 |
| 入场、接镜与收束 | 从前段接住什么、边界过程、交给后段什么及落稳阅读条件；首尾、直切和同镜继续也明确 |
| 素材、能力与验收 | 素材/分层/来源及缺口，已实现/独立试样/待实现的实际范围；本段应看见的验收结果和未审项 |

字幕、分类与接镜的细则沿 [视觉分镜](visual-storyboard.md)，自定义组件沿定位到的 FOUNDATION 的 modules/components/DESIGN.md；本表不另立配色、动作时长或分类规则。

组件选型遵循 FOUNDATION 的 modules/components/DESIGN.md 中“当前创作偏好”：从片段内容主动构思，不只从现有目录挑版式；现成组件很贴合或没有合适的自定义方案时不硬造。脚本写明选择依据，具体规则不在本页另存一套。

## 组件明细

单个简单组件可在详情的“组件选择＋组件风格与样式＋组件形态与空间＋状态与动作”中写完整，不强制再抄一遍。多个组件或有独立变化时附表，避免“若干组件配合展示”一笔带过：

| 组件 ID / 名称 | 解释任务 / 复用判断 | 初态与输入 | 触发 → 动作 → 末态 | 保留、归属与空间关系 | 外观约定引用 | 实现依据 / 缺口 |
| --- | --- | --- | --- | --- | --- | --- |

新机制在表内明确行为，较长五维设计可引用项目附件；引用不能代替本段关键行为。复用组件列真实调用范围，不能把设计名称写成可执行 kind。没有组件时解释画面怎样承担表达，不为填表硬造组件。

## 组件外观与空间约定

组件设计在脚本阶段确定，不留给制作临时补选。新设计默认引用 FOUNDATION 的 `modules/style/COMPONENT-ART.md` 共同画风，再明确本片材质/尺度/受光/接触和组件差异；旧图库尚未迁移，不能用旧图代替新规范。简单单组件直接填片段详情；复杂或多个组件分别用下表，组件明细以 ID 引用，避免加成十余列的宽表。全片/片段共用约定可命名为 A01 等，再由每个组件显式写“继承 A01；本段差异为……/无差异”；跨段沿用同一组件也要说明状态变化是否改变材质、颜色或层次，不允许无意换皮。已有规则只继承明确选择，不能用省略字段的运行默认值代替设计决定。

| 维度 | 每个组件要确定什么 |
| --- | --- |
| 身份与依据 | 对应组件 ID、基础 kind/自定义身份、真实能力或参考源；自定义项目名不等于已注册 kind |
| 风格 | 选定风格或明确无风格；为什么服务本段理解与主次；基础组件按 FOUNDATION 的 modules/components/BASIC-COMPONENTS.md 确定 visualStyle |
| 组织样式 | 主体、读数、标签、传递路径怎样组织；基础组件明确 styleVariant，自定义按对象设计，不硬套三种布局 |
| 堆叠与层次 | 明确启用/关闭、厚度、层间错位、容纳与遮挡的具体作用；基础组件对应 features，自定义按真实实现说明，不虚构参数 |
| 外形与比例 | 实物轮廓、视角、宽高比例、组件与场景的相对尺度；同类实例哪些保持一致 |
| 材质、颜色与光影 | 主材质、明暗层次、主光方向；常态/重点/警告/失效各颜色的职责；是否有透明或辉光及范围，不能只写“高级”“科技感” |
| 文字与阅读 | 组件内标题、数值、单位、标签的区域和层级；字数/位数变化如何留空间，与片段字幕分工 |
| 运动的外观机制 | 风格怎样通过传动、充流或对象自身运动成立；各状态哪些外观变、哪些保留，不能只换颜色或贴装饰 |
| 背景适配与实现 | 像素尺度、受光、接触、遮挡、对比与留白如何同框；区分现有参数可执行、需换素材和需补绘制实现 |

基础组件的合法风格/样式/特性组合以 FOUNDATION 的 modules/components/BASIC-COMPONENTS.md 为唯一依据，脚本不新增选项：朴素分支的组织样式写“不适用”，堆叠关闭；机械/能量按现有互斥规则选一种，堆叠继承该风格。不能把序列化保留的 inset 解释成朴素组件也有一体样式。

自定义组件仍可无风格、选项目既定风格或按对象重设计；选择机械/能量时遵守现有互斥规则。用文字明确造型与机制，不把视觉意图直接写成未实现的 visualStyle/styleVariant/features。所需风格、材质、堆叠或动作若超出现有执行器，明确缺口并先补试样，不能把“代码能跑”当作外观符合脚本。

## 交付前审查与工程交接

- 总览与详情的 ID、顺序、文案、状态、时间依据和边界承接一致；多镜片段覆盖所有镜头。
- 每段十六个维度都有具体内容或明确不适用理由；组件不能只写“用动画表现”“制作时决定”。关键设计缺失的脚本标为草稿并由 agent 补齐，不能标为可制作交接。
- 逐组件核对风格、组织样式、堆叠和形态/材质/空间约定；引用的共用约定存在且无冲突。基础选择满足合法组合，自定义外观不冒充基础字段。未决定的关键外观由 agent 补设计，不直接交给制作猜；具体参数值可在实现时细化，但不得改变已定的视觉机制。
- 已确定的行为与待实现能力分开，不能让制作补猜关键机制，也不能把完整文字表当作实现已完成。素材或代码缺口可保留，但需明确补什么及怎样验收。
- 这是 agent 的交付前内容审查；现有 check/handoff 仍只按工程模型和引用校验，不会自动判断表格完整性或语义质量。表格不是强制用户逐项审批的清单。
- 工程保持 brief/script/storyboard/production-plan 四份源归属。表格展示这些源和设计意图，重复出现的文案/时间只作当前快照；修改回唯一源，再同步快照。纯方案不强制建工程。
