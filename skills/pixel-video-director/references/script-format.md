# 导演设计格式：大白话、草图与详细设计

按 [导演四阶段](director-workflow.md) 使用不同深度的表达，不让粗构思承担完整制作表。当前 [模板](../assets/templates/segment-script.md) 按阶段组织；旧 [六列示例](../examples/script-format.md) 仅作详细交接参考。

## 阶段二：大白话与构思参考

每段展示对应文案、大白话描述、粗线框草图和待讨论问题。草图用简单元素与箭头，不要求视频或完整组件/声音参数。明确标“构思参考，后续可调整、替换或不采纳”；用户明确要求单列保存，不从草图自动推断。

## 阶段三：结构化设计与白模

默认突出文案/表达任务、背景与构图、起态→动作→末态、字幕/阅读时序、前后连接。以 [工作台数据](director-project.md) 驱动同一片段的播放；完整风格、组件、声音和能力细节按需展开，不能让一张宽表遮住主要决定。

## 六列主表

需要详细文字交接或兼容旧稿时，按下表展示阶段三已采用的当前设计。按模块分组、每镜一行，保留片段、镜头和文案 ID，不复制出第二份可冲突的稿。

| 片段 / 镜头 / 时间 | 文案与屏幕文字 | 画面设计 | 动作与接镜 | 声音 | 制作备注 |
| --- | --- | --- | --- | --- | --- |
| 稳定 ID；预估区间或工程事件 | 引用文案；字幕形式与阅读 | 主体、构图、背景、风格与组件 | 起态→动作→末态；交出、接住与停留 | 旁白/配乐/环境/音效的安排 | 素材、实际能力、缺口及验证 |

## 填写边界

- 文案引用编剧唯一源；白模字幕直接引用文案 ID。无真实音轨明确预估，不能声称精确对齐。
- 草图只是参考，采用决定在本阶段独立落实；阶段二未细化内容不算失败。
- 画面解释关键转折，身份、数量、归属、焦点与接镜明确；动作与阅读分开估时。
- 正式制作前确定必要的风格、外观和能力依据；白模可用占位验证节奏，但不能声称正式外观或复杂能力通过。
- 声音四类按需判断，当前动态工具无音轨，不自动配音或用占位声音冒充混音。
- 已建工程按 [创作合同](authoring.md) 回写唯一源；白模不成为第二条正式执行时间线。

## 组件明细

单个简单组件可在主表的“画面设计＋动作与接镜”中写完整，不强制再抄一遍。多个组件或有独立变化时附表，避免“若干组件配合展示”一笔带过：

| 组件 ID / 名称 | 解释任务 / 复用判断 | 初态与输入 | 触发 → 动作 → 末态 | 保留、归属与空间关系 | 外观约定引用 | 实现依据 / 缺口 |
| --- | --- | --- | --- | --- | --- | --- |

新机制在表内明确行为，较长五维设计可引用项目附件；引用不能代替本段关键行为。复用组件列真实调用范围，不能把设计名称写成可执行 kind。没有组件时解释画面怎样承担表达，不为填表硬造组件。

## 组件外观与空间约定

组件设计在导演视觉设计阶段确定，不留给制作临时补选。新设计默认引用 FOUNDATION 的 `modules/style/COMPONENT-ART.md` 共同画风，再明确本片材质/尺度/受光/接触和组件差异；旧图库尚未迁移，不能用旧图代替新规范。简单单组件直接填主表；复杂或多个组件分别用下表，组件明细以 ID 引用，避免加成十余列的宽表。全片/片段共用约定可命名为 A01 等，再由每个组件显式写“继承 A01；本段差异为……/无差异”；跨段沿用同一组件也要说明状态变化是否改变材质、颜色或层次，不允许无意换皮。已有规则只继承明确选择，不能用省略字段的运行默认值代替设计决定。

| 维度 | 每个组件要确定什么 |
| --- | --- |
| 身份与依据 | 对应组件 ID、基础 kind/自定义身份、真实能力或参考源；自定义项目名不等于已注册 kind |
| 风格 | 选定风格或明确无风格；为什么服务本段理解与主次；基础组件按 FOUNDATION 的 modules/components/BASIC-COMPONENTS.md 确定 visualStyle |
| 组织样式 | 主体、读数、标签、传递路径怎样组织；基础组件明确 styleVariant，自定义按对象设计，不硬套三种布局 |
| 堆叠与层次 | 明确启用/关闭、厚度、层间错位、容纳与遮挡的具体作用；基础组件对应 features，自定义按真实实现说明，不虚构参数 |
| 外形与比例 | 实物轮廓、视角、宽高比例、组件与场景的相对尺度；同类实例哪些保持一致 |
| 材质、颜色与光影 | 主材质、明暗层次、主光方向；常态/重点/警告/失效各颜色的职责；是否有透明或辉光及范围，不能只写“高级”“科技感” |
| 文字与阅读 | 组件内标题、数值、单位、标签的区域和层级；字数/位数变化如何留空间，与片段字幕分工 |
| 运动的外观机制 | 风格怎样通过传动、充流或对象自身运动成立；各状态哪些外观变、哪些保留，不能只换颜色或贴装饰 |
| 背景适配与实现 | 像素尺度、受光、接触、遮挡、对比与留白如何同框；区分现有参数可执行、需换素材和需补绘制实现 |

基础组件的合法风格/样式/特性组合以 FOUNDATION 的 modules/components/BASIC-COMPONENTS.md 为唯一依据，脚本不新增选项：朴素分支的组织样式写“不适用”，堆叠关闭；机械/能量按现有互斥规则选一种，堆叠继承该风格。不能把序列化保留的 inset 解释成朴素组件也有一体样式。

自定义组件仍可无风格、选项目既定风格或按对象重设计；选择机械/能量时遵守现有互斥规则。用文字明确造型与机制，不把视觉意图直接写成未实现的 visualStyle/styleVariant/features。所需风格、材质、堆叠或动作若超出现有执行器，明确缺口并先补试样，不能把“代码能跑”当作外观符合脚本。

导演阶段三按 [Check](segment-check.md) 核对同一设计及白模；六列/十列仅是按需展开或交接的视图，各视图引用相同 ID 与唯一源。

## 交付前审查与工程交接

- 文案与视觉主表的 ID、顺序、文案、状态、时间依据和边界承接一致；多镜片段覆盖所有镜头。
- 六列覆盖全部镜头；不再逐段填写十六维详情，无此项说明理由；组件不能只写“用动画表现”“制作时决定”。关键设计缺失的脚本标为草稿并由 agent 补齐，不能标为可制作交接。
- 逐组件核对风格、组织样式、堆叠和形态/材质/空间约定；引用的共用约定存在且无冲突。基础选择满足合法组合，自定义外观不冒充基础字段。未决定的关键外观由 agent 补设计，不直接交给制作猜；具体参数值可在实现时细化，但不得改变已定的视觉机制。
- 已确定的行为与待实现能力分开，不能让制作补猜关键机制，也不能把完整文字表当作实现已完成。素材或代码缺口可保留，但需明确补什么及怎样验收。
- 这是 agent 的交付前内容审查；现有 check/handoff 仍只按工程模型和引用校验，不会自动判断表格完整性或语义质量。表格不是强制用户逐项审批的清单。
- 工程保持 brief/script/storyboard/production-plan 四份源归属。表格展示这些源和设计意图，重复出现的文案/时间只作当前快照；修改回唯一源，再同步快照。纯方案不强制建工程。
