# 本系列上层要求与经验：计算机知识口播

适用于延续本项目的计算机知识分享视频。开始新主题或局部修复时，先把相关约束写进 brief，再选择场景与配方；用户的新要求优先。这里记录项目偏好，不改变基础 skill 的通用默认值。

本文件维护**当前有效的制作要求**，作为本系列新片与修改任务的入口。表格说明采用什么方向，纠偏记录说明为什么；具体模块的参数、能力状态和历史实验仍由各自文档维护。实现暂缺时应列为制作缺口，不能把实现现状当作降低用户要求的理由。

| 维度 | 已确认的方向 | 制作时的含义 |
| --- | --- | --- |
| 画风 | 像素游戏风格，服务计算机知识口播 | 保留清楚的像素颗粒、道具与场景质感；减少战斗、任务、HUD 等包装时，仍保留像素画风 |
| 气氛 | 偏暗、丰富、精致；不以城市赛博楼群作背景 | 用局部冷暖光、材质与前中后景建立层次；为标题、主体与字幕留出可读空间 |
| 人物 | 已确认 V3：无围巾的阿棕为主角，阿墨、栗子、老麦为配角；出镜按脚本需要选择 | 主角可作为口播人物直接讲述，嘴形、表情和停顿要有说话感；情境插画可选主角或配角。无人镜头同样成立，不给所有画面硬塞小人 |
| 半身仿真人 | 陈先生为虚构专题配角，仅半身 | 仅用于人物画像/身份、历史复刻或人物核心的关键场景，如决策、访谈、观点与情绪转折；历史人物另做对应身份画像。常规口播和流程图解使用像素人物 |
| 画面主次 | 精致画面优先，人物不必每镜出现 | 保留形象识别；物体特写、场所转换或总结关系需要空间时，可暂时退场 |
| 组件结构 | 基础五类组件的整体效果已获明确认可，用户希望继续丰富选择 | 保持共同视觉语言，按信息关系扩展流程、结构、数据与讲解能力；多组件组合先定主次，避免同镜堆满 |
| 背景选择 | 固定风格基调并保留样板，背景不固定为几张图 | 按本镜场所与构图生成/选取项目素材，允许用户按镜头换图或替换画面 |
| 插图参考 | 当前插图集合只供参考风格与演绎方法，是否使用由本片脚本决定 | 不要求每片包含此集合或插画片段；故事结构、镜头顺序、构图、动作及数量重新设计，不照搬“书桌→抱头→趴下”或“插画开场→组件总结” |
| 人物与表演 | 五人形象和30张动作参考已确认；讲述需要低幅度动态，避免全程微笑 | 拆头拼身被否定；完整人物/场景先成立，再制作相邻姿态。新完整插画试样为有限关键姿态动画，尚待审美反馈，无通用骨骼或音素对齐 |
| 情境演绎 | 文案涉及具体处境、行为、情绪或因果时，允许使用本系列人物制作动态插画 | 在组件讲解之间安排有解释任务的情境镜头，例如操作电脑、查阅资料、遇到报错、核对结果；建立处境、动作、结果再回到讲解。保持角色身份、像素基调与空间接触关系，详见 [人物动态与情境插画](character-illustration.md) |
| 叙事与转场 | 有辨识度，随观点推进 | 先设计概念、物体状态和空间关系，再选转场；不能靠同一房间反复推拉来承担所有论点 |
| 文字与声音 | 画面解释，旁白组织，字幕辅助阅读 | 标签保持短；连接线和节点也要避字。声音绑定可见事件，嘴型只按已实现能力描述 |
| 游戏反馈细节 | 竞赛 V6 的选中、回弹、筹码转移、确认、阶段进度和结算获得认可 | 按状态复用基础层 `modules/scenes/GAME_FEEL.md`，保留已认可的视觉节奏 |
| 音效 | 已确认街机电子主体＋鼓点＋轻重／切分／回弹的六种声音原子 | 先读基础层 `modules/audio/ARCADE.md`，用 `arcade-select/pickup/seat/launch/reject/reward` 按可见动作选择；新项目另调音量和密度 |
| 维护 | 小入口、独立模块、结构化创作源 | 风格、人物物体、文字、运动、音频、场景分别维护；参数与文案不堆成一大段 prompt |

## 本轮纠偏的具体依据

| 曾经的误解 | 应保留的判断 |
| --- | --- |
| “不要太重的游戏感”被改成普通科技背景 | 调整的是题材包装与信息密度，像素画风仍是明确要求 |
| 人物不必常驻，于是取消脚本里的主角口播；或为了统一形式每镜都放人 | 人物职责与出镜比例分别决定；脚本需要主角讲述时保留口播并做出说话感，概念、流程、数据和物体镜头可无人 |
| 人物站立，被理解成其屏幕像素必须固定 | 场景运镜与角色肢体表演是两件事；完整房间可以统一变换 |
| 侧边站立，被执行成单张人物全程微笑 | 用户在 2026-10-19 明确要求低幅度动态；站位稳定仍需人物自身的自然动作，画面推拉不能证明人物已在表演 |
| 丰富了组件，就把整段文案都填入组件 | 文案中的处境、行为和情绪可以让本系列人物进入情境演绎；组件继续负责结构、比较和总结。场景插画需要有可见动作与理解结果 |
| 将右侧连续房间裁成一个缩放窗口 | 局部运动适合独立图文、透明物体或真实面板；墙、桌、灯不能被无依据地裁断 |
| 修掉局部裁片后，始终在同一背景推拉 | 空间连续只是基础；还要让场所、主物体或状态变化推进理解 |
| 首尾一致、无透明边角、测试通过，就宣布转场好看 | 再检查叙事作用、节奏与实际成片；技术检查不能替代审美判断 |

## 2026-10-19：人物动态与情境插画反馈

用户评价 32 秒《AI 全栈路线怎么走》的人物：“我希望人是能动态的，幅度可以很低，但得有，不能就站在那里傻笑，很奇怪”。同时提出借鉴参考片，在讲解中按文案插入由现有人物形象演绎的动态插画。

这两条是本系列当前要求；V3 五人基准和动作参考保留。后续拆头双样例被用户否定，改为完整人物/完整情境插画，补齐必要姿态后编成片段接入原片。技术帧率与像素变化不能替代视觉验收。参考拆解、失败原因及当前试样见 [人物动态与情境插画](character-illustration.md)。

## 2026-10-20：参考范围、出镜与口播职责

用户明确插图集合“是参考，而不是说每次都要有”，参考“风格和模式”，不照搬结构；同时强调不是所有画面都要有小人，主角可作为口播人物说话，插画按脚本选择主角或配角。这些要求已进入上表和 [选镜头规则](character-illustration.md)。

用户指出现片缺少说话感觉。当前情境姿态只展示角色经历和反应，不证明主角口播已实现；后续安排出镜讲述时，需补嘴形、表情与话语停顿的配合，以连续播放检查说话感。实现暂缺应记录并补齐，不能把“静态人物配旁白”当成达标，也不能因此把口播职责全部取消。

## 怎样继续积累

后续反馈按“日期与用户原话 → 适用范围 → 当前采用的规则 → 相关模块/源工程 → 实现与验收状态”记录。能改变新片决策的结论进入本表或纠偏记录；详细版本取舍进入基础 skill 的 `references/iteration-history.md`，参数和能力状态回到所属模块。

例如，本次“人物需要动态”记录为本系列要求，具体眨眼/口播资产的实现状态归人物模块；“组件指南缺少图片参考”由组件模块补充实渲染图片、状态对照和可运行源。文档已补充与用户已认可分别记录。更新时保留原反馈的适用范围，新的明确要求覆盖冲突的旧解释。

## 实例与认可范围

2026-10-19，用户明确认可 [基础五类组件演示的源工程](../examples/component-system/brief.json)及可变背景方案，并要求继续扩展。其认可覆盖该次演示的整体风格和组件方向；[新增七类与组合](../examples/component-expansion/brief.json)是后续扩展，审美认可状态独立记录，不自动继承。

[18 秒考研叙事版](../examples/cs-postgrad-narrative-18s/brief.json)展示概念、物体与空间共同推进观点，结尾回收真实镜头作为判断材料。复用设计方法，片长、镜头数、道具与配色按新主题决定。

各次用户反馈、竞赛 V3–V8 的取舍及音效停止探索的边界，统一保存在基础 skill 的 `references/iteration-history.md`；通过 [基础依赖](handoff.md) 定位后读取。当前延续 V6 视觉 / V8 音画与六种已确认声音，新项目另做实际混音核验。
