# 计算机知识口播：已确认的表达方向

适用于延续本项目的计算机知识分享视频。开始新主题或局部修复时，先把相关约束写进 brief，再选择场景与配方；用户的新要求优先。这里记录项目偏好，不改变基础 skill 的通用默认值。

| 维度 | 已确认的方向 | 制作时的含义 |
| --- | --- | --- |
| 画风 | 像素游戏风格，服务计算机知识口播 | 保留清楚的像素颗粒、道具与场景质感；减少战斗、任务、HUD 等包装时，仍保留像素画风 |
| 气氛 | 偏暗、丰富、精致；不以城市赛博楼群作背景 | 用局部冷暖光、材质与前中后景建立层次；为标题、主体与字幕留出可读空间 |
| 人物 | 已确认 V3：无围巾的阿棕为主角，阿墨、栗子、老麦为配角 | 按基础库 `modules/library/CHARACTERS.md` 选人设与动作；常态侧边站立，动作有触发与收束，整体相机可带人物进出画面 |
| 半身仿真人 | 陈先生为虚构专题配角，仅半身 | 仅用于人物画像/身份、历史复刻或人物核心的关键场景，如决策、访谈、观点与情绪转折；历史人物另做对应身份画像。常规口播和流程图解使用像素人物 |
| 画面主次 | 精致画面优先，人物不必每镜出现 | 保留形象识别；物体特写、场所转换或总结关系需要空间时，可暂时退场 |
| 组件结构 | 基础五类组件的整体效果已获明确认可，用户希望继续丰富选择 | 保持共同视觉语言，按信息关系扩展流程、结构、数据与讲解能力；多组件组合先定主次，避免同镜堆满 |
| 背景选择 | 固定风格基调并保留样板，背景不固定为几张图 | 按本镜场所与构图生成/选取项目素材，允许用户按镜头换图或替换画面 |
| 人物与表演 | 五人形象、人设、脸型差异和每人六张动作参考已确认 | 待机、挥手、口播、左右迷糊摇头与抱头崩溃均按情节使用；当前支持按事件切换解释、疑惑、挥手和待机姿态，保持脚底锚点；音素口型、骨骼和透明清稿尚未完成 |
| 叙事与转场 | 有辨识度，随观点推进 | 先设计概念、物体状态和空间关系，再选转场；不能靠同一房间反复推拉来承担所有论点 |
| 文字与声音 | 画面解释，旁白组织，字幕辅助阅读 | 标签保持短；连接线和节点也要避字。声音绑定可见事件，嘴型只按已实现能力描述 |
| 游戏反馈细节 | 竞赛 V6 的选中、回弹、筹码转移、确认、阶段进度和结算获得认可 | 按状态复用基础层 `modules/scenes/GAME_FEEL.md`，保留已认可的视觉节奏 |
| 音效 | 已确认街机电子主体＋鼓点＋轻重／切分／回弹的六种声音原子 | 先读基础层 `modules/audio/ARCADE.md`，用 `arcade-select/pickup/seat/launch/reject/reward` 按可见动作选择；新项目另调音量和密度 |
| 维护 | 小入口、独立模块、结构化创作源 | 风格、人物物体、文字、运动、音频、场景分别维护；参数与文案不堆成一大段 prompt |

## 本轮纠偏的具体依据

| 曾经的误解 | 应保留的判断 |
| --- | --- |
| “不要太重的游戏感”被改成普通科技背景 | 调整的是题材包装与信息密度，像素画风仍是明确要求 |
| 人物不必常驻，于是整片删掉人物；或为了动感让人物行动 | 人物职责与出镜比例分别决定；侧边站立口播仍需保留 |
| 人物站立，被理解成其屏幕像素必须固定 | 场景运镜与角色肢体表演是两件事；完整房间可以统一变换 |
| 将右侧连续房间裁成一个缩放窗口 | 局部运动适合独立图文、透明物体或真实面板；墙、桌、灯不能被无依据地裁断 |
| 修掉局部裁片后，始终在同一背景推拉 | 空间连续只是基础；还要让场所、主物体或状态变化推进理解 |
| 首尾一致、无透明边角、测试通过，就宣布转场好看 | 再检查叙事作用、节奏与实际成片；技术检查不能替代审美判断 |

## 实例与认可范围

2026-10-19，用户明确认可 [基础五类组件演示的源工程](../examples/component-system/brief.json)及可变背景方案，并要求继续扩展。其认可覆盖该次演示的整体风格和组件方向；[新增七类与组合](../examples/component-expansion/brief.json)是后续扩展，审美认可状态独立记录，不自动继承。

[18 秒考研叙事版](../examples/cs-postgrad-narrative-18s/brief.json)展示概念、物体与空间共同推进观点，结尾回收真实镜头作为判断材料。复用设计方法，片长、镜头数、道具与配色按新主题决定。

各次用户反馈、竞赛 V3–V8 的取舍及音效停止探索的边界，统一保存在基础 skill 的 `references/iteration-history.md`；通过 [基础依赖](handoff.md) 定位后读取。当前延续 V6 视觉 / V8 音画与六种已确认声音，新项目另做实际混音核验。
