# 计算机知识口播：已确认的表达方向

适用于延续本项目的计算机知识分享视频。开始新主题或局部修复时，先把相关约束写进 brief，再选择场景与配方；用户的新要求优先。这里记录项目偏好，不改变基础 skill 的通用默认值。

| 维度 | 已确认的方向 | 制作时的含义 |

## 配乐要求

2026-10-20，用户指定本系列 BGM 为 Kevin MacLeod 的 [《Chill Wave》](https://kevinmacleod.bandcamp.com/track/chill-wave)。除非用户另行指定，延续本项目时使用该曲；它是选定曲目，不只是风格参考。曲目选择属于本系列偏好，不改变基础 skill 的通用默认值。

- 在 brief 中记录曲名、作者、来源链接和配乐要求；实际使用的音频文件随项目记录，不把网页链接当作已取得的音频素材。
- 旁白保持清楚，BGM 作为底层氛围；配合六种已确认音效调整音量和密度。开头与结尾平滑淡入淡出，截取或循环按片长安排，接点需实际听音核验。
- 该 Bandcamp 曲目页链接的许可为 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。发布时保留曲名、作者、曲目来源与许可链接；如有截取、循环或混音，注明实际修改。可在发布说明中写：`配乐：Chill Wave — Kevin MacLeod；来源与许可见链接；音频修改按本片实际情况注明。`
- 制作时通过基础层 `import-bgm PROJECT` 将内置原曲导入创作工程，再把输出配置写入 `production-plan.bgm`。本系列初始使用 `gain=0.18`、`speechDuck=0.25`，60fps 下淡入60帧、淡出90帧；按片长与实际听感调整。handoff 后 Canvas 与 Remotion 共用配乐混音，流程见基础层 `modules/audio/MUSIC.md`；新配置不继承旧成片的听音认可。

## 本轮纠偏的具体依据

| 曾经的误解 | 应保留的判断 |
| --- | --- |
| “不要太重的游戏感”被改成普通科技背景 | 调整的是题材包装与信息密度，像素画风仍是明确要求 |
| 人物不必常驻，于是整片删掉人物；或为了动感让人物行动 | 人物职责与出镜比例分别决定；侧边站立口播仍需保留 |
| 人物站立，被理解成其屏幕像素必须固定 | 场景运镜与角色肢体表演是两件事；完整房间可以统一变换 |
| 将右侧连续房间裁成一个缩放窗口 | 局部运动适合独立图文、透明物体或真实面板；墙、桌、灯不能被无依据地裁断 |
| 修掉局部裁片后，始终在同一背景推拉 | 空间连续只是基础；还要让场所、主物体或状态变化推进理解 |
| 文档写“允许换背景”，制作时仍在旧房间之间轮换 | 先按新主题设计空间、尺度与主体变化，再找素材；风格一致不要求场所、光线与构图相同。需要新图时实际制作并接入 |
| 首尾一致、无透明边角、测试通过，就宣布转场好看 | 再检查叙事作用、节奏与实际成片；技术检查不能替代审美判断 |

## 当前单主角口播约束与原因

本轮用户进一步明确：成片不显示人物姓名；顶部用实心矩形推进；口播保持一个姿势只张嘴闭嘴；配角应作为插图形象，不能接棒口播。上一版的问题出在把“首镜放配角”扩写为“由配角发问”，并将配角填入 actor 讲述者槽位，同时把技术上可运行的低帧全身姿态切换误当成合适的口播表现。上述做法已撤回，旧示例只保留复盘和插图素材价值。

后续该系列在 brief 中设置：

```json
{"singleNarrator":{"narrator":"actor.azong.v3","hiddenCharacterNames":["阿棕","阿墨","栗子","老麦","陈先生"]}}
```

actor 只放主角或 null；配角通过项目插图/场景素材出现。库内姓名、文件名和角色 ID 仍可用于工程管理，但不进入画面标签、姓名条、字幕、旁白或图片烘焙文字。开场疑问也由同一主角口播，画面可展示配角的疑惑情境，不能靠更换主持人来解释出场角色。

同姿势口型需要一张固定底图和对齐的局部开闭嘴帧；身体、脸部其余区域与手臂不随开闭嘴改变。开合跟随实际旁白区间，无声间隙闭嘴，不要求音素级对齐。当前姿态执行器尚未提供该适配，下一次制作必须先补齐并验证，不能把静态图或 neutral/talk 全身图交换当作完成。
