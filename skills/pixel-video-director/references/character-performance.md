# 人物表演：行为、触点与反应

本系列默认超粗像素游戏精灵与完整姿态表演，先读 FOUNDATION 的 `references/current-style.md`。精细人物、整幅插画和其他造型只在本片需要时使用；画法不限定可演的行为。

## 按本段行为设计

先确定人物想完成什么、谁或什么阻碍了他、这次尝试留下什么结果。把动作写进既有 `visual.action/result/continuity` 与 `intent`，具体时刻只在 storyboard 事件维护。

- 疑惑源于刚到达的消息、操作反馈或比较结果；视线、停顿和姿态回应该事件，不默认每次歪头、抱头或摊手。
- 主动操作先定支撑面与交互边缘，再排准备、接触与结果。手、脚或指针触到对象的帧带动状态和必要的声音。
- 反应可以保持一张清楚姿态，周围物件继续推进；需要跑跳或移交时，按用途补完整姿态与轨迹，不靠全程摇摆制造动作。
- 相邻动作的目的、轮廓、接触对象、节奏与结果相同，就合并停留或换成确有意义的行为。允许重复起势来对照第一次失败、第二次完成。

## 每段的最小表演约定

| 决定 | 要写清的画面 |
| --- | --- |
| 起态 | 朝向、支撑点、手与物体原来在哪里，当前由谁持有 |
| 触发与转折 | 哪条消息或哪个事件改变行为；接触后哪个对象给反馈 |
| 过程 | 完整起姿、关键中间／接触姿、末姿，位移轨迹与遮挡层 |
| 收束 | 哪个结果保留、对象归谁，何时落稳阅读及交给下一镜 |

手机对话可看 [消息与反应](../../pixel-game-video/examples/asking-motion/index.html#chat-reaction) 和 [人物感谢特写](../../pixel-game-video/examples/asking-motion/index.html#thanks-closeup)。先让消息被读到，再由疑惑或举拳启动运镜。运镜期间让触发这次反应的那条气泡保持可读。跨镜接物要看交出、在途和接住，给接收者留出辨认空间。

## 素材与实现

以本片已选人物原图为身份基准，用同一机位准备完整姿态。超粗精灵核对剪影、服装色块、朝向、支撑和触点；其他画法按对应结构核对。不要拆头拼身、随意镜像、拉伸肢体或用叠化产生双手和双物。

姿态曝光可以抽帧，整身位移、飞行轨迹和相机逐帧求值；脚落板时须跟随真实承载面。普通 Canvas 的 `poseAtlas` 按 FOUNDATION 的 `modules/scenes/PRESENTER-ACTIONS.md` 装配，独立试样按 `modules/scenes/character-performance/README.md` 纯采样。检查正放、倒拖和随机帧的一致性。

动作词汇与关系草案用于构思，示意图、候选图集和旧六姿态不表示本镜能力已完成。缺素材就按当前授权制作，再看实际占画尺寸与连续播放。共享入库、引擎接入和本片采用分别记录，不能把某个案例的认可推广为整库可用。
