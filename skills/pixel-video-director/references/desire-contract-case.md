- 文件约 44.37 秒，592×1280，是手机录屏；横屏正文约位于原画幅 y=380–714。平台头像和按钮叠在正文右侧，上方弹幕、下方账号信息不属于正文设计。末段约 43.5 秒起被手机控制中心遮住。

- 片中将观点归于纳瓦尔并展示《纳瓦尔宝典》；这是画面中的归属声明，本次未核验书中文字、引文准确性或幸福相关论断。开心条及“0次”等计数作为修辞示意观察，不当作统计证据。

## 叙事逻辑：从熟悉的期待到重新解释

| 约略位置 | 可见字幕与情境 | 本段在推进什么理解 |
| --- | --- | --- |
| 0–10 秒 | 小时候期待长大；随后期待考上，再期待有钱。人物年龄、装束与手中物改变，每次出现一份合同 | 用相似句式建立熟悉经验；期待换了对象，但“达到条件才幸福”的模式没有变。合同先作为尚未解释的线索出现 |
| 10–13 秒 | 字幕追问等了多年是否等到；人物与合同缩小，更多合同扩展到远处，出现“0次”提示 | 把三个例子扩展为不断累积的模式，并让原先承诺与当前状态产生矛盾，给新解释留下位置 |
| 13–22 秒 | 一份“欲望合同”占据中心；羽毛笔写入甲方“你”、乙方“你自己”；正文逐步显露等待得到某物之前同意不开心，随后签章 | 将关注点从“还没获得幸福”转到“自己设定了什么前提”。签约双方和条款是概念的核心，签章让承诺变成可见的确认动作 |
| 22–26 秒 | 暗场、聚光灯下展示书封，并通过字幕说明主题来自书的下半部分 | 在问题与概念已出现后交代书和内容位置。书封提供归属与结构线索，本身不证明观点成立 |
| 26–32 秒 | 字幕承接上一期“钱”，再提出有了钱仍不开心；人物坐在金钱堆上，头上有阴云，后来下雨 | 区分拥有资源与主观感受，说明这一期为什么继续谈幸福；金钱堆和阴云同时出现，画面呈现两者并存 |
| 32–34 秒 | “第一份”合同章节卡，盖章后进入案例 | 将总概念分解为可逐一查看的例子；片段不足以确认后面还有几份或怎样总结 |
| 34–41 秒 | 等快递的日历推进至第15天；开箱出现鞋、暖光、彩屑，开心条上升；“3天后”房间变冷，鞋在角落落灰，出现“下一双…” | 在同一物品上比较获得前、刚获得、获得后的状态，具体演示满足可能短暂、欲望再转向下一个对象的说法 |
| 41–约43.5 秒 | 考上后的烟花与开心条；随后开始出现涨薪例子，录屏随即被遮挡 | 从消费场景扩展到成就场景；只确认例子已展开，不推断后续论证与收束 |

这段可重建为“熟悉期待 → 模式累积 → 追问落差 → 提出解释 → 说明内容位置 → 具体例子展开”。这是本段的组织方式，不是每支科普片必须套用的结构。值得迁移的是：新观点回应前面已经建立的疑问，而不是一个标题结束后换另一个标题。

## 画面设计：变化为什么有用

| 可见做法 | 解释作用 | 迁移时保留什么 |
| --- | --- | --- |
| 同一舞台、同一角色，年龄、服装和持物变化；合同留下 | 观众不用反复认识新空间，能比较不同阶段相似的期待 | 保持比较中的共同项，只改变需要比较的条件；不强制人物必须长大或换装 |
| 三份合同扩成大量合同，人物相对变小 | 拉远带出数量与累积，尺度变化增加信息 | 运镜落点揭示之前看不到的关系；画面中的大量是示意，不能编造实际数量 |
| 合同由环境中的物体变成主要阅读面 | 同一母题从线索变为解释模型，前面的画面获得新的含义 | 先埋下可辨对象，再用它解释前段；不是到概念段才突然加一个无关隐喻 |
| 依次填写签约双方、条款，再盖章 | 阅读顺序与概念拆解一致；“双方都是自己”需要被实际看见 | 将信息顺序写清，让动作确认状态；合同文字与字幕重复处也需检查阅读负担 |
| 深蓝环境中集中照亮人物和合同；书封阶段周围更暗 | 当前主体有明确轮廓、亮度和尺寸优势 | 控制焦点与环境竞争；不直接复制黑金色、聚光灯或暗色舞台 |
| 日历、开箱、开心条、冷暖变化、落灰、下一双 | 物品、时间、情绪和下一次期待形成前后可对照的状态链 | 反馈由具体事件触发，结果留到后续；情绪条是辅助说明，不替代事件或真实数据 |
| 某些段落主要读合同，某些段落看物体动作，章节卡短暂分段 | 图解、情境与结构提示分工，观众的观看任务随段落变化 | 按信息任务选择形式，同一场景内部也可推进；不设每几秒换镜或插画占比 |

从这些抽帧只能确认屏幕上的尺度变化、遮挡和状态顺序，不能确认原作者使用的引擎、真实三维运镜、素材分层或成本。尤其合同切到书封之间有暗场，不应描述成已证实的无缝物体变形。

## 对照我们的当前设计

本次以工作区最近的完整项目《毕业前，别只练交作业》作为主要对照，并审读导演规则与代表样例。这不是对所有作品的评分，也不回改旧片。对照片约180秒，项目设为仅音效；与参考片段在主题、长度和声音安排上不同，不直接比较切镜频率或字幕速度。

核对对象为工作台导出的 MP4、同名项目 JSON、SRT、`source/author.py` 与 `source/plates.cjs`。本轮重新解码成片约每5秒取样，结合源事件检查设计；未做本片连续有声审片。MP4 SHA256：`eac0e2b1cb82863cc08990ad7832b01f2584a725a50170673306530f2232a090`；配对项目 JSON SHA256：`113fd0d5f81540346831f33d8cc547b3c01792b27588f2661297d2f105618be2`。

| 对照位置 / 源镜号 | 已经有效的设计 | 仍可改进的地方 |
| --- | --- | --- |
| 0–15秒 / s01–s02 | 用兑换机与成绩建立“满绩能否兑换好人生”的问题，随后交出任务；开头有可辨道具 | 后续对成绩与现实任务的关系主要转为文字比较。兑换隐喻如何被修正、怎样在结尾兑现，还能更明确 |

| 60–86秒 / s05 | 让资源变化、调整关键流程、试用、受阻、修改与确认形成状态链；源事件明确区分尝试与结果 | 可继续使用修改后的指引与实际操作结果连接后文，不必在动作完成后丢弃案例 |
| 86–109秒 / s06 | 层级图清楚列出负责人、待确认与使用反馈 | 从活动空间切回书房，具体交接变成文字条目；“文件有人接得住”尚可用实际接收与使用的区别呈现 |

| 164–180秒 / s09 | 回到完整书桌情境，保留“满绩”物，呼应开头；不是完全没有回收 | 回收目前更多是同一物品再出现。可让它与新产生的任务判断、修改记录共同出现，明确它在整段解释后的新位置 |

因此，缺口不是“没有漂亮背景”或“卡片不能用”。现有 skill 已写有主体初态→动作→结果、母题、统一空间、阅读层级和转场承接。需要强化的是**整段观点的依赖关系，以及前镜结果怎样进入后镜成为判断材料**。字段填全、背景更换、卡片逐项显露都不能单独保证这一点。

## 下次分析新参考片

1. 先确认素材是完整原片、节选还是录屏，列明可见范围、遮挡及实际检查方式。平台 UI、评论和弹幕与正文分开。
2. 按观点转折记录“约略位置／字幕或画面事实／新增理解／引出的问题”，再分析画面如何承担它。缺失的前后内容保留未知。
3. 对关键运动核对连续片段或顺序帧；说明是否实际听音。将观察事实、效果判断、技术推测和自己的新设计分开。
4. 对照当前真实工程与渲染结果，分别找已有有效方法、执行不足和规则缺口。将题材/系列选择留在原范围，不因参考片更丰富就增加特效、场景或插画配额。
5. 把可复用方法更新到唯一所属规则，用当前项目的一个设计改法检验它是否具体。记录文档验证与未审项目，不把本次分析写成重制完成或用户审美认可。
