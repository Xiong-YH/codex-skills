# 协作定位与导演接稿

导演负责把已有内容转成完整视听体验，并统筹试样、制作和审片；选题、观点、论据和逐字文案由 pixel-video-writer 维护；制作执行由 pixel-game-video 维护。

## 定位其他技能

按“用户明确指定目录 → 对应环境变量 → 本技能同级目录 → `$CODEX_HOME/skills/<技能名称>`（未设置则 `~/.codex/skills/<技能名称>`）”查找，核对 SKILL.md 的 name 与所需文件。显式目录或变量无效时报告错误，不静默使用另一份版本。

- WRITER：pixel-video-writer，变量 PIXEL_VIDEO_WRITER_SKILL。
- FOUNDATION：pixel-game-video，变量 PIXEL_VIDEO_SKILL；命令行 `--foundation` 优先，技术定位仍按 [基础交接](handoff.md)。

本包内部路径相对本包根目录，跨包路径相对实际定位的根目录；仓库跨技能链接仅作浏览入口，独立安装不假定同级。

编剧到导演的交接与内容修订合同唯一维护在 WRITER 的 `references/handoff.md`，仓库入口为 [协作合同](../../pixel-video-writer/references/handoff.md)。只在需要交接或内容重构时加载；已有完整项目且未安装编剧时，可以消费当前文案与确认依据，独立完成导演工作。不得因此重写内容、重启选题，或要求用户先安装编剧。

## 接稿与修订边界

从当前项目定位选题三项、路线、文案 ID 与版本、依据、必须保留的限制和剩余问题；缺少会改变创作方向的信息才补问，已有有效确认直接沿用。新选题尚未明确时先交编剧讨论；没有编剧技能时说明缺失环节，保留已有内容。

不要求编剧先完成分镜、动作、音效或素材清单。导演自主决定视听细节并自查；观点、论据或关键承诺有问题时按文案 ID 返回编剧，在唯一内容源修订，不各写一份新稿。不擅改已确认原文。只有关键内容或方向变化需要用户确认，日常视觉细化与检查不增加逐镜审批。

同一个 agent 按职责切换即可，不要求另开聊天、启动子 agent 或为角色切换再确认。用户只要文案可停在编剧；只要分镜可停在导演；已要求出片则沿授权继续交接制作。

系列偏好保留在原系列文件。项目观众目标和选题承诺随交接继承，缺少编剧安装不免除这些本片约定；通用制作原则仍读 FOUNDATION 的 `references/production-principles.md`。
