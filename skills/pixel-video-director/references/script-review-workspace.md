# 导演工作台：讨论、预览与修订

## 当前主入口

沿 [导演四阶段](director-workflow.md)，在同一页面浏览大模块、单片段大白话与线框草图、结构化设计与动态白模、正式制作/审片记录。“编剧文案”保留原稿入口。主页面不再默认铺开五步流程说明、全片宽表和全部细节。

左侧聊天负责理解要求、生成与修订；页面负责查看、改稿、播放和反馈。同一片段保留稳定 ID，改稿写入本地工作副本；只有 agent 核对并回写源后才是持久更新。

## 简约布局

- 顶部突出项目标题和实际进度，导演四步使用轻量导航，编剧资料作为另一视图。
- 片段列表用于切换，一次突出一个片段。大白话与粗草图并排或窄屏上下排列，明确用户要求折叠展示。
- 动态阶段以播放器为主；画面组成、动作时序、前后连接按需展开。完整多维设计保留在详情，不默认展示超宽表。
- 当前片段与前后接镜一起核对，必要时连播相邻段；修改时提示邻接及显式关联片段的复核范围。
- 常用操作仅保留改稿、反馈与继续请求。导入、下载和帮助收进“更多”；改稿颜色和状态不只靠颜色区分。

## 构思图与动态白模的边界

阶段二的构思图是静态线框、火柴人和运动箭头，只辅助解释，后续可调整、替换或不采纳。它与阶段三采用的动态设计独立，页面不会自动转用图中配置。用户明确的约束单独保存并继承。

阶段三用当前片段动态数据画出背景、字幕、占位对象与关键动作；支持播放、拖动时间、相邻段/全片连播及导出 WebM。素材选择、支持范围和样板记录见 [白模工具](director-project.md)。没有动态设计就显示待补，不从描述补假动画。无背景图显示布局底色并提示；未接音轨明确无声及预估。

描述、文案、模块共识或相邻描述变化时，相关参考/白模显示待复核；过期动态设计不能导出。导演核对后更新依据，不能仅改标识使旧方案看似有效。最终制作与视听核验仍走基础工作台和 [Review](review.md)。

## 草稿、返回与冲突

字段修改与意见按项目、revision 和源摘要保存；浏览和切段不修改原项目。请求带来源、片段、原值/新值、意见和受影响范围。用户发送后由聊天修订唯一源，再构建同一入口；复制、发送和进入工具不等于已应用。

来源不同的草稿保留但不覆盖。旧页面草稿和旧审阅返回记录作为待核对材料显示/下载/交回，不能因重构丢弃。图片编码不塞入聊天，下载完整草稿 JSON 再由 agent 合入。低频高级动态结构可编辑，但必须通过合法性检查。

## 旧工具与成片审阅

旧 [片段审阅设计工具](../assets/segment-review/design-review.html) 保留原格式导入导出和返回能力，供历史记录继续使用。它不提供新四阶段动态白模，不再是阶段五必须打开的主入口。旧返回不会自动改写当前源。

已绑定真实工程和成片时，仍按本地成片审阅服务定位时间、问题与证据。它需要核对项目与版本，不能把演示白模当作用户成片或视听通过依据。
