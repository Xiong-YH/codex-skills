# 为什么第二次读得更快？

[打开 Canvas](index.html) · [拍位与事件](src/timeline.js) · [素材来源与锚点](media/sources.json) · [超粗精灵原图与提示词](media/azong-sprite-poses.json) · [试样记录](review/direction.md)

14 秒、60 fps 的独立视听小样。沿用缓存题，面向刚接触缓存的观众，用两次对同一份资料的访问解释有效副本怎样省掉往返源站的路径。浏览器直接打开 `index.html`，可播放、拖动、逐帧、半速和切换声音。

| 时间 | 画面变化 |
| --- | --- |
| 0–2.9 秒 | 读取端的 A 请求撞上空槽。精细像素小棕换成完整疑惑姿态，空槽和请求保留。 |
| 2.9–3.5 秒 | 缓存位置向外展开，A 请求带进源站空间。 |
| 3.5–6.9 秒 | 超粗像素小棕跑、蓄力、起跳。6 秒踩板，冲击沿地面散开，光沿线路传到闸门。6.5 秒松开卡夹，A 从待取请求变为可取资料。 |
| 6.9–8 秒 | 取到的 A 向左返回，同读取端交接，随后移到缓存槽并亮起副本标记。 |
| 8–11.4 秒 | 先读清本地副本。第二次请求从读取端发出，沿短路拿到一份 A，原副本留在缓存槽。 |
| 11.4–14 秒 | 本地副本沿浅底展开进入对照图。两次路线含去程和回程，保留副本有效这个条件。 |

## 复现

项目自带预览所需的 WebP 和 MP3，以及角色图集的 PNG 原图。从仓库根目录可运行下列命令。重新构建素材需要 Python 3、Pillow、Node.js 和支持 MP3 编码的 FFmpeg。可通过 `--ffmpeg` 指定路径，或通过 `--pulse-wav` 使用已有的《步进》一分钟版母带。

```text
python work/cache-route-canvas/src/build-media.py
node work/cache-route-canvas/src/build-preview.mjs <输出 HTML 片段路径>
```

`index.html` 是可直接打开的入口。第二条命令将相同画面和媒体内嵌为对话内预览片段。`src/timeline.js` 维护关键帧，改动音效触点后重新构建素材。
