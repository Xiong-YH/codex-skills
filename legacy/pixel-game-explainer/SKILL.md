# 现代像素口播视频

把讲解变成可见的状态变化：问题变成目标，关系变成路径，验证变成护盾，选择变成方案卡，交付变成项目组装。保留讲解的清晰度，游戏表达服务于意思。

## 先判断当前请求

- 只讨论风格或原因：读对应参考并回答，不擅自出片。
- 修改已有视频：先找最近被用户认可的版本，复用它的角色、工程和已选声音，仅改本次目标。
- 新主题：从语义分镜开始，随后复制种子工程并改内容。种子自带的是已认可的 32 秒示例；它不会自动把新标题变成新故事。
- 用户明确要求只看人物、转场样片或视觉：先交付相应范围。复用已经确认的角色和链路时，直接推进，不重复索要确认。

## 这套风格的默认方向

用户当轮要求优先。下列是这套视频的已确定方向，不是所有像素视频的通用规则：

- 现代像素簇、清晰阶梯轮廓、有限色板；不要靠模糊或缩小普通插画制造“像素感”。
- 一般只有一个主角。头大、身体小、头身直接衔接、手臂短而放松。把表现力放在讲解、物体变化和镜头上。
- 文案和标签是独立高清文字层，保持清晰，不和像素世界一起低分辨率光栅化。
- 嘴巴要动：用小口型、音节差异、闭唇和句间停顿。不要大黑洞、反复露齿、机械开合，也不要用音效振幅驱动嘴巴。
- 转场利落且连贯：共享物体、焦点、路径或运动方向；不是慢吞吞漂移，也不是每场停住后重新弹入。
- 游戏感来自任务、规则、状态与结果反馈；UI 保持克制，不给普通转场全部加胜利特效。
- 默认只有音效，无人声、无背景音乐。沿用 G2 赛博竞技方向，声音短、干、少气音，按动作分配材质。

## 制作流程

1. **拆解语义。** 给每句话指定焦点物体、状态变化和它向下一镜交接的方式。内容少就缩短，不用粒子、飘动和长停顿填时长。见视觉参考中的分镜字段。
2. **锁定角色。** 默认复用种子中的 02 暖棕蓬发主角。新人物或明显改比例时先出独立静态人物图，让用户看清头身、脸和衣服；不要把占位人物当成最终角色。只改主题不必重新画人物。
3. **先看关键交接。** 新转场先在本地渲染关键段。如果用户要求先定链路，就先交付短样片；方向已确定且用户要求出片时，自审后继续完成整片。
4. **实现连续场景。** 在原生像素网格上构造稳定图层；到最终分辨率才做浮点位移和缩放。每段演绎一种主要机制，保留上一段的焦点或因果。
5. **安排嘴型与声音。** 嘴型按讲解节奏，音效按可见事件，两条时间线分别设计。更换文案时同步修改拼音短句；更换动作时同步修改音效事件，不能直接复用旧时点。
6. **渲染与自审。** 先看静帧的比例、文字、重叠，再看转场前中后及实际 MP4。合成音效后检查时长、帧时间、音轨、同步和峰值；这些媒体检查不替代视觉判断。
7. **交付。** 给可直接播放的视频；按需附自包含预览、源码与独立音效。简述改了什么和实际检查结果。用户明确指出的问题写入该工程的决策记录，不把一次试验写成永久偏好。

## 可运行种子与命令

`assets/starter/` 包含完整 V7 场景源码、02 人物、嘴型数据、可编辑声音事件及已合成的音轨；没有依赖原项目路径。

在下面命令中将 `SKILL_DIR`、`PROJECT_DIR` 换成实际绝对路径：

```sh
python3 "$SKILL_DIR/scripts/project.py" init "$PROJECT_DIR"
python3 "$SKILL_DIR/scripts/project.py" build "$PROJECT_DIR"
python3 "$SKILL_DIR/scripts/render.py" "$PROJECT_DIR" --name handoff --start 15.2 --end 16.2 --silent
python3 "$SKILL_DIR/scripts/render.py" "$PROJECT_DIR" --name film
```

先读制作参考了解依赖与哪些文件要一起改。只看视觉时用 `--silent`，无需先制作声音。更换主题必须修改场景演绎、标题、字幕、短句、章节和声音事件；不要只替换标题或拉伸 32 秒的时间轴。

种子默认 1920×1080、60 fps、320×180 原生世界。这些是可运行示例参数。原生网格、片长、镜头数、配色和人物都可因题材调整，但应同步改引擎与数据并重新看效果。
